# Підключення до журналу — поетапні перевірки

## Етап 1 — ключі джерела та єдиний school_sync

Міграція 0069 перетворює наявні ключі JournalAPIKey на SHA-256 із маркером
формату. Оригінальний Bearer-ключ продовжує працювати у v1 і v2; хеш ключа
не приймається як ключ. PK, власник, права й активність зберігаються.
Старі одноразові ключі прибираються з сесій зі збереженням решти налаштувань
і входу користувача. Новий повний ключ показується лише у відповіді на
створення, без збереження в сесії. Повторний перегляд і копіювання старих
ключів прибрано. Legacy query-ключі маскуються в журналі запитів і статистиці
онлайн-клієнтів; повідомлення винятків не розкривають їх.

SHA-256 не має зворотного перетворення. Повернення до старої версії коду,
що зберігала ключі відкрито, виконується відновленням приватної копії перед
оновленням через чинний механізм відкату; reverse migration не виконується.

school_sync побайтно збігається зі SchoolJournal і SchoolTest, з усіма
чинними захисними перевірками. API v2 schema_version=2 не змінено.

41 цільовий тест API v1 / v2, передачі списків, міграції ключів, одноразового
показу та маскування журналу успішно в ізольованому Docker на SQLite.
26 спільних тестів протоколу успішно. Схема відповідає моделям.

Ручна перевірка на тестовій копії: до оновлення зберегти тестовий ключ;
після 0069 перевірити ним GET roster, створити новий ключ і скопіювати його
з відповіді. Після звичайного GET налаштувань повний ключ відсутній.
Дані учнів і робіт не змінюються. Це підготовчий коміт; ping та новий
інтерфейс додаються на наступних етапах.

## Етап 2 — легка перевірка і права

GET `/api/v2/ping` доступний без ключа й повертає лише source, instance_id,
version. Авторизований `/api/v2/journal/connection/` повертає фактичні
export / roster_import без учнів та оцінок. Невідомий / неактивний ключ
дає 401, чинний ключ без потрібного дозволу — 403. Перевірки не додають
фіктивних онлайн-клієнтів і не створюють зайвих записів журналу запитів.

44 цільові тести API / ключів / discovery на SQLite та 29 спільних тестів
успішно. Ручна перевірка на тестовому ключі: ping без ключа — 200;
connection — фактичні права; за вимкненого roster import POST roster — 403,
а за вимкненого export GET grades — 403. Наявні v1 / v2 маршрути збережено.

## Етап 3 — одна сторінка підключень

Journal: owner-scoped «Підключення», мережеві профілі, картки статусу / прав /
UUID / версії / часу, майстер адреса → ключ → перевірка → готово, безпечна
заміна ключа. Старе меню ключів переходить у новий центр; налаштування
класу більше не просять адресу й токен. Порти задано профілем один раз,
збережені legacy-порти мають пріоритет. У конфігурації локального сервера
потрібні фактичні LOCAL_SCHOOLTEST_PORT / LOCAL_SCHOOLWORK_PORT.

SchoolTest / SchoolNet: довідка з UUID і готовими адресами, копіювання
працює також у LAN HTTP. Код підключення використовує поточну адресу
запиту. Ключ показується лише після створення. Необов'язковий Linux
compose.lan.yaml публікує лише LAN IP у tmpfs: worker без секретів, БД,
host-файлів, capabilities і Docker socket; застосунок читає том readonly.
За відсутності прав на інтерфейси сторінки продовжують працювати.

Цільові перевірки: ізоляція чужих сервісів / профілів / адрес, CSRF і POST,
повторне додавання, два джерела з одним host, відмова нового ключа без
втрати старого, відсутність ключів у DOM / JSON. 160 тестів SchoolTest і
74 API / key / roster / shared тестів SchoolNet пройшли. Повні остаточні
перевірки, браузер і встановлення виконуються після етапів 4–5.

Ручна перевірка на синтетичному стенді: додати обидва джерела в одну
мережу, перевірити картки; змінити мережу; спробувати неправильний ключ;
переконатися, що старі класи й оцінки залишилися. На джерелах скопіювати
поточну адресу та новий ключ і перезавантажити — ключ більше не показаний.
