# SchoolNet 4.5.14 — перевірка та оптимізація сповіщень

Перевірено попередні зміни 4.5.11–4.5.13 та коміт `0f2335b`, API доставки,
сторінку `/teacher/settings/?tab=environment&section=notifications` і Docker-сервіси.

Виправлено тест звуку при вимкнених перемикачах, втрату постійних карток при
перезавантаженні, перехід демонстраційних карток до реальних робіт та повторний
показ подій після «Закрити всі». Поля шаблону й мелодії адаптовано для вузьких
екранів. Фонова перевірка налаштувань дотримується серверного інтервалу.

Сторінка сповіщень отримала окремий легкий шаблон та ранню відповідь сервера:
без статистики ШІ, сканування сховища й прихованих вкладок. Форма зберігає
попередні права доступу, CSRF, повідомлення про успіх і перевірку значень.

| Вимірювання на синтетичних даних | Повна сторінка середовища | Сторінка сповіщень |
|---|---:|---:|
| SQL-запити, весь запит Django | 78 | 18 |
| HTML, байти | 695 537 | 88 887 |
| Медіана 5 прогрітих запитів, мс | 46,21 | 11,34 |

Це локальне порівняння SQLite, не навантажувальний тест сервера. API сповіщень
виконує три основні SQL-запити; міграція на інший транспорт зараз не потрібна.
За увімкнених сповіщень видима вкладка опитує сервер раз на 3 секунди,
прихована з дозволеною фоновою доставкою — щонайменше раз на 8 секунд,
вимкнені сповіщення — раз на 30 секунд. Мобільна ОС може обмежувати фоновий звук.

102 серверні тести пройшли. Chrome перевірив збереження, шаблони, мелодії,
таймер, постійні картки після перезавантаження, чергу, відсутність повторного
звуку, ізоляцію класів, навігацію й мобільний вигляд. Окремо пройшли
фонова доставка/звук/заголовок та відновлення застарілої черги після «Закрити всі». Окремо перевірено
`manage.py check`, узгодженість міграцій та `git diff --check`.

Додано міграцію `0068_sync_notification_template_labels`: лише узгодження
підписів choices, без зміни збережених ключів та значень. Django застосовує
її штатним Docker entrypoint разом із collectstatic.

Деталі й команди повторної перевірки: [сповіщення](docs/SUBMISSION_NOTIFICATIONS.md).

## Docker та робочий сайт

Зібрано `schoolwork2-app:4.5.14-15478196afc1` із коміту `756395b`.
Відбиток джерел образу збігається з перевіреним кодом. У фінальному образі,
без мережі та робочих томів, повторно успішно виконано 102 тести (6,372 с).

Перед встановленням робочі app, ai_worker, PostgreSQL, updater та code_runner мали статус healthy.
`http://192.168.1.12:8000/healthz/` повертає 200; пряме відкриття налаштувань
без авторизації — очікуваний 302. Додаткова перевірка чинної сторінки через
внутрішній GET із профілем учителя та блокуванням SQL-записів: 200, форма
сповіщень присутня, SQL-записів немає. HTML поточної сторінки з реальними даними
має 884 907 байтів; один непрогрітий запит виконувався 717,76 мс. Ці числа
не порівнюються напряму з вимірами на синтетичних даних вище.

### Установлення після підтвердження користувача

20.10.2026 встановлено `schoolwork2-app:4.5.14-15478196afc1` одночасно для
app та ai_worker. Перед перезапуском активних задач ШІ й хмарних імпортів не було.
Збережено перевірену копію PostgreSQL у `backups/2026-10-20_notifications_VjaQDa`
та попередній образ `schoolwork2-app:before-notifications-4514-20261020`.
Медіафайли залишилися у чинному томі; цей випуск їх не змінює.

Після запуску:

- Усі п’ять сервісів мають статус healthy. App і worker використовують один
  образ; відбиток їхнього коду збігається з перевіреним checkout.
- Міграцію `feed.0068_sync_notification_template_labels` застосовано,
  `manage.py check` та `migrate --check` успішні, статику зібрано entrypoint.
- Кількість завдань, вкладень, відповідей, учителів, учнів, класів, закладів,
  подій та налаштувань сповіщень до й після встановлення збігається.
- `/healthz/` повертає 200 та версію 4.5.14. API сповіщень повертає 200 і не
  відтворює історичні події на першому запиті. Налаштування без входу очікувано
  спрямовують на авторизацію (302).
- Сервер видає JS/CSS сповіщень із SHA-256, тотожним файлам перевіреного коду.
- Внутрішній GET сторінки як учитель: 200, форма присутня, прихованого модуля ШІ
  немає, SQL-записів немає. HTML має 92 467 байтів, виконано 11 SQL-запитів,
  один непрогрітий виклик — 244,37 мс. Внутрішній виклик не включає HTTP middleware
  та автентифікацію; його кількість запитів відрізняється від повного тестового
  запиту Django вище. Це перевірка після запуску, не навантажувальне випробування.
