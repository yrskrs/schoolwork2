1. Що та як зберігати

Основні дані завжди включаються: тести або завдання, налаштування робіт, класи та списки учнів.

Інкрементальне: стиснені ZIP-блоки повторно використовуються між копіями, у хмару передаються лише нові дані. Для відновлення потрібні опис копії та її блоки; сайт збирає їх автоматично. Можна підготувати повний ZIP для завантаження.
ZIP: звичайний архів з даними й вибраними файлами, зручний для ручного перенесення. Кожен запуск передає повний архів, тому потребує більше місця та трафіку.

Із паролем використовується AES-256 ZIP; для відкриття потрібна сумісна програма, наприклад 7-Zip. Без пароля копія не зашифрована. Пароль зберігається на сервері в зашифрованому вигляді для розкладу. Збережіть його окремо: після втрати сервера забутий пароль відновити неможливо. Зміна пароля починає нове сховище; старим копіям потрібен старий пароль.

Запишіть цей ідентифікатор поза сервером. На новому встановленні підключіть той самий хмарний акаунт, укажіть цей ідентифікатор, пароль і відповідний обсяг копії та позначте «лише для відновлення». Сайти використовують різні папки. Одне сховище має обслуговувати лише один сервер; після відновлення створіть нове для подальших запусків.

Початкове налаштування Nextcloud та Google Drive

Nextcloud: у своєму акаунті відкрийте «Налаштування → Безпека → Паролі додатків», створіть окремий пароль для цього сайту. Введіть базову адресу без /remote.php/…, логін і пароль додатка. Сервер сайту має мати доступ до Nextcloud; для HTTPS потрібен дійсний сертифікат.

Google: у Google Cloud Console створіть проєкт, увімкніть Google Drive API, налаштуйте OAuth consent screen та OAuth client типу Web application. Додайте свій акаунт до тестових користувачів, якщо застосунок у тестовому режимі. Відкрийте сайт через HTTPS-домен. До Authorized redirect URIs додайте точну адресу: публічна HTTPS-адреса цього сайту (за потреби з поля вище) + {{ backup_base }}/google/callback?scope={{ backup.scope }}. Для обох обсягів додайте обидві адреси: scope=personal і scope=server.

Збережіть Client ID / Secret і натисніть «Підключити Google». Потрібен доступ drive.file до створених застосунком файлів; пароль Gmail та API key не підходять. Після втрати сервера використайте той самий OAuth client; його налаштування збережіть окремо. У тестовому режимі Google offline-доступ може спливати — перепідключіть акаунт за повідомленням про помилку.

3. Автоматичні копії

Розклад працює, поки сервер і фоновий процес увімкнені. Після простою виконається один пропущений запуск. Історія точок відновлення — 30 днів; остання успішна копія зберігається завжди. Блоки зберігаються для цілісності копій; зайняте місце може перевищувати розмір останньої копії.

4. Запуск і відновлення

Операції використовують збережені налаштування.

Оновити список і стан

Відновлюйте на новому встановленні сумісної версії, без тестів, завдань та інших учителів. Особиста копія приєднується до поточного вчителя; повна копія відновлює облікові записи та може вимагати повторного входу. Зовнішні інтеграції й доступи налаштовуються повторно. Якщо файли не включались до копії, їх неможливо відновити.
