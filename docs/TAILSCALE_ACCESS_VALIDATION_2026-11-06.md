## Реальний браузер

```bash
/tmp/schoolnet-venv/bin/python scripts/test_access_links_ui.py
```

Headless Chrome, окремий тимчасовий профіль, справжній HTTPS із тимчасовим
самопідписаним сертифікатом, окремі локальний/публічний домени та тимчасова SQLite.
Тестовий WSGI-проксі відтворює заголовки Funnel. Живий Tailscale не викликається.
Chrome та локальний HTTPS-сервер потребували виконання поза мережевим sandbox.

Перевірено:

1. Типово вимкнене підключення; збереження адреси/ввімкнення через форму адміністратора.
2. Зрозуміла помилка перевірки служби без підключеного CLI.
3. Створення через UI всіх чотирьох типів посилань з окремими назвами й цілями.
4. Показ потрібних полів, справжнє натискання кнопки копіювання та завантаження SVG QR.
5. Десктоп 1440 × 1100 та мобільна ширина 390 px без горизонтального переповнення.
6. Відмова без дозволу; підтвердження персонального посилання; перехід без секрету в адресі.
7. Автоматичне ім’я й клас; справжня здача текстової відповіді через форму; перевірка `student_id` та класу в БД.
8. Один підтверджений перехід / один браузер; скасування через UI вчителя; відмова для тієї ж учнівської cookie.
9. Відсутність JavaScript exceptions.

Результат: **успішно**. Скріншоти й JSON генеруються у `/tmp/schoolnet-access-ui`;
для іншого каталогу використовуйте `QA_ARTIFACTS`. Фікстури БД, сертифікат і
профіль браузера видаляються після завершення.

Браузерна перевірка виявила несумісність `Referrer-Policy: no-referrer` із CSRF
для звичайного POST-переходу. Використовується `same-origin`: секрет не потрапляє
до сторонніх сайтів, а форми проходять CSRF-перевірку.

## Межі перевірки та встановлення

- Команди локального адаптера перевірено з імітацією daemon-відповідей: DNS вузла, конфлікт чужого кореневого сервісу, таймаут, аргументи без shell, відсутність `reset` та зміни інших портів.
- Не виконувалися живі команди Funnel, авторизація Tailscale, відкриття портів або перевірка публічного DNS на сервері.
- Не запускалися Docker-збірка, PostgreSQL та монтування CLI/socket хоста. Це слід перевірити при встановленні; застосунок працює й із ручним керуванням Funnel без доступу контейнера до daemon.
- Для встановлення потрібні оновлені залежності/образ і `manage.py migrate`. Після міграції підключення залишається вимкненим; увімкніть його на сторінці налаштувань після підготовки сервера.
- Локальний доступ і авторизований учитель збережені. Після скасування учнівського посилання вже відкритий вміст не стирається, але наступний запит відхиляється.
