# Сповіщення про здачу робіт

## Як увімкнути

У **Налаштування → Середовище → Сповіщення про здачу робіт** учитель обирає:

- показувати сповіщення собі, учням, обом або нікому;
- звук окремо для кожної аудиторії;
- тривалість 1–60 секунд (початково 5 секунд) або показ до натискання;
- поведінку для учнів: чи відкривати здане завдання при кліку на картку (або просто закривати її);
- аудиторію класів: показувати учням сповіщення в загальному без прив'язки до обраного класу, або обмежувати обраним класом;
- роботу у фонових вкладках: доставку та звук, навіть коли вкладка браузера згорнута чи неактивна;
- вигляд картки: загальний без прив'язки до класу («ПІБ здав/ла роботу») або з показом бейджа класу.

Налаштування стосуються завдань поточного вчителя. Початково сповіщення та звук
вимкнені. Кнопки прикладів перевіряють вигляд і звук із поточними значеннями форми,
не зберігаючи їх; для застосування потрібна кнопка «Зберегти сповіщення».

Картка знизу праворуч показує повні прізвище й ім’я та скорочену назву
завдання (і за бажанням вчителя — бейдж класу). Повторна здача має бурштиновий акцент, номер спроби й іншу мелодію.
Стать у профілі не зберігається, тому текст використовує «здав/ла».

Учитель натисканням відкриває роботу для перевірки. Учень, якщо дозволено вчителем,
відкриває здане завдання, або закриває картку без переходу. Окрема кнопка × завжди закриває її без переходу.
Для колективної здачі надходить одна картка з авторами. Одночасно показуються до трьох карток; решта чекають у черзі.
Таймер для наступної картки запускається після її появи. Є кнопка закриття всіх.

За замовчуванням учні бачать сповіщення незалежно від відкритого завдання чи класу.
За потреби вчитель може увімкнути сувору фільтрацію за обраним класом. Індивідуальні,
неопубліковані й архівні завдання не транслюються учням. Учнівський API не передає
оцінок, коментарів учителя, вмісту файлів чи посилань на перевірку робіт. Обліковий запис
учителя отримує події лише власних завдань.

Браузер дозволяє звук після першої взаємодії зі сторінкою. Якщо WebAudio
недоступний або звук заблоковано, текстові картки продовжують працювати.
Звук синтезується локально, без зовнішніх аудіофайлів чи CDN.

## План і виконання

1. Досліджено `SubmissionForm`, нумерацію повторних спроб, перевірку прав,
   базовий шаблон, теми й налаштування вчителя.
2. Додано моделі налаштувань і подій та міграцію `feed.0065_submission_notifications`.
3. Подія записується всередині транзакції форми після збереження файлів і
   співавторів. Відкат здачі відкочує подію. Оцінювання чи зміна файлу не створює
   додаткових сповіщень.
4. Додано асинхронний API, чергу карток, обидві мелодії, налаштування й приклади.
5. Перевірено сервер, Chrome, мобільний вигляд і обидві теми.

Подія зберігає дозволені на момент здачі аудиторії. Якщо обидві вимкнені, подія
не створюється. Увімкнення аудиторії не показує їй здачі, які відбулися, поки
сповіщення для неї були вимкнені. Поточні перемикачі також перевіряються сервером
при кожному опитуванні.

Курсор і незакриті картки зберігаються в `sessionStorage` окремо для вчителя або
учнівського класу. Після перезавантаження отримані картки не озвучуються повторно.
Перший візит установлює поточний курсор без показу історичних здач. Перехід між
сторінками тієї самої вкладки зберігає чергу за наявності доступу до сховища браузера.
Коли вкладка прихована, мережеві опитування припиняються; після повернення вони
продовжуються з курсора, без обмеження віку пропущених подій.

## Навантаження

Механізм сумісний із наявним Gunicorn `gthread`, SQLite та PostgreSQL і не вимагає
Redis, WebSocket або окремих постійних серверних з’єднань.

- Активна сторінка з увімкненими сповіщеннями: один короткий JSON-запит приблизно
  раз на 5 секунд. Вимкнені сповіщення: перевірка налаштувань раз на 30 секунд.
- Прихована/офлайн-вкладка не опитує сервер. Після помилок затримка зростає до
  60 секунд; завислий запит переривається через 10 секунд. Запити не накладаються.
- Основний API виконує три запити БД: налаштування, верхня межа курсора та нові
  події. Підтверджено тестом кількості запитів; сесія/автентифікація Django може
  додавати свої запити. Шаблони, матеріали робіт, конвертація й ШІ не запускаються.
- Події читаються порціями по 25 через первинний ключ та індекс учителя.
  У DOM не більше трьох карток. При черзі у 100 карток курсор зупиняється до
  звільнення місця, щоб не втрачати наступні події й не роздувати пам’ять браузера.
- Записується одна невелика подія на успішну здачу з увімкненою аудиторією, без
  дублювання тексту роботи чи файлів. Видалення здачі видаляє й подію.
- Успішні опитування не засмічують додатковий журнал `OnlineClientsMiddleware`;
  помилки продовжують журналюватися. Gunicorn має власний access log.

Для 30 видимих сторінок це орієнтовно 6 запитів/с, для 300 — 60 запитів/с.
Це розрахунок частоти, а не результат навантажувального тесту. Один клас не має
створювати значного додаткового навантаження; для одночасного використання всією
школою потрібно виміряти затримки на реальному обладнанні й БД. Нові події зазвичай
з’являються протягом інтервалу опитування та часу відповіді сервера; зміна вимкнених
налаштувань підхоплюється відкритою сторінкою протягом приблизно 30 секунд.

- 18 нових серверних тестів, 69 тестів разом із пов’язаними перевірками здач,
  співавторів, учнів, переведень і компонування — успішно.
- Chrome з тимчасовою БД: збереження через справжню форму з CSRF; доставка тексту;
  різні послідовності частот WebAudio; 5-секундний таймер; режим до натискання;
  перехід учителя до перевірки; закриття учнем; мобільна темна тема; черга з шести
  подій; відновлення після перезавантаження без повторного звуку; призупинення й
  відновлення опитування за зміною видимості; вимкнення аудиторії; ізоляція класів,
  зокрема після зміни AJAX-фільтра стрічки;
  робота тексту без AudioContext. Винятків JavaScript немає.
- `manage.py check`, `makemigrations --check --dry-run`, `git diff --check` — успішно.
- Ширший набір: 273 тести, 266 успішних, 4 пропущені, 3 давні збої. Ці самі збої
  відтворено окремо на чистому `HEAD` до змін:
  `IntelligentStudentEvaluationRequirementsTests.test_11_feedback_and_revision_advice_consistency`
  (`KeyError: strengths`),
  `ExcelChartExtractionTests.test_extract_images_from_xlsx_visual_rendering`
  (порожній результат рендерингу),
  `TeacherMaterialsAITaskRecognitionTests.test_ai_recognizes_task_in_teacher_presentation`
  (відсутня очікувана PDF-частина).

Повторити перевірки:

```bash
DJANGO_SETTINGS_MODULE=schoolnet.test_settings python manage.py test \
  feed.tests_submission_notifications feed.tests_submission_layout \
  feed.tests_merge_and_coauthors feed.tests_roster_transfer \
  feed.tests_outside_students feed.tests_platform_layout --noinput
python scripts/test_submission_notifications_ui.py
```

Браузерному сценарію потрібні Chrome/Chromium, Python `websockets` і дозвіл
відкрити локальний тестовий HTTP-сервер. Він використовує лише синтетичні дані
в тимчасовій БД. Знімки зберігає у `/tmp/schoolnet-notifications-ui` або каталозі
`QA_ARTIFACTS`.

## Установлення

Зміни підготовлено в коді; робочу БД і запущені контейнери не змінено.
Під час розгортання потрібні міграція та нова статика:

```bash
python manage.py migrate
python manage.py collectstatic --noinput
```

Штатний Docker entrypoint уже виконує ці команди перед запуском Gunicorn.
Після перезапуску з оновленим кодом учитель може ввімкнути потрібну аудиторію.
