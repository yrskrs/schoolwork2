# Підключення ШІ та спільна черга моделей — 4.1.7

## План і виконання

1. **Виконано: аудит.** Попередній механізм мав два слоти ключів і запускав активну модель перед списком пріоритетів. Статистика підставляла 850 вхідних / 380 вихідних / 1230 загальних токенів без даних API. Деякі ідентифікатори Gemini непомітно замінювалися іншими.
2. **Виконано: зберігання підключень.** Додано список підключень із власними ідентифікаторами, постачальником, назвою, ключем і Base URL. Можна мати кілька ключів одного постачальника. Ключі не вставляються в HTML або JSON сторінки; порожнє поле під час редагування зберігає попередній ключ. Зміна постачальника потребує окремого підключення, щоб ключ не використовувався випадково в іншого постачальника.
3. **Виконано: міграція.** 0051 додає поля підключень і статистики роботи. 0052 переносить обидва старі ключі, URL, чергу й вимкнені моделі. Поточна модель збережена першою під час одноразового перенесення. Два ключі одного постачальника залишаються окремими підключеннями; старі поля ключів очищуються. Історичні колонки й методи збережено для сумісності з неперенесеними записами, але перенесені налаштування використовують лише нову чергу.
4. **Виконано: єдина послідовність.** Рядок черги містить конкретне підключення й точний ідентифікатор моделі. Ідентичні назви на різних ключах не об’єднуються. Стрілки, увімкнення, видалення й «Зробити #1» діють лише на відповідний рядок. Перевірка використовує першу ввімкнену модель із налаштованим підключенням, потім наступні після помилки, включно з непридатним JSON. Кожна модель у новій черзі має одну спробу; без автоматичного переходу використовується лише перша доступна модель. Генерація критеріїв і пояснення завдання використовують ту саму чергу. Прибрано підміну версій Gemini; технічний префікс `models/` видаляється при формуванні Google endpoint.
5. **Виконано: дані перевірки.** З відповіді саме успішної спроби зберігаються постачальник, модель (поле `model` / `modelVersion`, якщо доступне), вхідні, вихідні й загальні токени. Одиночний перегляд, результат пакетного job та повторне завантаження пакетної черги показують ці дані окремо від оцінки. Самоперевірка учня й синхронізація співавторських робіт також зберігають метадані.
6. **Виконано: перевірки й документація.** Додано 20 регресійних тестів. Оновлено попередні тести форм під нові підключення. README містить порядок налаштування й пояснення токенів. Версія та журнал змін — 4.1.7.

## Облік токенів

Лічильники читаються з Gemini `usageMetadata` або сумісного `usage`. Значення 0 зберігається; відсутні або некоректні значення залишаються невідомими. Загальний лічильник API не замінюється сумою вхідних і видимих вихідних токенів: він може включати міркування. Офіційні джерела: [Gemini: облік токенів](https://ai.google.dev/gemini-api/docs/generate-content/tokens), [OpenRouter: відповідь chat completions](https://openrouter.ai/docs/api/api-reference/chat/send-chat-completion-request).

Блок показує запит, який сформував оцінку, а не суму всіх спроб перевірки. Кожен фактичний виклик продовжує записуватися окремо в AIRequestLog. Для нового журналу `usage_reported` відрізняє відсутню статистику від справжнього нуля. Історичні лічильники не переписуються й можуть містити умовні оцінки попередніх версій. Для старої роботи не підбирається випадковий запис зі спільного журналу: її токени залишаються невідомими.

## Перевірки

- Цільовий набір: підключення, вибір конкретного ключа, порядок і HTTP-форми моделей, пропуск вимкнених / неналаштованих моделей, локальний API без ключа, видалення підключення, точне перенесення двох ключів одного постачальника, переходи при 429 / 401 та некоректній відповіді, перехід при генерації критеріїв, фактичні токени й модель після переходу, результат job і перезавантаження черги.
- Повний локальний набір: **456 тестів, 454 успішні, 2 пропущені, помилок немає**, 50,652 с. SQLite, медіа та кеші тестів тимчасові; LibreOffice виконувався поза sandbox. Робочі дані не використовувалися.
- Повний набір у фінальному Docker-образі: **456 тестів, 454 успішні, 2 пропущені, помилок немає**, 46,786 с; контейнер без мережі та робочих томів.
- Django `check`, `makemigrations --check --dry-run`, `git diff --check` успішні.
- Згенеровано три сторінки вчителя (налаштування, перегляд роботи, пакетна перевірка): немає вкладених форм. Перевірено синтаксис двох нових / змінених зовнішніх JS та дев’яти унікальних inline-скриптів. У V8 перевірено екранування моделі, нульові токени й невідомі токени.
- Візуальна перевірка у справжньому браузері недоступна в середовищі. Мережеві відповіді постачальників імітовано; чинність робочих ключів та якість живої моделі не перевірялися платними запитами.

## Оновлення й повернення

Перед застосуванням міграцій треба зупинити `app` і `ai_worker` та створити перевірену копію PostgreSQL і медіа. 0052 навмисно незворотна: повернення до двох слотів втратить довільну кількість підключень. Для повернення на 4.1.6 використовуйте копію БД до міграції разом з образом 4.1.6; не запускайте старий код із новою БД, де старі поля ключів очищено. Медіафайли ця зміна не перетворює й не видаляє.

```bash
venv/bin/python manage.py test feed --settings=schoolnet.test_settings --noinput
venv/bin/python manage.py check --settings=schoolnet.test_settings
venv/bin/python manage.py makemigrations --check --dry-run --settings=schoolnet.test_settings
git diff --check
docker compose build app
SCHOOLNET_BACKUP_KEEP_STOPPED=1 ./scripts/backup.sh
docker compose up -d --wait --wait-timeout 240 app ai_worker
```

Резервна копія перед міграцією: `backups/2026-10-05_19-34-56_6J7fiX` (дамп і архів перевірені). Образи: `schoolwork2-app:4.1.7`, попередній — `schoolwork2-app:before-v4.1.7`.

Розгортання завершено: `app`, `ai_worker` та PostgreSQL мають стан healthy. Застосовано 0051–0052. Хеші ключів і URL до / після перенесення збігаються; усі попередні моделі збережено. Кількість робіт і завдань не змінилася. Django `check` успішний. Головна сторінка повертає 200 і показує 4.1.7; нові JS / CSS доступні з кодом 200. Збережені ключі відсутні у публічних даних підключень.
