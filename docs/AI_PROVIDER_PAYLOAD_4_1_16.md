# SchoolNet 4.1.16: жива діагностика OpenRouter та Groq

Користувач повторив перевірку роботи №42 (завдання №36), підтвердив, що всі її матеріали тестові та нечутливі, і попросив перевірити зовнішні API. Діагностика виконує штатне оцінювання з одним підключенням усередині транзакції, яка відкочується. Порівняння запису Submission до й після кожного тесту підтвердило відсутність змін. Ключі не виводяться; в цьому звіті немає тексту роботи чи міркувань моделі.

## Причини

1. **Qwen 413.** За [документацією Groq Vision](https://console.groq.com/docs/vision) кожне зображення Qwen коштує 2048 вхідних токенів, максимум — три зображення. Попередній плановий розрахунок резервував 1000. Два зображення сторінок ODT роботи (кожне 1273×1800) давали 4096 візуальних токенів; API повідомив 7568 при ITPM 7000. Стиснення PNG зменшує байти, але не фіксовану плату за зображення.
2. **OpenRouter без оцінки.** Прямий повтор старого запиту повернув HTTP 200, `dots-studio/dots-3-note-preview:free`, `finish_reason=length`, порожній content і 5380 токенів внутрішніх міркувань. Міркування витратили весь бюджет відповіді. За [документацією OpenRouter](https://openrouter.ai/docs/api_reference/errors-and-debugging) такий запит не варто повторювати з незмінними параметрами. Помилки провайдера також можуть бути в тілі HTTP 200.
3. **Нескінченне очікування.** Проміжні пробіли OpenRouter підтримували з’єднання; звичайний socket timeout скидався, поки клієнт чекав усе тіло. Це дозволяло запиту тривати кілька хвилин.
4. **Додатковий MAX_TOKENS Qwen.** Після усунення 413 перша жива відповідь обірвалася на 1800 вихідних токенах. ITPM обмежує вхід; віднімання відповіді від цього числа не лікує 413. [Groq розрізняє ITPM, OTPM і сумарний TPM](https://console.groq.com/docs/rate-limits), фактичні межі залежать від організації.
5. **Неточна статистика.** HTTP 200 з порожнім рядком рахувався успішним, а код мережевого збою 0 зберігався як 200.

## Зміни

- PDF-рендеринг додає ідентифікатор документа й номери сторінок. Qwen об’єднує лише суміжні сторінки одного документа в підписане зображення: ліворуч/праворуч, проміжок 16 пікселів, PNG без втрат. Усі початкові пікселі й роздільність збережено. Зображення інших документів, фотографії, прозорі/анімаційні файли та завеликі полотна залишаються окремими; межа полотна — 6 млн пікселів. Початковий список не мутується.
- Облік Qwen використовує 2048 токенів за зображення; плановий вихідний бюджет не опускається нижче 3500, якщо виклик сам не просить менше. Це не штучна перевірка квоти: остаточне рішення приймає API.
- OpenRouter отримує той самий компактний доказовий контекст і правила, що Groq. У швидкому режимі `reasoning.enabled=false`; приховування міркувань через `exclude` не використовуємо як заміну їх вимкненню. Глибокий режим зберігає свою поведінку. [Офіційний опис reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).
- Помилки верхнього рівня й choices усередині HTTP 200 нормалізуються; частковий JSON за наявності помилки не приймається. MAX_TOKENS показує фактичну модель і доступну кількість reasoning tokens. Фільтр вмісту/відмова розпізнаються окремо й не видаються за порожню відповідь.
- Free router має один повтор після порожньої відповіді чи отриманого 502/503. Не повторюємо timeout, 429, відмову чи вичерпаний бюджет. Максимум очікування для його оцінювання підвищено до 90 секунд. Читання доступними порціями перевіряє загальний дедлайн навіть за сигналів keepalive; наступна порція перевіряється після повернення транспортного читання, яке теж має socket timeout. Без сигналів очікування обмежене транспортним timeout. Автоматичний повтор POST іншим транспортом заборонено.
- Помилки та порожні відповіді правильно позначаються в метриках; код 0 залишається кодом 0.
- Текст учня, задана вправа, критерії, власні інструкції й необхідні візуальні докази збережені. Попередні правила явно неперевірених візуальних критеріїв GPT-OSS і межі трьох зображень Qwen залишаються чинними. Нових міграцій немає.

## Живі перевірки роботи №42

Штатний процес включає парсинг JSON, валідацію оцінки та формування результату, а не лише HTTP-з’єднання. Кожне з трьох підключень тестувалося окремо; резервна модель не могла замаскувати збій.

| Підключення | Фактична модель | Вхідні токени API | Вихідні токени API | Час HTTP | Результат |
| --- | --- | ---: | ---: | ---: | --- |
| Groq Qwen | qwen/qwen3.8-27b | 5378 | 1828 | 4,55 с | success, завершений JSON |
| Groq GPT-OSS | openai/gpt-oss-120b | 3560 | 2031 (97 reasoning) | 4,86 с | success, завершений JSON |
| OpenRouter/free | nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free | 3777 | 627 (0 reasoning) | 17,09 с | success, завершений JSON |
| OpenRouter/free після розгортання | dots-studio/dots-3-note-preview:free | 7030 | 2734 (0 reasoning) | 49,32 с | success, завершений JSON |

Qwen: **7568 → 5378**, зменшення на **2190 токенів (29%)**, 2 сторінки в одному зображенні, без втрати їх пікселів. Повний компактний промпт — 7428 символів, правила — 2893; додаткові підписи зображень передаються адаптером. Фінальний тест OpenRouter використовував штатний ліміт 90 секунд і завершився за 17,09 с. Ще один окремий діагностичний запит із межею 120 секунд також успішно завершився за 22,28 с (3777 вхідних, 779 вихідних токенів, 0 reasoning). Попередній новий запит із межею 35 завершився дедлайном; фактична модель не відома, бо відповідь не завершилась.

Наявність успішної відповіді не гарантує доступність усіх випадково обраних backend. [Free router](https://openrouter.ai/docs/guides/routing/routers/free-router) змінює моделі залежно від потрібних можливостей і поточної доступності. Помилки 429/502/503 чи недотримання окремим backend параметра reasoning залишаються можливими; система має коректно показати причину та продовжити дозволену чергу.

## Регресії

Тести покривають точний збіг усіх пікселів обох сторінок після об’єднання; збереження непідхожих файлів; фіксовану вартість Qwen; бюджет завершеної відповіді; HTTP 200 із верхньою/вкладеною помилкою; відмову фільтра; вичерпання reasoning; keepalive-дедлайн; порційне Unicode JSON; одноразовий повтор пустої відповіді; відсутність повтору MAX_TOKENS/timeout/429; правильні метрики збоїв. Робочі томи й база недоступні ізольованим тестам; мережа вимкнена.

Повний фінальний набір: **526 тестів, 524 успішних, 2 пропущені**, 51,065 с. `git diff --check` пройшов.

## Розгортання

Зібраний образ 4.1.16 пройшов **101 цільовий тест**, `manage.py check` та `makemigrations --check --dry-run` без мережі й робочих томів. Попередній образ збережено як `schoolwork2-app:before-v4.1.16`. Узгоджена перевірена копія БД і файлів: `backups/2026-10-06_00-13-36_8J08gp`.

Оновлено `app` і `ai_worker`; обидва healthcheck пройшли. Сторінка входу відповідає HTTP 200, HTML містить 4.1.16, worker повідомляє 4.1.16 та актуальний heartbeat. Міграцій немає.

Після розгортання штатна черга трьох підключень OpenRouter/Groq перевірила роботу №42 на коді встановленого образу (без підміни модулів). Перша відповідь була HTTP 200 із `error.code=502`: Nvidia повідомила переповнену чергу воркера `16/16`. Новий адаптер правильно нормалізував її до 502, а evaluator виконав один дозволений повтор. Другий маршрут — Dots, яка раніше витратила 5380 токенів на міркування, — повернув повний результат за 49,32 с, 2734 вихідні токени, **0 reasoning tokens**, `finish_reason=stop`. Валідація завершилась `status=success`; наступні моделі не викликались. Порівняння повного запису Submission до й після транзакції: `saved_submission_unchanged=True`. Цей тест підтверджує і виправлення початкового reasoning-only збою Dots, і обробку прихованої помилки HTTP 200, і достатність нового часу очікування.
