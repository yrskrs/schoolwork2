## Знайдено під час перевірки

1. **Виправлено:** `COMPOSE_FILE` у серверному `.env` посилався на відсутній
   `compose.override.yaml`, тому `docker compose config` падав. Змінено на
   `compose.yaml:compose.tailscale.yaml`; резервна копія —
   `.env.bak-compose-file-20261108`. `docker compose config -q` тепер успішний.
2. **Конфігураційний ризик:** увімкнено `allow_without_link=True` (відкритий
   доступ). Через Funnel без посилання доступні опубліковані завдання, сторінки
   здачі, перегляду робіт і сповіщення (у відповіді є імена/класи). Це виглядає
   навмисним для школи, але якщо публічний Funnel не повинен показувати всі
   роботи — вимкніть відкритий режим і видайте учням посилання доступу.
3. **Посилення безпеки:** через HTTPS не встановлюються `Secure` для session і
   CSRF cookie; немає HSTS/CSP. LAN працює через HTTP, тому вмикати Secure
   глобально не можна без окремого HTTPS-режиму. Рекомендовано налаштувати
   HSTS/Secure на Funnel-рівні або окремим environment-профілем.
4. `/healthz/` через Funnel — 404; це правильно, але зовнішній монітор не
   повинен вважати сайт недоступним за цією адресою.
5. `/admin/` через Funnel віддає лише 302 на login, а `/admin/login/` — 404;
   адмін-вхід назовні не відкритий.
