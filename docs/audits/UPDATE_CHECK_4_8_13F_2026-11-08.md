# Виправлення перевірки оновлень для версій із літерою — 4.8.13f

## Симптом

На `/teacher/updates/` сторінка показувала:

> Не вдалося перевірити оновлення. Не вдалося перевірити GitHub:
> Некоректна версія на GitHub.

## Причина

`scripts/update_metadata.py::check_remote()` приймав лише суто числову
версію:

```python
if not re.fullmatch(r'\d+\.\d+\.\d+', remote_ver):
    raise ValueError('Некоректна версія на GitHub')
```

А `VERSION` на GitHub — `4.8.13e`, тому перевірка падала **до** читання
`RELEASES.json`/`CHANGELOG.md`.

Додатково були ті самі припущення в інших місцях:

- `version_tuple()` відкидав літеру, тому `4.8.13d` і `4.8.13e` виглядали
  однаково;
- `parse_changelog_markdown()` не розпізнавав заголовок `## 4.8.13e`;
- `scripts/select_release_image.py` відхиляв версію з літерою, тому
  майбутній `update.sh` не зміг би вибрати образ.

## Що виправлено

1. `version_tuple()` / `parse_version_tuple()` тепер розуміють літеру:
   `4.8.13 < 4.8.13a < 4.8.13d < 4.8.13e < 4.8.13f`.
2. Перевірка GitHub приймає `\d+\.\d+\.\d+[a-z]?`.
3. `CHANGELOG.md` парситься з заголовками `## 4.8.13e` та `## [4.8.13e]`.
4. `select_release_image.py` приймає версію з літерою.
5. Додано регресійні тести для сортування, CHANGELOG і GitHub-перевірки.

  помилки.
- На момент перевірки `raw.githubusercontent.com/.../main/VERSION` ще
  віддавав закешований `4.8.13e` (CDN GitHub), хоча закріплений коміт
  `9e85cba` уже містить `4.8.13f`. Це не помилка застосунку: після
  оновлення кешу перевірка побачить `4.8.13f`. Кеш GitHub може відставати
  на кілька хвилин.
