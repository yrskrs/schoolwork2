# Журнал реалізації ШІ-перевірки — 08.11.2026

Обсяг погоджено користувачем: локальна реалізація рекомендацій аудиту, синтетичні перевірки; тестування/встановлення на робочому сервері — окремий наступний етап.

## План і журнал

- Початковий стан: HEAD `c53924b`; наявні незакомічені файли попереднього аудиту збережено.
- Досліджено чергу, адаптери, учнівську самоперевірку, пакетну сторінку, критерії та тести.
- Створено ізольоване тестове Python-середовище у `/tmp/schoolwork-ai-venv`; залежності встановлюються окремо від проєкту. Робочі дані й сервер не використовуються.

Реалізовано: виправлення повноти доказів/контексту/авторства; межа приватності; вимірювання; квоти та слоти; паралельний worker і справедливість черги; серверний пакет із відновленням/скасуванням; локальна фонова підготовка й кешування; компактні відповіді.

### Виконані етапи

1. Додано міграцію 0073: стан координації, серверні пакети, метрики та відкладений запуск робіт, явний режим приватності. Міграцію виконано лише в тимчасових тестових БД.
2. Worker запускає обмежену кількість ізольованих процесів: типово 3 перевірки, з них 1 слот зарезервовано учням; ще 1 процес готує матеріали локально. Після трьох учнівських запусків звичайна черга отримує чергу, якщо для неї є місце.
3. Слоти перевіряють власника й мають строк дії довший за жорсткий таймаут процесу. Квоти спільної групи резервуються в БД перед кожним POST, включно з повторними викликами адаптера. Локальна відмова до надсилання не витрачає квоту. Відповіді 429 обробляються з Retry-After; робота повертається в чергу без витрачання учнівської спроби.
4. Додано налаштування квот на підключенні. Типово підключення одного провайдера об'єднано консервативно; незалежність проєктів потрібно явно вказати різними групами. Добовий бюджет обліковується у ковзному вікні 24 години, без припущення про часовий пояс скидання провайдера.
5. Пакет ставиться на сервер однією операцією, повторний request_id повертає той самий пакет, створення серіалізоване. Сторінка відновлює останній пакет, скасування не перериває вже запущених перевірок. Повторно відкладена робота скасованого пакета не запускається знову.
6. Після здачі/редагування завдання ставиться локальна підготовка без API. Конвертації захищено від одночасного повторення. Для паралельних SQLite-процесів усунено конфлікт підвищення read-транзакції до write через IMMEDIATE; PostgreSQL використовує блокування рядків.
7. Контекст зберігає три поля вчителя, попередні зауваження перездачі та знеособлені факти збігів. Прибрано обрізання зображень і текстового контексту під ліміт моделі. Читабельний текст не є підставою вилучати візуальний оригінал. Від двосторінкового пакування в API відмовлено: збереження локальних пікселів не гарантує, що провайдер не зменшить спільне зображення.
8. Компактні правила застосовуються також до Gemini; власні інструкції вчителя не обрізаються. Відповідь стисло покриває всі критерії. Явно відхилені параметри Gemini запам'ятовуються на 24 години за endpoint/model/значенням параметра, без збереження промпта чи ключа.
9. Відомі імена, назви файлів, email, українські телефони та приватні параметри URL очищуються перед API. Публічні параметри URL зберігаються. Зображення в дозволеному візуальному режимі перекодовуються без EXIF і без зміни декодованих пікселів. Це не приховує відомості на самих зображеннях.
10. Прибрано автоматичний штраф і штучне підвищення впевненості через стиль/метадані. Докладні промпти, коментарі та сирі відповіді більше не пишуться в діагностичні журнали оцінювання. Метрики містять час, байти, лічильники, статуси й ознаки влучення в кеш.
11. Браузерні запити під час очікування квоти стають рідшими. Перевірка доступу до пакета виконується одним запитом для всіх робіт; JSON-відповіді пакета підтримують gzip.
12. Worker повторно перевіряє ввімкнення модуля перед початком оцінювання. Старі тести з підміною оцінювача тепер явно вмикають модуль; новий тест підтверджує, що вимкнення зупиняє ще не розпочату перевірку без API-запиту. Додатковий конкурентний тест підтвердив одну PDF-конвертацію для чотирьох одночасних звернень.

## Рішення щодо якості та приватності

- Жодна оптимізація не має мовчки відкидати учнівські сторінки або критерії.
- Підозра використання ШІ подається вчителю окремо від змістового бала.
- Не обіцяємо повної анонімізації довільного файла: якщо очищення потрібних візуальних доказів не можна підтвердити, хмарний запит блокується з поясненням.
- Усі API-маршрути оцінювання, включно з резервними, проходять одну межу приватності.
- Точні робочі квоти налаштовуються за підключенням/спільною групою; їх не можна вважати незалежними лише через різні ключі.

## Перевірки

- Перший повний прогін: 977 тестів, 11 невідповідностей і 3 помилки. Усунено відсутню залежність qrcode, узгоджено тестове середовище з requirements-docker.lock; для реальних конвертацій синтетичних Office-файлів потрібен запуск поза обмеженнями sandbox. Застарілі очікування обрізання/автоматичної впевненості замінено перевірками нової погодженої поведінки; пошкоджені фіктивні файли в тестах транспорту замінено валідними синтетичними файлами.
- Повторний повний прогін: **977 тестів успішні, 2 пропущено**, 105,710 с. Після нього додано уточнення квот, кеш сумісності API та додаткові тести; потрібен фінальний повний прогін.
- Проміжний цільовий прогін: **122 тести успішні**.
- Наскрізний запуск із реальною чергою, окремими Python-процесами та фіктивним HTTP API лише на 127.0.0.1: 9 робіт успішні; відновлення після 429; контрольні імена/email не передані. Час цього тесту не є прогнозом швидкості хмарних моделей.
- Chromium: пакет надсилається один раз; перезавантаження відновлює пакет; скасування працює; текст учня екранується; JavaScript-помилок немає. Переглянуто знімки 1440 і 390 px.

### Остаточний результат

**987 тестів: 985 успішних, 2 пропущено, помилок немає**, 106,823 с. Два пропуски — спеціальні тести блокувань PostgreSQL; локальний набір використовує SQLite. Окремі перевірки Django, відповідності міграцій, залежностей і синтаксису JavaScript успішні. `git diff --check` не виявив проблем.

Додано **28 синтетичних тестів**. Уточнення в процесі також перевірено цільовими прогонами: зокрема 122, 31 та 71 тест успішні. Проміжні невідповідності після посилення перевірки ввімкнення модуля усунено явним налаштуванням старих тестових сценаріїв; окремий тест захищає нову відмову при вимкненому модулі.

Наскрізний тест: **9 успішних робіт, 10 HTTP-запитів, відновлення після одного 429, три використані фіктивні моделі, до двох одночасних HTTP-запитів у цьому запуску**. Контрольні імена/email не передані. 5,927 с — тривалість конкретного локального тесту з фіксованою затримкою фіктивного API, не прогноз хмарної перевірки. Раніший запуск без доданого 429 досягав трьох одночасних HTTP-запитів.

### Відтворення

Перевірений Python: `/tmp/schoolwork-ai-venv/bin/python`, Django 6.1.2, залежності `requirements-docker.lock`. У командах нижче `python` означає Python із цими залежностями. Потрібні системні LibreOffice/Poppler; для браузера — Node, Playwright і Chromium/Chrome (`CHROME_EXECUTABLE` може вказати на наявний браузер).

```bash
PYTHON_DOTENV_DISABLED=1 python manage.py check --settings=schoolnet.test_settings
PYTHON_DOTENV_DISABLED=1 python manage.py makemigrations --check --dry-run --settings=schoolnet.test_settings
PYTHON_DOTENV_DISABLED=1 python manage.py test --settings=schoolnet.test_settings --noinput
python scripts/test_ai_synthetic_runtime.py --output /tmp/ai-runtime-result.json
python scripts/render_ai_synthetic_pages.py
node scripts/test_ai_batch_browser.cjs
```

Наскрізний скрипт створює тимчасові БД/медіа/кеш/налаштування, вимикає завантаження `.env` і використовує лише HTTP API на 127.0.0.1. Браузерний скрипт перехоплює всі запити сторінки. Звичайні Django-тести використовують окрему тестову БД і тимчасові медіа. У цьому середовищі запуск LibreOffice, Chromium і локального HTTP-сокета потребував дозволеного виконання поза sandbox; це не було доступом до робочого сервера.

### Межі та наступний етап

- **Робочий сервер, його БД, конфігурація й установлені образи не змінювалися.** Випуск/розгортання не виконувалися; зміни залишені локально для перегляду.
- Реальні хмарні моделі не викликалися. Рівність якості між моделями, p50/p95 реальних перевірок і фактичні квоти ще не виміряні.
- Суворий режим типово блокує неперевірені зображення/PDF. Повної анонімізації довільного тексту або візуального вмісту не заявлено. Режим візуальної перевірки треба обрати свідомо; це описано в [інструкції](../guides/AI_CHECKING.md).
- На наступному погодженому етапі потрібні ізольована серверна перевірка PostgreSQL, контроль ресурсів worker/конвертерів, налаштування груп квот і перевірка погодженого знеособленого набору справжніми моделями. Синтетичні результати самі по собі не є дозволом на виробниче розгортання.
