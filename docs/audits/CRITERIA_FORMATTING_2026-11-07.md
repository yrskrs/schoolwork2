# SchoolNet 4.8.10: критерії, темна тема й текст DOCX

## Причина та виправлення

У завданні 93 ШІ сформував Markdown із заголовками, таблицею рівнів/балів/вимог, списками та кодом. Компонент criteria_modal показував поле як екранований звичайний текст із white-space:pre-line, тому розмітка не перетворювалася на таблицю й форматування. Переноси в цьому записі — звичайні Windows CRLF, а не текстові послідовності `\r\n`.

Додано окремий renderer `feed/criteria_rendering.py` на markdown-it-py 4.2.0 (mdurl 0.1.2 у серверному lock). Режим js-default із html=False, вимкненими зображеннями та штатною перевіркою URL. Довільний HTML залишається текстом, небезпечні протоколи посилань не виконуються, зовнішні зображення не завантажуються автоматично. Налаштування відповідають [рекомендаціям бібліотеки для недовіреного тексту](https://markdown-it-py.readthedocs.io/en/latest/security.html).

Метод Assignment.get_formatted_custom_criteria використовується спільним вікном критеріїв на сторінці завдання та здачі. Збережене поле не переписується: редактор, архіви, дублювання та оцінювання ШІ отримують попередній точний текст. Уже створені завдання не потребують повторної генерації; міграцій немає. Запит до помічника уточнено: Markdown із короткими заголовками, списками й за потреби таблицею, без HTML і загальної обгортки кодом.

Вікно розширено до 900 px на desktop; довгі назви переносяться. Таблиці оформлені в кольорах поточної теми. На телефоні горизонтально гортається лише таблиця, з підказкою та фокусованою областю для клавіатури; решта вікна залишається в межах екрана. Нижня кнопка закриття й вертикальний скрол збережені. Інші критерії, політика ШІ та її дозволи не змінені.

## Перевірки

- 8 нових тестів renderer: таблиці/заголовки/списки/код, звичайний текст і CRLF, порожній вміст, HTML/script/iframe, небезпечні посилання, відсутність автоматичних зображень, звичайні посилання та незмінність джерела при рендерингу моделі й шаблону.
- 45 цільових перевірок renderer, помічника ШІ, редактора, сторінки завдання та здачі пройшли. Новий тест помічника підтверджує вказівку використовувати Markdown.
- Для локальної перевірки використано копію лише назви та критеріїв завдання 93 в окремій тимчасовій SQLite, без навчальних даних чи запису на робочий сервер. Повторний запит до платного ШІ не виконувався.
- У браузері перевірено точний зразок критеріїв завдання 93: таблиця з чотирма рівнями, заголовки, списки й код. Перевірені desktop у світлій темі та телефон у темній; на 320 px вікно залишається в межах екрана, таблиця горизонтально гортається окремо, у тому числі клавішею ArrowRight. Знімки й метрики збережені локально.
- Фінальний серверний образ: **953 тести, OK (skipped=2)**, 87,2 с; **35 перевірок оновлювача, OK (skipped=1)**.

## Додаткові виправлення з перегляду користувача

У короткому описі завдання 99 був вставлений span з background-color:rgb(248,249,250). Темна тема окремо примусово задавала світлий колір тексту — на світлому тлі це робило фрагмент нечитабельним. Scoped CSS для темної стрічки робить тло вставлених фрагментів прозорим і успадковує колір опису. Оригінал опису, форматування жирним/курсивом та посилання збережені; світла тема й верхня панель не перероблені. У браузері підтверджено зміну з rgb(248,249,250) на прозоре тло й збіг кольору тексту з батьківським блоком. Ключ кешу CSS оновлено.

Для файла 215 із завдання 97 режим mode=text уже викликав конвертер, але декоратор для складних DOCX замінював отриманий HTML зображеннями сторінок і використовував спільний кеш із графічним переглядом. Додано reading_mode до обгортки конвертації: у режимі читання цей крок пропускається, а ключі кешу відокремлені. Графічний режим та вчительський перегляд залишаються попередніми. З оригінального файла витягнуто 1831 символ і 14 абзаців; перевірено в браузері: 0 PDF/iframe та 0 растрових сторінок, текст доступний для виділення. Вбудовані в сам документ ілюстрації збережені. Оригінальний DOCX не змінений.

Додано регресію для складного DOCX з прогрітим графічним кешем, читанням і повторним графічним відкриттям; серверний endpoint передає reading_mode. 24 цільові перевірки матеріалів, критеріїв та доступу пройшли. Перший повний прогін зупинив розгортання через стару перевірку буквального «1. Теза» в HTML: тепер це семантичний ol/li із нумерацією браузера. Тест оновлено на перевірку всіх трьох пунктів у сторінках завдання й здачі. До успіху повторного прогону робочі контейнери залишалися на 4.8.9.
