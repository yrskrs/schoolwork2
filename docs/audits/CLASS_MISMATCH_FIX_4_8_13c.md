# Виправлення хибних `class_mismatch` — 4.8.13c (2026-11-08)

## Проблема

`feed/gemini_service.py` → `detect_invalid_or_teacher_template_submission()`
ловив будь-який фрагмент «цифра-літера» через альтернативу
`\s*-\s*[А-Яа-яA-Za-z]`. Через це `4-a` у
`"packageVersion":"0.8.4-alpha2"` усередині ZIP-моделі Teachable Machine
перетворювалося на «4 клас» і блокувало 9 робіт 8-Б.

## Що змінено

- Дозволено лише явні форми: `N клас`, `N класу`, `N-й клас`,
  `N-го класу`, `N кл.`, `N-А клас`, `N-Б класу` (велика українська
  літера після дефіса + слово «клас»/«класу»/«кл.»).
- Перед пошуком маскуються семантичні версії, поля
  `packageVersion`/`version`/споріднені, UUID, hex, base64 і код у
  markdown-блоках.
- Вміст архівів, коду та моделей не перевіряється: для них
  аналізується лише назва файлу. Це прибирає ZIP-моделі з перевірки.
- Для таблиць, де заголовок «Клас» стоїть окремо, а в клітинках лише
  `11-А`, такий токен зараховується тільки за наявності явного слова
  «клас»/«кл.» у тексті. Сам по собі `11-А` (як і `4-a`) не блокує.
- Кожне блокування `class_mismatch` пише в журнал код, клас, очікувані
  класи, знайдений клас і фрагмент-тригер. У повідомленні вчителю
  показується безпечний фрагмент: для таблиці — лише клітинка, без
  імен інших учнів.
