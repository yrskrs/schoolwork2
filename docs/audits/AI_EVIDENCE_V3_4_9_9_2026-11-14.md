# Реліз 4.9.9 — доказове оцінювання без галюцинацій: техпаспорти, guardrails і захист від обходів

**Дата:** 14.11.2026 · **Версія:** 4.9.9 · **Статус:** реалізовано, незалежно
перевірено, повний набір тестів зелений.

## Що увійшло в реліз

Реалізовано три рівні захисту від вигаданих доказів і суперечностей ШІ
(робота-прецедент №617: `.xlsx` без жодної формули, а модель хвалить
«застосування IF») та закрито всі P0/P1 з двох наступних аудитів.

### Рівень 1 — детерміновані технічні паспорти файлів

- `.xlsx/.ods`: формули за `cell.data_type=='f'` (+ArrayFormula/DataTableFormula),
  умовне форматування, data validation, іменовані діапазони; перелік функцій;
  `formulas_count==0` → точний маркер. Текстова «формула» (`'=IF(...)`) більше
  не зараховується як справжня.
- `.py`: `ast.parse`, синтаксичні помилки, цикли/функції/розгалуження,
  «лише статичний вивід» лише для літеральних `print`; `runtime_verified=False`.
- `C++/JS/Java/Go/…`: статичні факти конструкцій, `no_code_constructs`,
  явне обмеження «синтаксис/запуск не перевірено».
- `.pptx/.odp`: слайди, порожні слайди, нотатки доповідача, SmartArt/діаграми.
- `.docx/.odt/.pdf`: слова/абзаци, зокрема текст у `w:sdt`, текстових блоках,
  SmartArt; порожній документ без хибних спрацювань.
- `.sb3`: реальні блоки коду, події запуску, скрипти; 0 блоків → маркер.
- `.accdb/.mdb`: таблиці, запити, зв'язки (за наявності `mdbtools`).
- `.csv/.tsv`, `.txt/.md/.rst`: verified `text_table`/`text_document`,
  instruction-like фрази, `audit_complete`; DoS-ліміти розпакування та
  парсингу `.sb3/.docx/.pptx/.xlsx`.
- Неперевірені формати (PDF, зображення, архіви, legacy Office, перейменовані
  файли) отримують unverified-заглушку: це не «тихий» обхід, а
  `implementation_unverified`.

### Рівень 2 — правила нульової толерантності

- `ASSESSMENT_RULES`/`COMPACT_ASSESSMENT_RULES` і системні пресети містять
  заборону хвалити відсутній елемент, стелі балів, правило «вигадане
  твердження → не Високий (≤9)», пріоритет вимоги вчителя, англійські
  синоніми/«ЯКЩО»/«ЕСЛИ», unverified-формат.
- Legacy-дефолтні системні промпти більше не інжектяться; кастомний
  `AISettings.system_prompt` додається після предметного промпту пресета;
  compact-провайдери обмежені системним бюджетом.
- Паспорти й аудит-прогалини передаються в обидва варіанти промпту.

### Рівень 3 — post-processing guardrails

- Видалення вигаданих похвал зі `strengths/summary/grade_explanation/
  feedback_comment`, очищення коментарів ГР, `unverifiable → missing` для
  доведеної відсутності.
- Per-file логіка (стара + виправлена робота не карається), перевірка
  конкретної функції/конструкції навіть коли інші формули є, clause-level
  аналіз («але/проте»), IF-логіка/ЯКЩО/ЕСЛИ.
- Стелі для формул/коду/слайдів/Scratch/БД, `format_gap` для PDF/скану
  (числовий бал ≤9 замість блокування), авторська шкала `custom_criteria`
  не ріжеться до 6, дублікат — детермінована стеля 4.
- Немає файлів/лише коментар/посилання на технічну вимогу —
  `implementation_unverified`/стеля 9; есе/усні не караються.
- Явний teacher waiver (лише в межах клаузи) поважається, але не скасовує
  видалення вигаданої похвали.

### Приватність, надійність, безпека

- Audit-блок більше не потрапляє учню; student-поля беруться лише з
  `student_ai_feedback`; raw-імена файлів не в публічних коментарях.
  Учитель бачить факти окремо (`Submission.ai_technical_evidence`,
  панелі `file_viewer`/`ai_job_payload`).
- `job_response(student_check)` — явний whitelist; provenance — evidence-gate
  (сирий model-only percent/boolean не дає «виявлено ШІ»).
- Duplicate-детектор перевіряє всі файли й анонімізує дані для учня;
  старі бекапи без нового поля відновлюються; journal API позначає
  AI-пропозицію; приватні вказівки не потрапляють у `student_explanation`.
- Міграції `0081_submission_ai_technical_evidence` і
  `0082_normalize_legacy_ai_defaults`.
