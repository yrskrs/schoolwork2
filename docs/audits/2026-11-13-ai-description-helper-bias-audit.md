## 0. Відповіді на головні питання

**1. Чи є упередження/жорсткі вставки, які впливають на генерацію всупереч умовам учителя?**
Так. Це не «характер моделі», а закладені в коді конструкції:

- у промпті жорстко прописана одна модель завдання — **письмова робота з файлом**, з блоками `📌 Вказівки до роботи`, `⚠️ Увага (вибір завдання)`, `📁 Вимоги до здачі`, з фразами «Збережіть результат під своїм прізвищем» і «Прикріпіть та завантажте збережений файл…». Модель відтворює цей каркас майже дослівно; живий приклад це показує (розділ 7, додаток Б);
- «вибір» зашитий як **«одне завдання на вибір відповідно до бажаної оцінки»** + шаблон «Завдання 1 (максимум N балів)», навіть коли вчитель про оцінку не писав;
- мова виводу жорстко **українська**, навіть для англомовного завдання;
- після генерації працює **евристичний фільтр** `_clean_hallucinated_choice_block`, який за підрядками слів видаляє цілі шматки відповіді. Він має критичні хибні спрацювання: знищує **легітимний** блок вибору («Оберіть один варіант», «2 з 3», «на ваш розсуд»), видаляє будь-яке загальне `⚠️ Увага:`, а після блоку може «з'їсти» дедлайн/критерії або взагалі повернути порожній опис зі статусом `success`.

**2. Чи впливає це на генерацію «за умовами вчителя»?**
Так, і в обидва боки:

- **надмірна генерація**: додає вимоги, яких учитель не давав (здача файлу, «бажана оцінка», бали, «під своїм прізвищем», інколи навіть «без файлу робота не зараховується»);
- **втрата умов**: фільтр видаляє справжній вибір, а разом із ним — наступні розділи; опис може стати коротшим за вчительський або порожнім;
- згенерований опис далі читає **автоматичне оцінювання** (парсер вибору, стеля балів за неповний обсяг), тому викривлений опис впливає і на оцінки.

**3. Чи працюватиме це на інших завданнях?**
Недостатньо. Поточна реалізація розрахована на один сценарій: письмова робота з файлом, 12-бальна оцінка, українська мова, вибір «одне з N за бажаною оцінкою». Ламається або спотворюється на:

- усних / оглядових завданнях і завданнях без здачі файлу (`no_submission_required`);
- тестах і онлайн-відповідях;
- завданнях, де матеріали — це посилання/YouTube, а не файли;
- виборі «2 з 3», «одне обов'язкове + одне на вибір», «на розсуд», виборі без прив'язки до оцінки;
- завданнях зі звичайною (traditional) або заліковою системою оцінювання;
- англомовних / іншомовних завданнях;
- математичних і програмістських умовах із символами `<`/`>` (окремий баг, розділ 4.3);
- довгих описах (жорсткий ліміт `max_output_tokens=3500` без повтору).

**4. Що робити?**
Мінімально необхідне — P0 у розділі 5: зробити фільтр fail-open (не видаляти, якщо є сумнів), не повертати порожній `success`, прибрати з промпту суперечливі/примусові рядки, передати в промпт `no_submission_required`, тип оцінювання, мову та матеріали-посилання. Далі — P1/P2: динамічна структура під тип завдання, валідація збереження фактів, регресійні тести.

**Загальний вердикт:** ідея помічника правильна і корисна, промпт дає передбачуваний, читабельний результат, але **поточний guardrail небезпечніший за проблему, яку він лікує**, а промпт занадто жорстко закодований під один тип завдання. Потрібне доопрацювання перед масовим використанням на різних предметах.

## 2. Як зараз працює ланцюг

```
Вчитель у редакторі
  ├─ «Ваша чернетка або вказівки»        → teacher_notes
  ├─ поточний текст редактора             → current_description (HTML → strip_html_tags)
  ├─ тема / предмет / класи               → title / subject_name / class_group_name
  └─ has_materials (файли на формі)       → bool
        │
        ▼  POST /teacher/assignment/refine-description/
  endpoint (валідація, ліміти, 20 запитів/хв)
        │
        ▼
  refine_assignment_description_with_gemini
  ├─ контекст: предмет, клас, тема, notes («найвищий пріоритет»), current_description
  ├─ промпт: §1 пріоритет, §2 зміст, §3 вибір/бали, §4 здача, §5 «рекомендована структура», §6 формат
  ├─ виклик моделі: system_prompt="", max_output_tokens=3500, timeout=35,
  │                 thinking_budget=0 для Gemini-flash, temperature з AISettings
  └─ пост-фільтр _clean_hallucinated_choice_block(notes, current_description)
        │
        ▼
  MarkdownIt(html=False) + sanitize_html
        │
        ▼
  UI-прев'ю → «Замінити опис у редакторі» (innerHTML / textarea)
```

Ключові особливості:
- ніякої валідації сенсу відповіді (окрім санітизації HTML) немає;
- фільтр застосовується після відповіді моделі й може змінити її безповоротно;
- згенерований текст одразу стає «описом завдання», який бачать учні та читає оцінювальний ШІ.

## 4. Знахідки

### 4.1. Промпт: жорсткі вставки та упередження

#### P-01. 🔴 Critical — Модель зобов'язана відтворювати один жорсткий шаблон завдання

**Де:** `feed/gemini_service.py:8622-8641` (§5 «РЕКОМЕНДОВАНА ЛАКОНІЧНА СТРУКТУРА»), плюс `:8619-8620` (§4).

Промпт дає не «пораду», а готовий скелет:

```
📌 **Вказівки до роботи:**
1. …
2. …
3. Збережіть результат під своїм прізвищем.

⚠️ **Увага (вибір завдання та оцінювання):** …
📁 **Вимоги до здачі:**
• Прикріпіть та завантажте збережений файл роботи у формі здачі нижче.
```

**Доказ:** живий скріншот `.local-audits/qa-4.9.4/ai-live-generation-materials.png` (додаток Б) — модель `deepseek-chat` відтворила ці рядки майже дослівно, включно з «Збережіть результат під своїм прізвищем» і «📁 Вимоги до здачі». Другий скріншот показує, що з'явилося навіть вигадане правило «Робота здається лише як прикріплений файл — без прикріплених файлів завдання не зараховується».

**Чому це проблема:** для усного завдання, тесту, роботи в зошиті, уроку-екскурсії ця структура не має сенсу; вона підміняє методику вчителя універсальним «зроби файл і здай». Крім того, шаблон змушує модель додавати пункти, яких учитель не просив.

**Рекомендація:** збирати структуру **динамічно** під тип завдання (письмова робота з файлом / усна / тест / робота з матеріалами / вибір / обов'язкові) і не тримати в промпті готові рядки, які модель копіює. «Рекомендовану структуру» замінити на короткі принципи, а не на зразок тексту.

#### P-02. 🔴 Critical — Примусова здача файлу ігнорує `no_submission_required`

**Де:** промпт `feed/gemini_service.py:8636`, `:8640-8641`; поле `feed/models.py:777-781`; чекбокс `templates/feed/components/assignment_editor/publication.html:14-21`; endpoint `feed/views.py:8731-8738` (прапорець **не передається**).

**Доказ:** наскрізний прогін (замоканий `call_ai_api`) з notes «Усна відповідь, нічого здавати не треба» → у фактичному промпті все одно присутні `📁 **Вимоги до здачі:**`, «Прикріпіть та завантажте…» і «Збережіть результат під своїм прізвищем». У формі при цьому може стояти прапорець «Не вимагає здачі робіт», а на сторінці завдання кнопка здачі прихована (`templates/feed/assignment_detail/*`, `feed/views.py:2939`).

**Рекомендація:** додати в сигнатуру `refine_assignment_description_with_gemini` та в endpoint параметр `no_submission_required` (і, бажано, `task_type`), а в промпті або не включати файлові блоки, або замінювати їх на «усна відповідь / робота в зошиті / відповіді в системі».

#### P-03. 🔴 Critical — Примусова українська мова ламає іншомовні завдання

**Де:** `feed/gemini_service.py:8644` («Зрозуміла, доброзичлива українська мова»), а також увесь список ключових слів фільтра `:8506-8507` — лише українською.

**Доказ:** репро з notes `«Students choose one of 3 tasks; no file needed»` (subject «Англійська мова») → у промпті все одно «українська мова», а фільтр не бачить англійського «choose one of 3» і **видаляє легітимний блок вибору**.

**Рекомендація:** мова результату = мова завдання/предмета (параметр `language`, з fallback на українську); фільтр зробити мовно-нейтральним або структурним (див. G-01).

#### P-04. 🟠 High — Матеріали враховуються лише як файли; посилання/YouTube не передаються

**Де:** `templates/feed/assignment_form.html:1003-1011` (`hasMaterials` = `.existing-file-item` + `input[type=file]`), промпт `feed/gemini_service.py:8595-8602`.

Не враховуються:
- `link_url`, додаткові посилання `AssignmentLink`, YouTube-посилання (`feed/models.py:664-679`, `:1755-1815`);
- прапорець `is_task_source_for_ai` (який файл є умовою, а який — матеріалом);
- файли, позначені на видалення.

**Доказ:** notes «Перегляньте відео за посиланням та дайте відповіді…» → промпт іде гілкою «До завдання НЕ прикріплено файлів: не згадуй „прикріплені матеріали“». Тобто модель отримує **хибний факт** про відсутність матеріалів. Живий скріншот без матеріалів показує, що модель не розрізняє «матеріали» і «файл, який здають», і здатна вигадати жорсткішу вимогу здачі.

**Рекомендація:** передавати окремі `has_files`, `has_links`, `has_youtube` (і, за потреби, назви/URL); у промпті розділити «матеріали завдання» і «файл, який здають»; дозволяти переказ матеріалів, якщо вчитель прямо просить.

#### P-05. 🟠 High — «Вибір» нав'язаний як «одне завдання на бажану оцінку»; немає «2 з 3»

**Де:** `feed/gemini_service.py:8606-8617` (§3).

- дозволені лише дві гілки: «вчитель прямо вказав вибір» → обов'язкова фраза «Оберіть та виконайте **одне завдання на вибір** відповідно до бажаної оцінки:» (`:8608`) і «Завдання 1 (максимум N балів)» (`:8609`); або «всі обов'язкові»;

#### P-06. 🟠 High — Самосуперечність §3 і §5; негативні приклади можуть відтворюватися

**Де:** §3 `feed/gemini_service.py:8613-8615` («КАТЕГОРИЧНО ЗАБОРОНЕНО писати „на вибір“…», «блок НЕ створювати взагалі») і §5 `:8638` — той самий заголовок `⚠️ **Увага (вибір завдання та оцінювання):**` у «рекомендованій структурі».

Модель отримує і «не роби цього», і «ось як це має виглядати». У живому прикладі (стара версія промпту) вона відтворила блок дослівно; у прикладі без вибору — не відтворила. Поведінка недетермінована, саме тому й з'явився пост-фільтр.

**Рекомендація:** прибрати `⚠️`-рядок із §5 зовсім; збирати §5 динамічно (окремий текст для вибору і для обов'язкових). Негативні приклади («не пиши X») замінити позитивними вимогами, де можливо.

#### P-07. 🟠 Medium — «АБСОЛЮТНИЙ пріоритет» і «ПОВНІСТЮ ВИДАЛЕНІ» можуть знищувати доречні деталі

**Рекомендація:** «зміни/видали лише те, що прямо суперечить новим вказівкам; усі інші умови збережи»; перелічити, що заборонено втрачати без прямої вказівки.

#### P-08. 🟠 Medium — Літерал `N` і жорстка нумерація «Завдання 1/2»

**Де:** `feed/gemini_service.py:8609` («Завдання 1 (максимум N балів)»).

**Рекомендація:** прибрати `N` з прикладу або явно пояснити, що це плейсхолдер; додати вимогу зберігати фактичні номери з notes/опису.

#### P-09. 🟡 Low — Текст учителя вставляється в промпт без розмежування «дані vs інструкції»

Ризик обмежений (ендпоінт лише для вчителя, ліміт 8000 символів), але якщо в тексті є «ігноруй попередні правила» — модель може це сприйняти як інструкцію. ### 4.2. Пост-фільтр `_clean_hallucinated_choice_block` (найризикованіше місце)

Функція: `feed/gemini_service.py:8497-8529`. Виклик: `:8706`. Логіка: якщо в notes є «обидва/всі/усі/кожен/кожне» **або** notes непорожні й не містять слів зі списку «вибір/одне завдання/одне з» → видалити рядки, починаючи з `⚠️` + «вибір»/«увага», і все до наступного `📁`/`📌`/`#`/«вимоги до здачі».

#### G-01. 🔴 Critical — Видаляє легітимний блок вибору

Список `has_choice` (`:8507`) не покриває типові формулювання: «оберіть один варіант/одного з», «виберіть одну з трьох», «обрати один із», «2 з 3» (без слова «вибір»), «два з трьох», «на ваш розсуд», «за бажанням», «будь-яке». Репро: notes «Оберіть один варіант» → блок вибору видалено (298 → 111 символів); те саме для «Оберіть 2 з 3 завдань», «на ваш розсуд», «Оберіть один із трьох». **Це найчастіші живі формулювання вчителя.** Якщо ж у notes уже є слово «вибір», фільтр не запускається — поведінка непередбачувана.

#### G-02. 🔴 Critical — Підрядки «всі/усі/кожен/обидва» перекривають явний вибір

`explicit_all` (`:8506`) шукає підрядки без меж слів і без заперечень, і має вищий пріоритет за `has_choice` (`:8509`):

- «**Не всі** завдання обов'язкові, можна обрати одне» → блок видалено;
- «Поясніть **усім** учням, завдання на вибір» → видалено;
- «На **кожен** урок — одне завдання на вибір» → видалено;
- «Поясніть **обидві** формули, завдання на вибір» → видалено.

#### G-03. 🔴 Critical — «З'їдає» довільний текст після блоку

Стан `skip_block` (`:8518-8522`) тримається до рядка, що починається з `📁`, `📌`, `#`, або містить «вимоги до здачі». Якщо після блоку йде «Термін здачі…», «**Критерії оцінювання:**», «**Додаткові умови:**» або `---`, ці рядки **безслідно зникають**. Якщо блок стоїть останнім — зникає все, що було після нього.

#### G-04. 🟠 High — `success` з порожнім описом → вчитель бачить порожнє прев'ю без помилки

Якщо весь вивід — це ⚠️-блок, фільтр повертає `''`. Повторної перевірки немає: функція повертає `status: success`, `markdown: ''`, `html: ''` (`:8706`, `:8716-8721`), endpoint — `HTTP 200`/`success` (`feed/views.py:8740-8746`).

**Уточнення (перевірено репро):** редактор **не стирається**, бо в UI є запобіжник `if (!lastGeneratedHtml) return;` (`templates/feed/assignment_form.html:1094`). Але вчитель бачить блок «✅ Згенерований опис завдання» з порожнім прев'ю, кнопка «Замінити опис» нічого не робить і жодної помилки не показує. Це хибний контракт API `success ≠ валідний результат`, а не втрата даних. Ризик стає критичним, якщо запобіжник у UI колись приберуть або змінять.

#### G-05. 🟠 High — Видаляє будь-яке загальне `⚠️ Увага:`

Тригер `:8515`: `⚠️` + (`вибір` або `увага`). Коли фільтр запускається, будь-яке попередження («не забудьте зберегти файл», «дедлайн у п'ятницю») містить «увага» → видаляється. Якщо ж емодзі немає (`**Увага:**`), воно не видаляється — тобто поведінка неконсистентна.

#### G-06. 🟠 High — Не працює для шляху «лише чернетка в редакторі»

`explicit_all` читає лише `teacher_notes` (`:8506`), а запуск вимагає непорожніх notes (`:8509`). Якщо notes порожні, а «виконати обидва» є в `current_description`, фільтр **не запускається** і галюцинований блок вибору лишається. Це сценарій, коли вчитель просто редагує існуючий опис.

#### G-07. 🟠 High — Заперечення вибору сприймається як вибір; заборонені фрази не розпізнаються

- «**Не** на вибір, обов'язково» → підрядок «на вибір» → `has_choice=True` → блок лишається.
- «Обидва завдання виконувати не потрібно» / «Не потрібно виконувати обидва завдання» / варіанти з `**` — точні підрядки `:8524` не спрацьовують.
- Блок без емодзі `⚠️` (`**Увага (вибір завдання та оцінювання):**`) не розпізнається.

**Загальний висновок по фільтру:** він реалізує крихку евристику «немає слова зі списку — отже, вибору не було» і замість захисту стає генератором нових відхилень. Потрібен fail-open підхід: у сумнівних випадках **не змінювати** текст, а краще — взагалі відмовитися від пост-обробки на користь структурованого виводу.

### 4.3. Даних не вистачає або вони спотворюються

#### D-01. 🟠 High — Форма передає лише частину контексту

Endpoint (`feed/views.py:8680-8751`) приймає: `teacher_notes`, `current_description`, `assignment_title`, `subject_name`, `class_group_name`, `has_materials`. Не передаються:

- `no_submission_required`;
- `ai_thinking_mode` / `default_thinking_mode` (режим мислення завдання);
- посилання, YouTube, додаткові матеріали;
- `is_task_source_for_ai` (який файл є умовою);
- тип оцінювання (`evaluation_type` пресета) і шкала;
- мова завдання;
- тип завдання (усне/тест/лабораторна/проєкт);
- для редагування — `assignment_id`, щоб сервер сам зміг прочитати ці поля.

**Наслідок:** модель змушена вгадувати, і вгадує за шаблоном.

#### D-02. 🟠 High — `has_materials` — клієнтська евристика, а не факт із БД

JS (`templates/feed/assignment_form.html:1003-1011`) рахує `.existing-file-item` і вибрані файли. Це:

- не враховує посилання/YouTube;
- рахує файли, позначені на видалення;
- не розрізняє «файл-умова» і «матеріал»;
- залежить від розмітки/вкладки, а не від даних завдання;
- при створенні/редагуванні може давати різний результат.

Для edit-режиму сервер міг би взяти ці факти з `Assignment`, але не робить цього.

#### D-03. 🟠 High — Жорсткі ліміти моделі: 3500 токенів, thinking=0 для flash

**Де:** `feed/gemini_service.py:8668-8683`.

- `max_output_tokens=3500` без повтору/збільшення: довгий або детальний опис може обірватися; `MAX_TOKENS` у `call_ai_api` повертається як помилка (`:584-599`, `:725-731`), і вчитель бачить загальне «Не вдалося сформулювати опис через тимчасову недоступність» — без пояснення, що це ліміт. На відміну від оцінювання, де є повтор із більшим бюджетом (`feed/gemini_service.py:7031-7105`), тут цього немає: усі моделі черги перебираються з тим самим бюджетом, тож 4 моделі = 4 однакові невдачі.
- `thinking_budget=0` для будь-якої Gemini-flash моделі — примусово, незалежно від `AISettings.default_thinking_mode` (`feed/models.py:3679`) і `Assignment.ai_thinking_mode` (взагалі не передається). Усі дефолтні моделі в черзі — flash, тож за замовчуванням «глибоке мислення» вимкнене завжди.

Інші налаштування генерації (temperature, system_prompt, timeout, custom_model, connection_id) — див. D-07.

#### D-04. 🟠 High — `strip_html_tags` псує математичні/програмістські умови

**Де:** `feed/gemini_service.py:3470-3501`, застосування до `current_description` — `:8556`.

Функція видаляє все, що схоже на HTML-тег (`<[^>]+>`). Для умов із символами «менше/більше» це руйнує текст:

```
'Порівняйте 2 < 3 і 5 > 4'  →  'Порівняйте 2 4'
'Знайти x, якщо x < 10 > 3' →  'Знайти x, якщо x 3'
```

Це прямий genericity-баг для математики, інформатики, фізики.

**Рекомендація:** не проганяти plain-text через HTML-очищення або використовувати безпечний парсер, який не чіпає одиночні `<`/`>`, і екранувати лише реальні теги.

#### D-05. 🟠 Medium — Сирий HTML у `teacher_notes`

`teacher_notes` лише `.strip()` (`:8554`), без `strip_html_tags`. Кнопка «Взяти поточний текст із редактора» в режимі HTML-коду копіює `descTextarea.value` (сирий HTML) — див. `templates/feed/assignment_form.html:954-968`. Модель отримує теги (включно з `<script>`) як «вказівки з найвищим пріоритетом», хоч їй заборонено їх виводити. Додатково: `current_description` очищується, тому він **не дорівнює** `teacher_notes` (сирий HTML) → у контекст потрапляють обидва блоки, і той самий текст дублюється (`:8570-8575`).

#### D-06. 🟡 Low — Немає серверної перевірки, що згенерований текст зберіг факти вчителя

Немає перевірки, що в результаті лишилися числа/бали/дати/формати файлів/назви з notes. Немає diff-перегляду; є лише `confirm()` і повна заміна. Для критичних деталей це ризик тихої втрати.

#### D-07. 🟠 Medium — Налаштування генерації з `AISettings` не доходять до помічника

**Де:** `feed/gemini_service.py:8652`, `:8669`, `:8672`, `:8680`, `:8683`; `feed/models.py:3671-3682`; `feed/views.py:8731-8738`.

- `default_thinking_mode`/`Assignment.ai_thinking_mode` ігноруються; thinking вимикається за підрядком `'flash'` у назві моделі.
- `AISettings.system_prompt` не читається ні помічником опису, ні генератором критеріїв (використовується лише `preset.system_prompt` в оцінюванні).

- `timeout=35` для не-Gemini провайдерів; в evaluation — 50 с для Gemini, 35 с для решти (90 с лише для router-retry, `feed/gemini_service.py:7060`, `:7082`).

**Наслідок:** адміністратор змінює налаштування, а генерація їх не застосовує; діагностика слабша, ніж в оцінюванні.

### 4.4. Надійність, UX, тести, процес

#### R-01. 🟠 High — Тести фільтра покривають лише два щасливі кейси

Потрібні behavior-тести (що модель отримує релевантний контекст), а не string-matching промпту.

#### R-03. 🟠 Medium — Ослаблені перевірки `scripts/ai-lab.sh` у тому ж коміті

#### R-04. 🟡 Low — Немає спостережуваності фільтра та збоїв

Неможливо зрозуміти, як часто й на чому фільтр шкодить у продакшені, і чому конкретний запит повернув порожній/обрізаний опис.

Порожній результат редактор не стирає (є guard `if (!lastGeneratedHtml) return;`), але втратити авторське оформлення при непорожній заміні цілком реально.

#### R-07. 🟡 Low — Rate-limit працює на процес, а не на систему; журнал перемикань може брехати

- `_ai_refine_rate_limited` (`feed/views.py:8666-8675`) використовує `django.core.cache.cache`; у проєкті це `LocMemCache` (`schoolnet/settings.py:187-188`). При кількох gunicorn-воркерах «20/хв на вчителя» множиться на кількість процесів, а після рестарту кеш обнулюється. Для антиспаму прийнятно, але не як захист дорогих запитів.
- `refine_assignment_description_with_gemini` вручну інвертує `is_backup_active` при відсутньому основному ключі (`:8544-8552`), а `get_request_configs()` будує конфіги від неперевернутого `get_active_config()` (`:8657`); через це перший конфіг може отримати `is_failover=True` і в `last_failover_reason` запишеться «автоматичний перехід», хоча резервний використано як основний. На роботу не впливає, але журнал перемикань неправдивий.

#### X-01. 🟠 Medium — `generate_criteria_with_gemini` жорстко кодує 12-бальну НУШ

#### X-02. 🟠 Medium — `generate_age_appropriate_student_guide` жорстко кодує файлову здачу

**Де:** `feed/gemini_service.py:8832+`, наприклад `:8935`, `:8946`, `:8957`, `:8975`, `:8985`, `:9026` — крок «Збережи файл / завантаж на платформу». Для усних/безфайлових завдань шаблон так само суперечить `no_submission_required`.

#### X-03. 🟠 Medium — Немає спільної інфраструктури промптів

Кожен генератор будує промпт окремо, з власними hardcoded-рядками; немає версіювання, спільного конфігу, snapshot-тестів і єдиного місця для «правил генерації». Це корінь genericity-проблем: виправлення в одному місці не поширюється на інші.

#### X-04. 🔴 High — Ендпоінт критеріїв падає 500 на не-string JSON, без rate-limit, тече деталі провайдера

**Де:** `feed/views.py:8599-8608` (`teacher_generate_assignment_criteria`).

- `body.get('teacher_notes', '').strip()` без перевірки типу: POST `{"teacher_notes": 123}`, `{"teacher_notes": null}`, `{"assignment_description": {"a": 1}}` → `AttributeError` → **HTTP 500** (перевірено 3/3). **Рекомендація:** винести валідацію/очищення в спільний хелпер для обох ендпоінтів, додати rate-limit, повертати 400 на некоректний JSON, санитизувати текст помилки.

## 5. Пропозиції (за пріоритетом)

### P0 — безпека даних учителя (виправити перед масовим використанням)

1. **Зробити фільтр fail-open і безпечним.**
   - Видаляти лише точний блок, що починається з `⚠️ ... (вибір` (не за словом «увага»), і лише якщо впевнено визначено **кінець** блоку: порожній рядок + наступний рядок не є пунктом/продовженням; якщо кінець не визначено — **не змінювати текст**.
   - Не запускати фільтр на основі підрядків у notes. Використовувати єдиний класифікатор наміру (`none / one_of_N / M_of_N / free`), який читає `notes + current_description`, враховує заперечення й кількісні формулювання; у стані «невідомо» — не чистити.
   - Нормалізувати Markdown перед пошуком (зняти `**`, `_`, `` ` ``, `#`, згорнути пробіли), шукати звороти з межами слів і гнучким порядком.
   - Кращий варіант: відмовитися від пост-фільтра — попросити модель повертати структурований JSON (секції + прапорець `choice_block_present`) або рендерити секції на сервері.
2. **Не повертати `success` з порожнім результатом.** Після очищення: якщо `result_text.strip()` порожній — повернути оригінал (без очищення) або `status: error` з людським повідомленням; ніколи не віддавати порожні `markdown`/`html`.
3. **Передати в промпт `no_submission_required` і тип здачі.** Додати параметри в `refine_assignment_description_with_gemini`, endpoint і JS; для таких завдань не додавати `📁`, «Збережіть під прізвищем», «Прикріпіть файл».
4. **Додати регресійні тести** (мінімум 20 на фільтр + 5 наскрізних на endpoint): легітимний вибір у 6+ формулюваннях, заперечення, загальне `⚠️`, блок у кінці, блок + критерії, порожній результат, порожні notes, англомовні notes, `no_submission_required`.

**Критерій готовності P0:** фільтр не змінює текст у всіх кейсах, де вибір явно є; не повертає порожній успіх; для `no_submission_required` у промпті відсутні файлові вимоги; тести зелені.

### P1 — узгодити промпт з типами завдань (1 тиждень)

5. **Динамічна структура промпту.** Замість §5-шаблону — набір правил/секцій, які включаються за типом завдання:
   - письмова робота з файлом (поточна);
   - усна відповідь / опрацювання (без файлу);
   - тест/онлайн-відповіді;
   - робота з матеріалами-посиланнями/відео;
   - вибір 1 з N; вибір N з M; обов'язкові без блоку.
6. **Умовні бали/оцінка.** Згадувати «бажану оцінку»/бали лише коли вчитель явно вказав оцінку/бали і `evaluation_type` це підтримує; додати нейтральні формулювання для «на розсуд», «бали однакові», «зараховано/не зараховано».
