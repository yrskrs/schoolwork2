# Tailscale та посилання доступу — SchoolNet 4.8.1

## Де знайти

**Налаштування → Tailscale та доступ** (`/teacher/settings/tailscale/`).
Підключення за замовчуванням вимкнене. Встановлювати Tailscale для роботи сайту
не потрібно. Змінювати підключення та запускати/зупиняти Funnel може
адміністратор (`is_superuser`); учитель керує власними посиланнями.

На сторінці підключення є кнопка **«Посилання доступу»** (`/teacher/access-links/`).
Ця сторінка працює й без тунелю: можна заздалегідь підготувати посилання та
переглядати збережену статистику. Пункт у головному меню вчителя з’являється
після ввімкнення підключення, тому непотрібна функція не займає основне меню.

## Доступ за звичайною адресою

На сторінці **«Посилання доступу»** адміністратор може встановити прапорець
**«Не вимагати посилання доступу»** й натиснути **«Зберегти режим доступу»**.
Тоді учні відкривають звичайну публічну адресу без секретного коду чи cookie
дозволу. Підключення Tailscale має бути ввімкнене; сам Funnel також має працювати.

Щоб повернути захист, зніміть прапорець і збережіть. Наступний запит без чинного
посилання буде закритий. У відкритому режимі скасування окремого посилання не
закриває звичайну адресу: для цього поверніть захищений режим або вимкніть
підключення. Наявні посилання та їхня статистика зберігаються.

Зміна загального режиму доступна лише адміністратору, захищена CSRF і записується
до журналу. Учительські сторінки й службові ресурси зберігають власний захист;
відкриваються лише звичайні учнівські маршрути та опубліковані матеріали.
Міграція 0072 додає прапорець зі значенням **вимкнено**. Самостійно публічний
доступ не вмикається, а вимкнене підключення завжди закриває зовнішній доступ.

## Чотири варіанти

| Тип | Доступ учня |
| --- | --- |
| Увесь сайт | Звична учнівська стрічка, вибір класу й імені, матеріали та здача робіт |
| Клас | Завдання, списки учнів і роботи вибраного класу |
| Персональне посилання учня | Завдання його класу, власні роботи, автоматично задані ім’я та клас |
| Одне завдання | Вибране завдання, матеріали, здача й роботи цього завдання |

Кожне посилання має назву, окремий тип/одержувача, строк дії або «до скасування»,
копіювання адреси, локально створений QR-код і незалежне скасування.
Учитель може редагувати кожне посилання. Зміна обмежень діє також для браузерів,
які вже отримали доступ. Скасоване посилання не поновлюється через редагування:
для нового доступу створіть нове посилання. Учитель вибирає свої класи,
їхніх активних учнів або власні завдання.

Персональний доступ не дозволяє підмінити основного учня чи клас у POST-запиті.
У цьому режимі додавання співавторів вимкнене. Для спільної здачі використовуйте
посилання на клас, завдання або весь сайт. Індивідуальні завдання іншого учня
не входять до персональної стрічки. Персональні історичні здачі без прив’язаного
`student_id` автоматично за збігом імені не відкриваються.

## Що бачить учень і що рахує статистика

Учень відкриває секретне посилання та натискає **«Відкрити сайт»**.
Логін і пароль не потрібні. Сайт установлює захищену cookie (`Secure`,
`HttpOnly`, `SameSite=Lax`) і переходить на стрічку або вибране завдання,
прибираючи секрет із поточної адреси. Для зовнішнього входу потрібен HTTPS.
Одночасно браузер користується одним посиланням: відкриття іншого замінює дозвіл.

- **Переходи** — успішні підтвердження кнопкою «Відкрити сайт». Повторне підтвердження рахується повторно.
- **Унікальні браузери** — окремі анонімні cookie браузера для кожного посилання. У БД зберігається хеш випадкового ідентифікатора.
- **Останній вхід** — час останнього успішного підтвердження; інтерфейс показує час Києва.

GET, HEAD і попередній перегляд у месенджері не надають дозволу й не збільшують
лічильники. Кількість браузерів не дорівнює кількості учнів: інкогніто, інший
пристрій або очищення cookie створюють новий ідентифікатор.

Строк дії та скасування перевіряються на кожному запиті, включно з матеріалами,
прямими `/media/`-адресами, HTTP Range, формою здачі, API та самоперевіркою ШІ.
Нові переходи й уже видані дозволи припиняють працювати після скасування.
Уже завантажені файли чи вже показаний вміст неможливо забрати з пристрою.
Скасування одного посилання не вимикає інші.

Це дозвіл власникові посилання, а не перевірка особи: посилання можна переслати.
Звичайний вхід учителя зберігається окремо.

## Перше підключення сервера

1. Установіть Tailscale на сервері та виконайте `sudo tailscale up`. Увійдіть у власний акаунт за адресою, яку покаже CLI.
2. Дозвольте MagicDNS, HTTPS і Funnel у своєму акаунті. Отримайте DNS-ім’я вузла, наприклад `school.tail123.ts.net`.
3. У налаштуваннях SchoolNet задайте `https://school.tail123.ts.net`, увімкніть **«Підключити Tailscale»** та збережіть. Також підтримуються порти 8443 і 10000. Шлях на кшталт `/test/` для цього встановлення не підтримується.
4. Налаштуйте доступ вебпроцесу до локального Tailscale CLI, якщо потрібні кнопки керування. Без нього можна керувати тунелем у терміналі.
5. Запустіть Funnel і відкрийте зовнішню адресу в окремому приватному вікні. Без учнівського посилання має відображатися повідомлення про необхідність доступу. Потім перевірте матеріал, здачу й скасування тестового посилання.

Для звичайного запуску, де сайт на порту 8000:

```bash
# Змінні середовища вебпроцесу; після зміни перезапустіть його.
SCHOOLNET_TAILSCALE_BINARY=/usr/bin/tailscale
SCHOOLNET_TAILSCALE_TARGET_PORT=8000

# Або ручне керування без доступу вебпроцесу до CLI:
tailscale funnel --bg --https=443 --set-path=/ http://127.0.0.1:8000
tailscale funnel --bg --https=443 --set-path=/ off
```

Локальний порт — порт сайту на вузлі, де працює **tailscaled**.
Для вашого сервера з портом 8080 вкажіть `SCHOOLNET_TAILSCALE_TARGET_PORT=8080`.
Якщо змінну не вказано, використовується `APP_PORT`, а без нього — 8000.
Шлях до CLI задається лише в середовищі сервера, а не довільним полем у браузері.
Команди запускаються без shell, з таймаутом 15 секунд. Стан показує доступність
служби, DNS-ім’я та наявність публікацій; це не перевірка публічного DNS/маршруту.

Під час запуску/зупинки сайт перевіряє відповідність DNS-імені поточному вузлу
та відмовляється замінювати кореневий маршрут, що веде до іншого сервісу.
Використовується конкретний порт і `--set-path=/`; `funnel reset`, `tailscale down`
чи зміни інших публікацій сайт не виконує.

### Docker і помилка «Керування Tailscale із сайту не підключено»

Наявність Tailscale на хості не надає контейнеру доступу до CLI та daemon.
Для цього у репозиторії є окремий **`compose.tailscale.yaml`**. Він додає
лише вебконтейнеру CLI `/usr/bin/tailscale` і каталог `/var/run/tailscale`
хоста в режимі read-only, задає шлях CLI та локальний порт із `APP_PORT`.
Каталог сокета змонтовано цілком, щоб перевідкриття сокета daemon не ламало mount.
ШІ-воркер, Docker socket і облікові ключі Tailscale для цього не потрібні.

Додайте файл до вже використовуваного списку `COMPOSE_FILE` у локальній `.env`,
зберігши інші файли конфігурації. Наприклад, для простого розгортання:

```dotenv
COMPOSE_FILE=compose.yaml:compose.tailscale.yaml
```

Якщо вже використовуються `.release-image.yaml`, `compose.override.yaml` чи
інші файли, залиште їх у списку й допишіть `:compose.tailscale.yaml` наприкінці.
Після перевірки `docker compose config -q` перестворіть вебконтейнер:

```bash
docker compose up -d --no-deps app
```

Шляхи, архітектура статичного Linux CLI та права користувача контейнера мають
відповідати серверу. Вебпроцес отримує доступ керування Tailscale через сокет;
кнопки керування доступні лише адміністратору. На іншому сервері файл не потрібно
підключати, якщо ця функція не потрібна. Нативний запуск також автоматично
визначає `tailscale` у PATH; явний `SCHOOLNET_TAILSCALE_BINARY` має пріоритет.

Після підключення натисніть **«Перевірити службу»**: з’являться стан `Running`,
DNS-ім’я вузла та стан публікацій. Якщо daemon уже авторизований на хості,
входити в акаунт повторно не потрібно. Монтування не запускає, не зупиняє й не
переналаштовує чинні тунелі автоматично.

## Вимкнення, адреса та локальна мережа

**«Підключити Tailscale» вимкнено** закриває зовнішній учнівський доступ,
зберігаючи посилання та статистику. Сам daemon/Funnel не зупиняється автоматично.
Кнопка **«Зупинити Funnel»** прибирає публікацію окремо; після неї локальний сайт
і сторінка керування залишаються доступними. Вхід учителя через доступний тунель
працює й при вимкненому учнівському підключенні.

Зміна зовнішньої IP-адреси не вимагає зміни посилань, якщо DNS-ім’я Funnel те саме.
Якщо зміниться саме ім’я вузла/порт, збережіть нову адресу та повторно надішліть
посилання; старі повідомлення й QR-коди автоматично не перепишуться.

Прямі запити з локальної мережі зберігають звичний доступ. Запити Funnel
визначаються за його заголовком, `.ts.net`-доменом та налаштованою адресою.
При ввімкненому підключенні також захищаються запити з публічних IP та через
проксі з forwarding-заголовками; підміна цих заголовків не надає локальних прав.
Проксі перед SchoolNet має зберігати заголовки Funnel/forwarding: не спрямовуйте
зовнішній трафік як нібито прямий LAN-запит. При типовому вимкненому підключенні
звичайні незалежні проксі-розгортання продовжують працювати.

Через Funnel учнівський дозвіл відкриває лише явно перелічені учнівські маршрути;
службові API та архіви ним не відкриваються. Інтеграції журналу через машинні API
залишайте на локальному/приватному маршруті з їхньою власною авторизацією.
Нова учнівська URL потребує додавання серверної перевірки області доступу.

## Дані та оновлення

Міграція `0071_optional_tailscale_access` створює таблиці підключення, посилань,
анонімних браузерів та журналу створення/редагування/скасування. Дані завдань
і наявні учнівські роботи не змінюються. Видалення класу/учня/завдання вимикає
пов’язане посилання, не заважаючи звичайному видаленню об’єкта.

Токен посилання — випадковий 256-бітний секрет; зберігається в БД для повторного
копіювання. Журнал керування не записує токени. Django/SchoolNet і налаштований
Gunicorn приховують секретний шлях у журналах, а `Referrer-Policy: same-origin`
не передає його стороннім сайтам і зберігає сумісність із CSRF для форм.
Окремі зовнішні проксі також слід налаштувати на приховування `/access/…` у логах.

Повна резервна копія БД містить посилання і статистику. Хмарний експорт/відновлення
застосунку виключає зовнішні дозволи, журнал доступу й підключення Tailscale,
так само як інші зовнішні ключі: після такого відновлення підключіть сервіс
і створіть посилання заново.

Оновлення: створіть перевірену копію, оновіть код/образ і залежності, виконайте
`python manage.py migrate`. Новий пакет `qrcode==8.2` створює SVG на сервері,
без стороннього сервісу. Для відкату збережіть повну БД та узгоджений образ;
видалення нових таблиць знищує статистику й посилання.

Офіційні джерела: [Funnel](https://tailscale.com/docs/features/tailscale-funnel),
[команди та вимкнення конкретного маршруту](https://tailscale.com/docs/reference/tailscale-cli/funnel),
[заголовки проксі у вихідному коді Tailscale](https://github.com/tailscale/tailscale/blob/main/ipn/ipnlocal/serve.go).
