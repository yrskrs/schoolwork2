# Google Drive без публічного домену

Для SchoolWork на `192.168.1.13:8080` можна одноразово підключити Google через SSH-тунель на комп’ютері вчителя. Сам сайт залишається доступним за чинною LAN-адресою. Google дозволяє HTTP callback для localhost; LAN IP `192.168.…` не є localhost.

## Підключення

1. На комп’ютері з доступом SSH до `yrsadmin@192.168.1.13` запустіть `bash scripts/google_backup_tunnel.sh` із каталогу SchoolWork. Скрипт створює фоновий SSH-тунель `127.0.0.1:18080 → сервер 127.0.0.1:8080`, перевіряє SchoolWork та повторно використовує вже доступний сайт. Паролі й ключі Google у скрипті відсутні.
2. У звичайному Chrome/Firefox на **цьому самому комп’ютері** відкрийте `http://localhost:18080/teacher/backups` і ввійдіть у SchoolWork своїм обліковим записом.
3. У [Google Cloud Console → Clients](https://console.cloud.google.com/auth/clients) відкрийте **наявний Web application client**, чиї Client ID / Secret уже внесені до SchoolWork. У **Authorized redirect URIs** додайте точні адреси та збережіть:

   ```text
   http://localhost:18080/teacher/backups/google/callback?scope=personal
   http://localhost:18080/teacher/backups/google/callback?scope=server
   ```

   Друга адреса потрібна для повної адміністративної копії. Додавати ці URL до JavaScript origins не потрібно.
4. У SchoolWork, відкритому через localhost, залиште поле **«Публічна HTTPS-адреса цього сайту» порожнім**, перевірте, що показаний callback починається з `http://localhost:18080/`, та натисніть **«Зберегти й підключити Google»**. Завершіть вхід і підтвердження доступу у Google. Після повернення має з’явитися повідомлення «Google Drive підключено для резервування».
5. Створіть першу копію та виконайте її перевірку через сайт. Для всього сайту потрібні адміністративний обсяг і всі категорії даних/оригіналів файлів.

## Після підключення

Тунель потрібен лише для проходження OAuth. Подальші ручні та автоматичні копії сервер передає Google без участі цього комп’ютера. Звичайну роботу можна продовжувати через `http://192.168.1.13:8080`.

Після перезавантаження комп’ютера або втрати SSH-з’єднання для повторного OAuth запустіть скрипт знову. З телефона чи іншого комп’ютера ця localhost-адреса не веде до створеного тут тунелю. Не використовуйте одночасно `localhost` та `127.0.0.1` у різних кроках: адреса callback у Google та у SchoolWork має збігатися буквально.

## Перевірка налаштування 01.11.2026

Тунель запущено лише на loopback-інтерфейсі; `localhost:18080/healthz/` повертає HTTP 200 і версію 4.7.1. Неавторизований перехід до резервування відкриває штатну сторінку входу. Генерація OAuth URL з наявними ключами перевірена без зовнішнього запиту та без запису OAuth state: HTTPS-перевірка пропускає localhost і використовує точний callback для personal. Підключення облікового запису Google та створення справжньої копії ще виконує власник у браузері.

[Вимоги Google до redirect URI](https://developers.google.com/identity/protocols/oauth2/web-server#uri-validation).
