# Центр налаштувань і довідка — аудит 4.4.8

Дата: 12 жовтня 2026 року.

## Що перевірено перед змінами

- «Розмір БД» намагався знайти локальний файл за назвою бази. Це працювало для SQLite, але для PostgreSQL із Docker повертало «—».
- Довідка містила блок «Списки та журнал» над шапкою модального вікна, поза областю прокручування; його бачили також учні. Він займав місце та порушував компонування.
- Опис налаштувань згадував три вкладки, хоча реалізовано чотири. Для «API та журнал» не було власної теми. Загальна кнопка довідки не враховувала вкладку ШІ; кнопка в налаштуваннях не враховувала API.
- Звірено чинні вкладки ШІ, власні критерії для класів, приватні вказівки ШІ та їх перенесення в ZIP, API і власників ключів, адміністративне оновлення, перезбірку й відкат. Ці можливості потребували доповнення довідки.

## Реалізовані зміни

- Модуль `feed/environment_storage.py` читає розмір підключеної PostgreSQL через `pg_database_size(current_database())`. Для SQLite підсумовуються файл бази та наявні `-wal`/`-shm`; БД у пам’яті займає 0 байт на диску.
- Матеріали вчителів визначаються за файлами завдань і документами критеріїв. Файли учнів охоплюють основний файл здачі та всі додаткові файли. Розмір береться з реальних файлів, а не із застарілого поля `file_size`.
- Окремо рахуються інші медіафайли, файлові кеші Django, приватні зображення переглядів і каталог серверних журналів `logs`. Аватари, накопичувальні архіви та медіафайли без запису в БД входять до «Інших медіафайлів».
- Один фізичний файл рахується один раз: повторні записи, групові здачі, жорсткі посилання й вкладені каталоги кешу не завищують суму. Відсутній файл не створює вигаданого обсягу. Символічні посилання всередині сховища не обходяться; такі пропуски позначаються попередженням.
- Загальна сума: БД + усі медіафайли + кеш + журнали. Це розмір даних SchoolNet у байтах, без накладних витрат файлової системи, Docker-образів, системних файлів, службових WAL PostgreSQL та резервних копій за межами врахованих каталогів.
- Знімок кешується на 60 секунд; на сторінці показано час вимірювання. Недоступний розмір БД має текст «Недоступно»; неповна сума — позначку ≥ і пояснення.
- Прибрано блок над шапкою довідки, виправлено висоту модального вікна та мобільні заголовки. Теми інтеграції розташовані всередині учительського акордеона, адміністративні оновлення — лише для адміністратора.
- Кнопки відкривають тему активної вкладки, зокрема після перемикання без перезавантаження. Перед відкриттям скидаються попередні акордеони. Пошук, вкладки ролей, згортання, Escape, закриття фоном, утримання фокуса в діалозі та повернення фокуса працюють.
- README, `CHANGELOG.md`, `RELEASES.json`, журнал сайту, `VERSION`, Dockerfile та стандартні теги Compose узгоджено з випуском 4.4.8. Міграцій БД не потрібно.

## Перевірки

```bash
venv/bin/python manage.py test \
  feed.tests_environment_storage \
  feed.tests_ai_settings_navigation \
  feed.tests_system_updates \
  feed.tests_platform_layout \
  --settings=schoolnet.test_settings --noinput

venv/bin/python scripts/test_settings_ui.py --artifacts /tmp/schoolnet-settings-ui
venv/bin/python manage.py check --settings=schoolnet.test_settings
git diff --check
```

- **51 серверний тест пройшов.** Покрито групові файли та дублікати, документи критеріїв, додаткові й відсутні файли, вкладені кеші, жорсткі/символічні посилання, порожнє сховище, кешування знімка, недоступну БД, помилки читання, права й чинні маршрути налаштувань.
- Запит PostgreSQL перевірено з підміною з’єднання, включно з помилкою БД. Файли SQLite та WAL/SHM перевірено в тимчасовому каталозі. Окремого запуску PostgreSQL/Docker у цьому аудиті не було.
- **П’ять браузерних сценаріїв Chrome пройшли:** довідка на ширині 1440 та 500 px у світлій/темній темах, картки сховища на обох ширинах. Перевірено тему кожної вкладки, пошук, акордеони, вкладки ролей, Escape, фон, фокус, прокручування й межі карток. Помилок JavaScript немає. Знімки зберігаються в переданому каталозі артефактів.
- Перевірка Django та `git diff --check` пройшли. Окремо перевірено відповідність версії 4.4.8 у метаданих випуску, журналі сайту, Dockerfile і Compose; позначка найновішого випуску є лише одна.
- Використано тестову БД SQLite у пам’яті та тимчасові медіафайли/кеші. Вимірювання не змінює файли користувачів; робочу БД не мігровано й сервер не перезапущено.

## Застосування

Після встановлення 4.4.8 відкрийте «Центр налаштувань → Середовище та заклад». Для перегляду нових обсягів після завантаження або видалення файлів дочекайтеся завершення 60 секунд кешування й оновіть сторінку. Загальну суму використовуйте як обсяг даних закладу; повну зайнятість дисків сервера й резервних сховищ перевіряйте засобами сервера.
