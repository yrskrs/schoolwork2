# Потрібні фактичні квоти ШІ-підключень (не вигадувати)

Статус: **очікує даних власника акаунтів**. Усі п’ять підключень мають
`quota_limits={}`; явних `quota_group` немає. Це означає, що локальний
координатор не може заздалегідь планувати хвилинні/добові ліміти.

Потрібно для кожного підключення вказати **фактичні** значення з кабінету
провайдера (або підтвердити, що ліміт невідомий і має лишатися порожнім):

- RPM (requests per minute)
- RPD (requests per day)
- TPM (tokens per minute, якщо є)
- TPD (tokens per day, якщо є)
- ITPM / OTPM (input/output tokens per minute, якщо провайдер їх розрізняє)
- concurrency (кількість одночасних запитів)
- `quota_group` — чи спільна квота в кількох ключів одного провайдера
- для двох Gemini-ключів: чи це **один** проєкт/квота, чи різні проєкти

Підключення (без секретів): Gemini ×2, OpenRouter ×1, Groq ×1,
Cloudflare ×1.

Джерела:
- Gemini: Google AI Studio / Cloud project quotas;
- OpenRouter: кабінет OpenRouter (ліміти залежать від маршруту);
- Groq: console.groq.com rate limits;
- Cloudflare: Workers AI plan/limits (пам’ять: офіційна сторінка лімітів).

Поки значення не надані, **не** заповнювати їх припущеннями, не ставити
«необмежено» і не вважати пункт завершеним. Порожні `quota_limits`
залишаються безпечним консервативним режимом: координатор покладається на
фактичні відмови провайдера.
