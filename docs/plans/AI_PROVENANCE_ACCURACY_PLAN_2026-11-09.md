# План підвищення точності виявлення використання ШІ

**Дата:** 09.11.2026  
**Статус:** P0 і P1 реалізовано 09.11.2026; P2+ заплановано  
**Мета:** збільшити точність і доказовість ознак використання ШІ в AI-перевірці, не перетворюючи підозру на автоматичний вирок.

## 1. Чесно про межі

- 100% визначення за текстом не існує; жоден LLM-детектор чи зовнішній сервіс не дає доведеного факту.
- Найточніші сигнали — **технічні** (C2PA, метадані, історія редагування), але вони мають неповне покриття: більшість текстів із чат-ботів не несуть метаданих.
- Стиль і «відсоток ШІ» — слабкий, некалібрований сигнал. Його не можна використовувати як єдину підставу.
- Мета плану — не «довести», а **підвищити precision (менше хибних звинувачень) і coverage (більше випадків із перевірюваними доказами)**.

## 2. Поточний стан

- `feed/ai_context.py`: модель просять повернути `ai_generated_percent`, `ai_authorship_analysis.evidence`, деталі.
- `feed/ai_provenance.py`: пошук назв генераторів у метаданих/тексті, EXIF/XMP, Office `docProps`, `TotalTime`, маркери ШІ, PDF-рядки.
- `feed/ai_provenance.normalize_authorship()`: поріг `ai_detector_tolerance_percent` (25%), стани `detected/not`, confidence `low/medium`, без впливу на бал.
- UI: «🤖 Ознаки ШІ N%».
- Чого немає: криптографічної перевірки C2PA, глибоких метаданих (автор/ревізії/дати), перевірки доказів моделі, калібрування, окремого звіту походження.

## 3. Цільова архітектура

Новий модуль `feed/ai_forensics.py` (або розширений `ai_provenance.py`) повертає **структурований звіт**:

```python
{
  "state": "none" | "suspected" | "insufficient" | "confirmed_provenance",
  "confidence": "none" | "low" | "medium" | "high",
  "signals": [
    {
      "source": "file.pptx",
      "location": "docProps/app.xml",
      "basis": "c2pa" | "metadata" | "text_marker" | "model_style" | "process",
      "strength": "strong" | "medium" | "weak",
      "observation": "...",
      "verifiable": true
    }
  ],
  "limitations": ["..."]
}
```

Правила:
- `strong`: валідний C2PA-маніфест із `trainedAlgorithmicMedia`; пряме самопідтвердження учня; метадані генератора, підписані/незмінені.
- `medium`: узгоджені метадані (застосунок Gamma/Canva/Google Slides, аномальний час редагування, автори коментарів) + текстові маркери.
- `weak`: стиль, «відсоток ШІ», загальні звороти.
- `high` — лише для криптографічно перевіреного C2PA або самопідтвердження; стиль і метадані самі по собі — не вище `medium`.
- Якщо доказів немає — `insufficient`, а не 0%.

## 4. Етапи

### P0. Чесний UX і три стани (0.5–1 день) — ✅ виконано

**Зробити:**
- Замінити бінарний «використав/не використав» і відсоток як головний показник на стани:
  - «ознак не знайдено» (`none`),
  - «є ознаки» (`suspected`),
  - «недостатньо даних» (`insufficient`).
- Відсоток показувати лише як допоміжну оцінку моделі з підписом «некалібрована оцінка».
- Заборонити автоматичне зниження балу за будь-який стан (уже діє — закріпити тестом).
- Додати коротке пояснення в UI, що це не доказ.

**Файли:** `feed/ai_provenance.py`, `feed/models.py` (поле `ai_authorship_state`), шаблони списків/деталей, `feed/views.py`.

**Критерій:** текстова робота без метаданих → `insufficient`, без відсотка й без звинувачення; усі старі оцінки не змінюються.

### P1. Технічні докази: C2PA + глибокі метадані (2–3 дні) — ✅ виконано

**Зробити:**
1. **C2PA-верифікація** для JPEG/PNG/WebP/PDF:
   - бібліотека `c2pa-python` (або CLI `c2patool`) у контейнері;
   - перевіряти підпис, `claim_generator`, `digitalSourceType` (`trainedAlgorithmicMedia`), `actions`;
   - не вважати згадку «c2pa» доказом — тільки валідний маніфест.
2. **Розширені метадані Office/PDF:**
   - `docProps/core.xml`: creator, lastModifiedBy, created, modified, revision;
   - `docProps/app.xml`: Application, Company, Template, TotalTime, Pages/Words;
   - автори коментарів і трекованих змін;
   - PDF: Producer, Creator, XMP-історія, дати;
   - ознаки Google Slides/Canva/Gamma (`Application`, `Template`, URL у примітках).
3. **PPTM/PPTX глибше:** нотатки слайдів, приховані слайди, вбудовані зображення (метадані кожного), службові XML.
4. **Єдиний формат сигналу** з `source/location/basis/strength/observation`.

**Файли:** `feed/ai_provenance.py` (або новий `feed/ai_forensics.py`), `requirements`/Dockerfile, тестові фікстури.

**Критерій:** на контрольному наборі файлів:
- валідний C2PA-маніфест → `strong`;
- підроблена/зіпсована копія → не `strong`;
- файл без метаданих → `insufficient`, не «0%»;
- жоден сигнал не посилається на неіснуючий файл/слайд.

### P2. Перевірка доказів моделі (2–3 дні)

**Проблема:** модель може вигадати цитату, слайд або «ознаку», якої немає у файлі.

**Зробити:**
- Для кожного `evidence` перевіряти:
  - файл справді є серед матеріалів;
  - цитата (нормалізована) зустрічається в тексті/слайді;
  - номер слайда існує;
  - для метаданих — поле реально існує.
- Непідтверджені модельні докази відкидати або знижувати до `weak` із позначкою «не підтверджено».
- Прибрати з промпту вимогу «постав відсоток» як основного результату; просити **спостереження з цитатами**, а відсоток — опційно.
- Додати тести на галюцинації: вигадана цитата, неіснуючий слайд, вигаданий файл.

**Критерій:** жоден `suspected` не може бути побудований лише на непідтвердженій цитаті.

### P3. Калібрування на мітках учителя (1–2 тижні, потрібні дані)

**Зробити:**
- Зібрати 100–200 робіт із мітками: `AI`, `not AI`, `unknown` (рішення вчителя, не синтетичний еталон).
- Порахувати precision/recall/FPR для кожного типу сигналів і порогів.
- Окремо для: текст, DOCX, PPTX, PDF, зображення; окремо для української мови.
- Ввести версію калібрування (`provenance_calibration_version`) і зберігати метрики.
- Поріг 25% замінити на калібрований для конкретного типу/мови; для текстів без метаданих — `insufficient` за замовчуванням.

**Команда:** `manage.py ai_provenance_calibrate` + звіт у `/teacher/ai/quality/` або окрема сторінка.

**Критерій:** FPR на контрольних «людських» роботах не вище узгодженого (напр. ≤5%); recall виміряний, а не заявлений.

### P4. Опційно: процесні докази без усного опитування (1 тиждень)

- Поле для чернетки/історії версій (файл або експорт Google Docs/Word).
- Порівняння чернетки й фіналу: час, обсяг, стиль, раптові вставки.
- Перевірка метаданих історії (revision, lastModifiedBy, дати).
- Для коду — git-історія/коміти; для Scratch — JSON-проєкт і дати.

Це не «детектор», але дає найсильніші докази процесу.

### P5. Опційно: зовнішній детектор як слабкий сигнал

- Адаптер до Turnitin/GPTZero/Copyleaks за згодою адміністратора.
- Передавати лише за потреби, з обмеженням даних і журналом.
- Результат — `weak`/`medium`, ніколи не єдина підстава.

## 5. Що не робити

- Не показувати «78% ШІ» як ймовірність.
- Не знижувати бал автоматично.
- Не вважати стиль доказом.
- Не використовувати зовнішній детектор без калібрування й політики.
- Не обіцяти «точне визначення».

## 6. Метрики успіху

| Метрика | Як міряти | Ціль |
|---|---|---|
| FPR (хибні звинувачення) | контрольні людські роботи | ≤5% |
| Precision | мітки вчителя | ≥80% для `suspected` |
| Coverage сильних доказів | частка робіт із `strong` | зростання |
| Частка `insufficient` | текст без метаданих | чесно висока |
| Зміни балів | до/після | 0 автоматичних змін |

## 7. Порядок і оцінка

1. **P0** — 0.5–1 день, одразу зменшує шкоду від хибних звинувачень.
2. **P1** — 2–3 дні, найбільший приріст доказовості.
3. **P2** — 2–3 дні, прибирає галюцинації моделі.
4. **P3** — 1–2 тижні після появи міток учителя.
5. **P4/P5** — опційно.

**Рекомендований перший крок:** P0 + P1, потім P2. Це вже дасть зрозумілий звіт «що саме знайдено», замість відсотка.


## 8. Реалізовано 09.11.2026 (P0 + P1)

### P0 — три стани замість вироку

- Нові поля `Submission.ai_authorship_state` (`none` / `suspected` / `insufficient`) і `ai_provenance_report`.
- `normalize_authorship()` повертає стан, confidence, структуровані сигнали й обмеження.
- Відсоток більше не є головним показником: у списках — «Є ознаки ШІ (confidence)», у деталях — «ознаки, а не доказ».
- Текстові роботи без метаданих → `insufficient` («походження не встановлено»), а не 0%.
- Старі записи з `ai_generated_detected=True` перенесено в `suspected` міграцією `0077`.
- Бал не змінюється автоматично (закріплено існуючою логікою та тестами).

### P1 — C2PA і глибші метадані

- `feed/ai_provenance.py`:
  - `_c2pa_signals()`: перевірка підписаного C2PA-маніфесту через `c2pa-python`; сигнал `strong` лише за `trainedAlgorithmicMedia`; звичайна згадка «c2pa» більше не доказ.
  - `_office_metadata_signals()`: `creator`, `lastModifiedBy`, `revision`, `Application`, `Company`, `Template`; генератори в застосунку/шаблоні — `medium`; різні автор/редактор — `weak`.
  - PDF: `Producer`, `Creator`, `Author`, XMP.
  - Кожен сигнал має `source`, `location`, `basis`, `strength`, `observation`.
  - Кеш provenance оновлено (`2026-11-09-states`), щоб не повертати старі результати.
- Залежність `c2pa-python` додана в `requirements.txt` і `requirements-docker.lock`.
- Сторінка «Що побачила модель» показує блок «Походження роботи»: стан, confidence, файли, сигнали, обмеження.

### Перевірка

- 268 тестів — `OK`, зокрема 6 нових тестів станів і метаданих.
- Лабораторні перевірки:
  - текстова робота 1104 → `insufficient`, 0 перевірених файлів;
  - презентація 1148 → `none`, 1 перевірений файл, сигналів немає;
  - обидві сторінки «Що побачила модель» мають блок «Походження роботи».
- C2PA на тестовому PNG без маніфесту коректно дає обмеження «маніфест не знайдено», без падіння.

### Що ще потрібно для P2

- Перевірка цитат/слайдів, які повертає модель (зараз модельні `evidence` мають `strength=weak` і не піднімають стан вище `insufficient` без підтвердження).
- Калібрування (P3) і тести на реальних C2PA-файлах.
