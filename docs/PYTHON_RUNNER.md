# Запуск Python під час перевірки

У переглядачі зданого `.py` або `.pyw` є **▶ Запустити Python**. Код запускається
лише після натискання кнопки. Термінал і графічний робочий стіл доступні в цьому ж
вікні; оцінювання та навігація між роботами залишаються доступними. Після появи
графічного вікна переглядач автоматично показує графіку, якщо вчитель ще не обрав
вкладку самостійно. Останній кадр програми зберігається після закриття її вікна.

У вкладці «Термінал» видно stdout, stderr і traceback. Поле вводу надсилає рядок
для `input()`, Ctrl+C перериває програму, EOF завершує введення. У вкладці
«Графічне вікно» можна натискати кнопки, вводити текст, керувати мишею та
клавіатурою. Підтримуються Tkinter, turtle, pygame та інші Linux/X11 бібліотеки,
сумісні з образом. Зображення оновлюється приблизно 3 рази на секунду; це режим
перевірки, а не повношвидкісний ігровий стримінг. Звук, камера, USB, браузерні
сервери та Windows API не підтримуються.

Усі прикріплені файли цієї здачі копіюються в робочий каталог, щоб програма могла
імпортувати сусідні `.py` та читати зображення або дані. Запускається обраний у
переглядачі файл. Дозволено до 50 файлів загальним розміром до 10 МБ. Назви мають
бути унікальними; архіви не розпаковуються. Для багатофайлових проєктів прикріпіть
вихідні файли окремо. Файли зберігаються поруч, без структури каталогів.

## Встановлення

У Docker Compose сервіс `code_runner` уже додано. Збірка та запуск сервісу:

```sh
docker compose build code_runner
docker compose up -d code_runner
```

Вебзастосунок теж має бути оновлено до коду з цією функцією та пересоздано з
новими змінними оточення `CODE_RUNNER_URL` і `CODE_RUNNER_TOKEN` з compose.yaml.
Чинний онлайн-оновлювач оновлює `app` та `ai_worker`; перше встановлення і
подальші оновлення образу `code_runner` виконуються наведеними вище командами.
Для локального Django встановіть `CODE_RUNNER_URL` на адресу окремо запущеного
брокера та однаковий `CODE_RUNNER_TOKEN` у двох процесах. Для локального доступу
до брокера можна тимчасово опублікувати **тільки loopback** порт
`127.0.0.1:8002:8002` через окремий Compose override.

Брокер вимагає секрет щонайменше з 32 символів; у Compose використовується
`CODE_RUNNER_TOKEN` або `SECRET_KEY`. Його порт не публікується назовні. Django
спілкується з ним через приватну мережу `runner_control`. Брокер не отримує
томи з медіафайлами, репозиторій чи змінні підключення до БД. Лише брокер має Docker socket;
ані вебзастосунок, ані контейнери з кодом учнів його не мають.

Якщо брокер не налаштований або недоступний, переглядач показує зрозумілу
помилку. Виконання учнівського коду у процесі Django чи на хості відсутнє.

## Бібліотеки

Перед запуском система статично читає `import` у прикріплених Python файлах,
відкидає стандартну бібліотеку й локальні модулі та визначає зовнішні пакети.
Є відповідності назв, наприклад `PIL → Pillow`, `cv2 → opencv-python`,
`sklearn → scikit-learn`, `yaml → PyYAML`. Доданий `requirements.txt` дозволяє
вказати точні версії та залежності, які завантажуються динамічно. Максимум —
30 прямих залежностей. Підтримуються назви, extras та обмеження версій; URL,
git/editable залежності, опції pip і environment markers не приймаються.
Нестандартні відповідності імен модулів і пакетів слід додати в
`runner/dependencies.py`; автоматично однозначно визначити їх неможливо.

Завантажувач отримує лише назви пакетів, завантажує готові wheels з PyPI в
тимчасовий Docker volume (до 256 МБ) та надає його контейнеру без мережі лише
для читання. Кожен запуск створює новий `venv` і встановлює
туди бібліотеки офлайн. Пакети без готового wheel для Linux/Python 3.12 або
пакети з додатковими системними залежностями можуть потребувати зміни образу.
Перше завантаження потребує інтернету. Помилки pip видно в терміналі.

## Ізоляція та життєвий цикл

Кожен запуск отримує окремий Docker контейнер: без мережі, каталогів хоста,
привілеїв і секретів; непривілейований UID, read-only root filesystem, власні
тимчасові `/tmp`, `/work` і `venv`. Обмеження: 1 CPU, 768 МБ пам’яті,
128 процесів. Дані й установлені бібліотеки видаляються разом із контейнером.
Завантажувач має ті ж обмеження, але має мережу та не отримує учнівський код.

Типово дозволено 4 одночасні запуски, 180 секунд виконання, до 420 секунд
загальної підготовки та виконання. Ліміти регулюють
`CODE_RUNNER_MAX_SESSIONS`, `CODE_RUNNER_RUN_SECONDS`. Зупинка, завершення
програми та перехід на іншу роботу прибирають контейнер. Якщо вкладка аварійно
закрита, запуск прибирається після 90 секунд без опитування. Новий Play зупиняє
попередній активний запуск цього вчителя, у тому числі в іншій вкладці.
Після перезапуску брокер видаляє лише залишені контейнери зі своїм namespace.

Доступ до старту, вводу, зупинки та результатів перевіряє Django: сесія вчителя,
права на здачу, CSRF для POST та підписаний токен конкретного запуску. Вивід
рендериться як текст, графіка — як JPEG; код учня не стає HTML сторінки перевірки.

Docker є межею ізоляції й потребує актуального Docker Engine та ядра хоста.
Опис обмежень: [Docker resources](https://docs.docker.com/engine/containers/resource_constraints/),
[Docker security](https://docs.docker.com/engine/security/),
[pip wheels](https://pip.pypa.io/en/stable/cli/pip_download/).

## Перевірка

```sh
venv/bin/python manage.py test feed.tests_python_runner --settings=schoolnet.test_settings
python3 scripts/test_python_runner.py
python3 scripts/test_python_runner.py --ui
```

Другий тест потребує Docker і зібраного образу. Він запускає тільки тимчасовий
брокер і синтетичні учнівські програми; дані школи не використовуються. Варіант
`--ui` також перевіряє Chrome та потребує Node і Playwright; шляхи задають
`NODE_BINARY`, `PLAYWRIGHT_MODULE`, `CHROME_BINARY`.

Перевірено: 27 тестів Django разом із перевірками існуючого переглядача;
реальні stdin, Ctrl+C, traceback, Tkinter, turtle, pygame, автоматичне
встановлення Pillow/pygame, мережеву й файлову ізоляцію, таймаут та очищення
контейнерів і томів. У Chrome перевірено Play, термінальний і український
графічний ввід, мишу, вибір файлу, збереження оцінки та мобільне компонування.
