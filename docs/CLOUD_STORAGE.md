# Хмарні матеріали SchoolNet 4.5.10

Nextcloud і Google Drive можуть бути підключені одночасно. Налаштування: **Профіль вчителя → Налаштування → Профіль → Хмарні диски**. Позначка «Налаштовано» означає збережені параметри; кнопка «Перевірити» окремо перевіряє фактичний доступ.

Прямий шлях у SchoolNet: `/teacher/settings/?tab=profile`, блок **«☁️ Хмарні диски та сховища»**. Для зміни вже налаштованого підключення натисніть **«Змінити»** у відповідному блоці. Кожний учитель налаштовує власне підключення.

## Який спосіб обрати

| Ваші матеріали | Спосіб | Що потрібно |
|---|---|---|
| У Nextcloud | [Nextcloud / WebDAV](#nextcloud) | Адреса сервера, користувач і пароль додатка |
| Окремі публічні файли Drive | [Публічні посилання](#public-links) | Посилання з дозволом на читання |
| Публічна папка Drive з офіційним списком | [API key](#api-key) | Публічна папка та ключ Google Cloud |
| Приватні файли або папки Drive | [OAuth](#oauth) | Client ID, Client Secret та вхід через Google |

Для звичайного підключення вчителю не потрібно змінювати Docker чи `.env`. Наявні Nextcloud і Google Drive працюють паралельно; вибір диска доступний у вікні матеріалів завдання.

## Google Drive: API та публічні посилання

Парсинг не є єдиним способом доступу. Офіційний **Drive API + OAuth** підтримує приватні матеріали, метадані, списки папок із пагінацією та завантаження. Для приватних файлів потрібен OAuth access token із дозволами Drive; пароль Gmail або App Password його не замінює. [Авторизація Google Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

<a id="oauth"></a>

### Приватні матеріали: налаштування OAuth

Цю частину один раз виконує адміністратор Google Cloud або вчитель, який керує власним проєктом.

1. Відкрийте [Google Cloud Console](https://console.cloud.google.com/), виберіть або створіть проєкт.
2. У цьому проєкті відкрийте [Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com) та натисніть **Enable / Увімкнути**.
3. У **Google Auth platform** налаштуйте назву застосунку, контактні дані й аудиторію. Для зовнішнього застосунку зі статусом **Testing** додайте потрібні облікові записи до **Test users**. Для організації Workspace можна використати **Internal**, якщо цей варіант доступний. [Екран згоди Google](https://developers.google.com/workspace/guides/configure-oauth-consent).
4. У дозволах **Data Access / Scopes** додайте `https://www.googleapis.com/auth/drive.readonly` та `https://www.googleapis.com/auth/userinfo.email`: саме їх запитує поточний код SchoolNet. Дозвіл Drive надає читання та завантаження, включно з приватними файлами, які доступні вибраному користувачу. Обмеження стартової папки в SchoolNet не звужує сам OAuth-дозвіл. [Дозволи Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).
5. Відкрийте [OAuth Clients](https://console.cloud.google.com/auth/clients) → **Create client** → **Web application**. У **Authorized redirect URIs** додайте точну адресу SchoolNet зі шляхом `/teacher/cloud/google/callback/`.
6. Наприклад, для сайту `https://school.example.org` callback буде `https://school.example.org/teacher/cloud/google/callback/`. Для локального запуску на порту 8000 — `http://localhost:8000/teacher/cloud/google/callback/`. Це шаблони адрес: використайте свій домен і порт. Схема, домен, порт і кінцевий `/` повинні збігатися з адресою, яку використовує сайт. Для зовнішнього сайту використовуйте HTTPS. [Вимоги до redirect URI](https://developers.google.com/identity/protocols/oauth2/web-server).
7. У SchoolNet відкрийте **«Google OAuth — приватні файли та стабільний список папок»**, введіть отримані **Client ID** та **Client Secret**, натисніть **«Зберегти ключі»**.
8. Після збереження натисніть **«Увійти через OAuth»**, оберіть потрібний Google-акаунт і підтвердьте запитувані дозволи. Після повернення натисніть **«Перевірити з'єднання»** у блоці Google Drive.
9. За бажанням у звичайній формі Google Drive збережіть посилання на стартову папку. Без нього відкривається корінь Drive. Відкрийте нове завдання та переконайтеся, що потрібна папка доступна.

Для зовнішнього застосунку в режимі **Testing** refresh token із дозволом Drive зазвичай діє 7 днів; тоді потрібен повторний OAuth-вхід. Для постійного поширення врахуйте вимоги Google до публікації й перевірки запитуваних дозволів. [Строки дії токенів](https://developers.google.com/identity/protocols/oauth2#expiration).

Дані доступу не передаються в query string і не підставляються назад у поля паролів. Порожнє поле збереженого секрету залишає його чинне значення. Відкликання доступу або прострочений refresh token потребує повторного OAuth-входу; помилка більше не маскується порожньою папкою.

<a id="public-links"></a>

### Публічні файли без OAuth: кроки для вчителя

1. У Google Drive відкрийте **«Поділитися»** для потрібної папки або окремого файла. Якщо матеріал призначений для публічного доступу, встановіть **«Усі, хто має посилання» → «Може переглядати»**. Для приватних шкільних матеріалів скористайтеся OAuth.
2. Скопіюйте посилання. Для папки воно має вигляд `https://drive.google.com/drive/folders/…`.
3. У SchoolNet у блоці Google Drive за потреби заповніть **«Посилання на папку Google Drive»**. Для роботи лише з окремими прямими посиланнями папку можна не вказувати. Email — необов'язкова назва підключення; пароль Gmail не вводиться.
4. Натисніть **«Зберегти та підключити»**. Якщо вказали папку, перевірте її читання кнопкою **«Перевірити з'єднання»**. Без папки та OAuth ця перевірка проситиме вказати папку; це не забороняє додавати окремі доступні публічні файли.
5. У завданні відкрийте **«Додати з хмарного диска» → Google Drive**. Відкрийте прив'язану папку або вставте посилання на окремий файл у **«Додати файл або документ»**. Далі натисніть **«Додати»**, позначте файл і натисніть **«Прикріпити до завдання»**.

- **Файл Drive** за посиланням `drive.google.com/file/d/.../view` завантажується як вихідний файл зі справжньою назвою й типом. Код не пробує перетворити його на Google Документ.
- **Google Docs/Sheets/Slides** за своїми `docs.google.com/.../d/...` посиланнями експортуються відповідно в DOCX/XLSX/PPTX. Це представлення нативного Google Документа для збереження поза Google, а не копія внутрішнього формату Google.
- **Публічні папки без API** читаються через HTML-перегляд Google. Це запасний режим: розмітка Google може змінитися, а повнота списку без офіційного API не гарантується. В інтерфейсі показано відповідне повідомлення. За невідомої розмітки чи закритого доступу показується помилка.
- Посилання з `resourcekey` зберігає цей параметр. Дозволене підтвердження завантаження великих публічних файлів обробляється лише на доменах Google й лише для того самого file ID.

Власник має дозволити читання/завантаження конкретного матеріалу. Для приватних файлів налаштуйте OAuth; змінювати спільний доступ усієї папки заради імпорту не потрібно.

Google офіційно розділяє завантаження звичайних файлів (`files.get`, `alt=media`) та експорт Google Документів (`files.export`). [Завантаження й експорт](https://developers.google.com/workspace/drive/api/guides/manage-downloads).

<a id="api-key"></a>

### Як отримати та підключити Google Drive API key

API key потрібен для офіційного списку й метаданих доступної публічної папки. Він не надає доступу до приватних файлів; для них використовуйте OAuth.

1. Відкрийте [Google Cloud Console](https://console.cloud.google.com/) і виберіть або створіть проєкт.
2. У цьому самому проєкті [увімкніть Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com).
3. Відкрийте [APIs & Services → Credentials](https://console.cloud.google.com/apis/credentials), натисніть **Create credentials → API key**. [Офіційна інструкція](https://developers.google.com/workspace/guides/create-credentials#api-key).
4. У параметрах ключа встановіть **API restrictions → Restrict key → Google Drive API** й збережіть. Запити SchoolNet виконує сервер: якщо налаштовуєте **Application restrictions**, використайте фактичну зовнішню IP-адресу сервера. Обмеження **Websites / HTTP referrers** призначене для браузерних запитів і не відповідає цьому способу підключення. [Обмеження ключів Google](https://docs.cloud.google.com/api-keys/docs/add-restrictions-api-keys).
5. У SchoolNet відкрийте редагування Google Drive, вставте ключ у **«Google Drive API Key»**, а посилання на публічну папку — у **«Посилання на папку Google Drive»**. Натисніть **«Зберегти та підключити»**.
6. Натисніть **«Перевірити з'єднання»**, потім відкрийте папку у вікні матеріалів завдання. Якщо OAuth уже збережений, SchoolNet використовує його для доступу; API key не скасовує налаштований OAuth.

Ті самі прямі посилання на створення ключа й увімкнення Drive API є біля поля ключа в SchoolNet. При повторному редагуванні порожнє поле API key зберігає попереднє значення.

## Nextcloud

1. Увійдіть у свій Nextcloud, відкрийте **Налаштування → Безпека → Пристрої та сеанси**, створіть окремий пароль додатка для SchoolNet. Скопіюйте його одразу: Nextcloud не показує цей пароль повторно. [Керування паролями додатків](https://docs.nextcloud.com/server/stable/user_manual/en/session_management.html).
2. У SchoolNet відкрийте блок Nextcloud та введіть базову адресу сервера, наприклад `https://cloud.example.org` або `http://localhost:8090`. Якщо Nextcloud встановлений у підкаталозі, збережіть його в адресі. Повний шлях `/remote.php/dav/files/…` вводити не потрібно — клієнт додає його сам.
3. Введіть ім'я користувача Nextcloud та створений пароль додатка. Це параметри Nextcloud; вони можуть відрізнятися від входу в SchoolNet.
4. Для HTTPS залиште перевірку сертифіката увімкненою. Прапорець **«Ігнорувати помилки SSL»** використовуйте лише як явне налаштування для свого сервера із самопідписаним сертифікатом.
5. Натисніть **«Перевірити з'єднання»**. Після успішного результату збережіть підключення кнопкою збереження Nextcloud.
6. У новому завданні відкрийте **«Додати з хмарного диска» → Nextcloud** й перевірте список папок і файлів.

Для локального Nextcloud на тому самому хості працює адреса на зразок `http://localhost:8090`: всередині Docker використовується шлюз хоста зі збереженням Host header. Вебсервіс та AI-воркер повинні мати однаковий маршрут до хоста. Для Nextcloud на іншому сервері вкажіть доступну саме з сервера SchoolNet адресу.

Для HTTPS сертифікат перевіряється за замовчуванням, у тому числі для localhost. Самопідписаний сертифікат можна дозволити явним прапорцем; кращий варіант для школи — довірений CA через `CLOUD_NEXTCLOUD_CA_FILE`. Слово `localhost` у шляху URL не змінює TLS-перевірку. Перенаправлення через шлюз зберігає перевірку початкового імені TLS.

Порожнє поле пароля при редагуванні зберігає попереднє значення, якщо адреса й користувач не змінені. Для нової адреси потрібні нові явно введені параметри.

## Додавання до завдання та прогрес

1. Відкрийте створення або редагування завдання й натисніть **«Додати з хмарного диска»**.
2. Виберіть Nextcloud або Google Drive. Пошук фільтрує поточну папку; «обрати все» вибирає лише видимі файли.
3. У рядку **«Додати файл або документ»** вставте посилання. Після перевірки метаданих у списку з'явиться справжня назва. Сторінка входу чи повідомлення Google не додається як файл.
4. Натисніть **«Прикріпити до завдання»**. Унизу видно прогрес, отриманий обсяг, стан перевірки та кількість готових файлів. Перемикання провайдера під час імпорту заблоковано; імпорт можна зупинити.
5. Після успіху діалог закривається. Біля матеріалів видно **«Додано та перевірено… Збережіть завдання»**, назви й остаточні розміри файлів. За потреби позначте один як **«Умова для ШІ»** й збережіть завдання: саме тоді матеріали остаточно прикріплюються.

Імпорт іде безпосередньо на сервер: браузер не завантажує в себе всі файли й не надсилає їх повторно. Черга зберігається в БД. Незавершений імпорт після аварійного завершення обробника може бути повторно взятий у роботу; для цього потрібен час завершення його попередньої оренди. Готові тимчасові файли доступні автору протягом 24 годин. Оновлення сторінки відновлює поточний пакет у тій самій вкладці. Відкриття нового завдання не прикріплює матеріали старого автоматично.

## Що перевіряється

- file ID та метадані офіційного API повинні відповідати обраному посиланню;
- фактичний розмір має збігатися з Content-Length і розміром джерела, якщо вони надані;
- SHA-256/MD5 джерела звіряється з отриманими байтами, коли Google API або Nextcloud надає контрольну суму;
- для кожного завантаження обчислюється SHA-256; тимчасова копія та остаточний файл завдання перевіряються повторно;
- ZIP/Office/Scratch перевіряються на структуру та CRC, PDF — на можливість читання структури, підтримувані зображення — на коректність формату;
- сторінки входу, невідповідний формат, неповні файли та розбіжності контрольних сум відхиляються;
- нові звичайні завантаження з комп'ютера також отримують розмір і SHA-256 зі звіркою після запису у сховище.

Якщо джерело не надає власної контрольної суми, можна підтвердити цілісність отриманої та збереженої копій, але не довести, що файл у джерелі ніколи не змінювався. Для експорту нативного Google Документа сума стосується отриманого DOCX/XLSX/PPTX. Коректність змісту документа й усіх сторонніх форматів автоматично не гарантується.

## Docker та експлуатація

Обробник імпорту запускається у `ai_worker` окремим потоком поруч з AI-чергою. Окремі імпорти не блокують виконання AI-перевірки. `app` та `ai_worker` повинні використовувати той самий образ і приватний спільний `app_cache`; шлях `CLOUD_IMPORT_ROOT` задається однаково. Каталог імпортів не роздається як `/media/`.

Налаштовувані параметри:

| Змінна | Типове значення | Призначення |
|---|---|---|
| `CLOUD_IMPORT_MAX_BYTES` | 1073741824 | Максимум одного хмарного файла, 1 GiB |
| `CLOUD_IMPORT_TIMEOUT` | 300 | Час передачі одного файла, секунд |
| `CLOUD_IMPORT_ROOT` | Приватний каталог поруч із AI-кешем | Спільне тимчасове сховище app/worker |
| `CLOUD_NEXTCLOUD_CA_FILE` | Порожньо | Додатковий довірений CA Nextcloud |

Звичайні учнівські завантаження цими новими хмарними лімітами не обмежуються. До початку імпорту перевіряється вільний диск; прострочені тимчасові файли прибираються. Docker-healthcheck воркера контролює також обробник хмарних імпортів. Завершення роботи воркера при обслуговуванні зупиняє обидва типи запису.

Після розгортання виконайте `python3 scripts/verify_release.py`: перевірка звіряє image ID вебсервісу й воркера та їхній відбиток коду з checkout. `/healthz/` показує версію, revision і source digest, якщо вони записані під час збірки. Залежності Docker закріплені у `requirements-docker.lock`.

Для синтетичної перевірки всього шляху без реальних акаунтів використовується `scripts/test_cloud_import_ui.py`; він створює власні БД, WebDAV, відповіді Google та профіль Chrome, перевіряє прогрес і порівнює прикріплені байти з оригіналами.

## Діалог та стан форми у 4.5.10

Текст діалогу має базовий розмір 16 px. Кнопки A− / A+ змінюють масштаб від 100 до 150%; налаштування зберігається для вчителя у цьому браузері. Панелі прогресу й дії залишаються доступними при прокручуванні вмісту.

Після успішного імпорту діалог закривається. Біля матеріалів показано кількість перевірених файлів і нагадування зберегти завдання. Завершена смуга прогресу не відновлюється. Черга та вибрані імпорти прив’язані до конкретного запису історії форми: перезавантаження цієї форми відновлює її файли, нове відкриття створення завдання починається без них. Видалення матеріалу оновлює цей стан. Старий спільний ключ сторінки більше не використовується.

Розмір Drive береться з офіційного API. Для публічних папок без API він уточнюється за заголовками відповіді максимум двома одночасними запитами без зчитування вмісту файла. Відсутній розмір позначається явно, а не як нуль. Для Google Документів розмір експорту може відрізнятися від розміру в Drive; остаточний розмір показано біля імпортованого матеріалу.

Поруч із полем API key є посилання на [Google Cloud Credentials](https://console.cloud.google.com/apis/credentials) та [ввімкнення Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com). Порядок створення ключа перевірено за [офіційною інструкцією Google](https://developers.google.com/workspace/guides/create-credentials).

## Типові проблеми

| Що видно | Що перевірити |
|---|---|
| «Налаштовано», але папка не відкривається | Окремо натисніть перевірку з'єднання: збереження параметрів ще не підтверджує доступ. |
| Google 401 / потрібен повторний вхід | Повторіть OAuth-вхід потрібним акаунтом; перевірте статус Testing і строк дії токена. |
| Google 403 / немає дозволу | Перевірте права вибраного акаунта, дозволи OAuth або публічний доступ до конкретного файла. Для API key перевірте проєкт, увімкнений Drive API та обмеження ключа. |
| `redirect_uri_mismatch` | Зіставте Authorized redirect URI з адресою `/teacher/cloud/google/callback/`, яку використовує сайт, включно зі схемою, доменом, портом і кінцевим `/`. Якщо SchoolNet працює за HTTPS-проксі, адміністратор має перевірити зовнішню схему запиту. |
| OAuth блокує вхід тестового користувача | Перевірте Test users або політики адміністратора Google Workspace; використайте обліковий запис, якому дозволений цей застосунок. |
| Публічна папка без ключа порожня або не читається | Перевірте доступ до неї. Якщо змінилася HTML-сторінка Google, використайте API key для публічної папки або OAuth для приватної. |
| «Розмір недоступний» / «Після експорту» | Джерело не передало розмір або файл є Google Документом. Остаточний розмір завантаженої копії буде біля готового матеріалу. |
| Nextcloud не відповідає з Docker | Перевірте доступність адреси й порту саме з app та ai_worker; localhost іншого сервера не веде на ваш Nextcloud. |
| Nextcloud відхиляє пароль | Перевірте користувача та чинність окремого пароля додатка; за потреби створіть новий. |
| «Обробник імпорту недоступний» | Адміністратор перевіряє стан ai_worker та доступність спільного приватного каталогу імпортів. |
| Файл не пройшов перевірку цілісності | Повторіть імпорт із доступного оригіналу; неповна або пошкоджена копія не прикріплюється. |

Збережені раніше зайві матеріали можна видалити під час редагування відповідного завдання. Виправлення ізоляції форм не прибирає вкладення з уже збережених завдань автоматично.

## Перевірка підключення перед роботою

1. Створіть тестове завдання й додайте невеликий звичайний файл з кожного підключеного диска. Для Google за потреби окремо перевірте експорт Документа.
2. Дочекайтеся підтвердження біля матеріалів, збережіть завдання й відкрийте вкладення. Перевірте назву, тип і вміст.
3. Відкрийте ще одну нову форму створення: попередніх файлів у ній не повинно бути. Просте відкриття вікна хмарних дисків не прикріплює файли.

Результати перевірки самого випуску: [4.5.9 — імпорт і цілісність](../RELEASE_VALIDATION_2026-10-19_CLOUD.md), [4.5.10 — діалог і стан форми](../RELEASE_VALIDATION_2026-10-19_CLOUD_UI.md).
