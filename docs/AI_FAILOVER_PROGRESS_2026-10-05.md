# ШІ: послідовний перехід і панель подій — 4.1.10

## План пріоритетів і виконання

1. **Встановити причину збою й фактичний порядок. Виконано.** Прочитано налаштовану чергу та часові записи `AIErrorLog` без API-ключів. Спроби 05.10.2026 о 18:25:29–18:25:56 UTC точно відповідають черзі: Gemini 3.1 Flash Lite → 3.6 → 3.8 → 3.7 → Flash Latest → Groq GPT-OSS-120B. Groq викликався й повернув 413. Це обмеження розміру тіла запиту, незалежне від використання квоти. 429 означає обмеження частоти/квоти, 503 — недоступність/перевантаження.
2. **Перевірити всі переходи. Виконано.** Єдина черга робить одну спробу на ввімкнену модель, за збереженим пріоритетом і з її підключенням. Успіх завершує перевірку. Помилки HTTP, порожня відповідь, некоректний JSON, бал поза шкалою та виняток передають запит далі. Виправлено дострокове завершення, коли модель повідомляла `assessment_blocked` або не повертала бал: інша модель може прочитати повні матеріали, тому перевірка переходить до неї без збереження сумнівного бала. Вимкнений автоматичний перехід як і раніше означає одну модель. При мережевому збої HTTP-пул не повторює POST і не надсилає його вдруге через urllib: після тайм-ауту перший запит міг уже бути оброблений. Обмежені повтори старої конфігурації та повтор без непідтримуваного формату залишаються сумісними.
3. **Показати перебіг перевірки. Виконано.** `AIJob.events`, міграція `0053`. Працівник записує підготовку, модель/номер спроби, причину помилки, перемикання, успішну відповідь і завершення. Статус API повертає події під час роботи та після завершення. Збереження прогресу не повинно ламати успішне оцінювання. Події обмежено 200 записами; сирі відповіді, промпти та ключі не додаються, відомі ключі всіх підключень вилучаються з повідомлень API. Контекст завдання скидається після виконання.
4. **Компактна панель для вчителя, учня й пакета. Виконано.** Спільний JS опитує статус раз на 1,5 с (5 с для прихованої вкладки). Видно поточну дію, індикатор очікування та розгортний журнал; при помилці журнал відкривається. Висота журналу обмежена 132 px. Немає вигаданого відсотка готовності. Повторні відповіді опитування не дублюють події. Панель залишається після результату, а останній журнал доступний після перезавантаження. Текст вставляється через `textContent`, адреса опитування перевіряється на той самий origin. Журнал учительської перевірки захищено тими самими правами, що результат; учень бачить лише самоперевірку. Пакет після вичерпання черги більше не запускає ту саму роботу нескінченно кожні 10 с через згадку 429 у загальній помилці: помилка фіксується, обробка переходить до наступної роботи.
5. **Уточнити сумісність Groq, зберігаючи всі докази. Виконано.** GPT-OSS-120B/20B — текстові моделі. Якщо є PDF/зображення, вони пропускаються до відправлення, з поясненням у панелі та переходом за чергою. Підключення й текстові запити залишаються працездатними. Немає автоматичної заміни введеної назви моделі або вилучення карт/схем заради успіху. Для відомої Groq `qwen/qwen3.8-27b` перевіряється документована межа 3 зображення після перетворення PDF та оптимізації. Інші моделі не обмежуються цим правилом. Локальне відхилення не рахується як фактичний API-запит у статистиці.
6. **Перевірити, документувати й випустити.** README, журнал версій і цей документ оновлено. Перед міграцією виконується узгоджена резервна копія PostgreSQL і файлів, попередній Docker-образ збережено для відкату. Новий образ проходить ізольовані тести, після цього запускаються `app` та `ai_worker`.

## Перевірки

- Host Python 3.14: **500 тестів**, 498 пройшли, 2 пропущені; 52,931 с. Окремо нові сценарії прогресу й транспортного рівня: 32 тести пройшли.
- Docker Python 3.12, ізольований запуск без мережі, робочих томів і виробничої БД: **500 тестів**, 498 пройшли, 2 пропущені; 53,623 с.
- Нові перевірки відтворюють точну послідовність 503 → 429 → 429 → 429 → 429 → 413; спостерігають живі події через API ще до відповіді моделі; перевіряють зупинку після успіху, відсутність наступної моделі, вимкнений перехід, порожню/заблоковану/некоректну відповідь, захист ключів, права читання й невитрачену спробу учня при збої.
- Інтеграція справжньої черги з транспортом (HTTP замінено тестовою відповіддю): Groq GPT-OSS відхиляється локально, Gemini отримує той самий візуальний доказ і повертає бал; лише відправлений запит додається до `AIRequestLog`. Текстовий GPT-OSS надсилається у Groq. Тайм-аут не спричиняє повтор через інший клієнт.
- Рендеринг чотирьох сторінок: перевірка вчителя, здача учня, пакет і налаштування. Немає вкладених форм. Синтаксис 10 унікальних вбудованих скриптів і спільного JS перевірено Node-компілятором.
- DOM-симуляція: послідовні події, відсутність дублікатів, доступність тіла фінальної відповіді, безпечний показ HTML як тексту, повторне використання панелі, розрив з’єднання та блокування сторонньої адреси опитування — пройдено. Реального браузера для візуальної перевірки в середовищі немає.
- Django `check`, `makemigrations --check --dry-run` та `git diff --check` — без помилок.

## Обмеження й налаштування

Панель спостерігає реальні спроби; вона не усуває зовнішні квоти чи недоступність API. Якщо всі сумісні моделі повернули помилку, оцінка не створюється. Наявна черга закінчується текстовим GPT-OSS: для візуальних робіт потрібно додати сумісну модель/підключення, здатні прийняти весь матеріал. Збережені пріоритети та ключі вчителя не змінюються автоматично. Події попередніх випусків не відновлюються заднім числом.
