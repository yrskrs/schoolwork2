Історичні записи описують стан відповідного випуску. Актуальний запуск та оновлення — у [README](../README.md); повний журнал сайту — у [feed/changelog.py](../feed/changelog.py).

## Оновлення 4.5.10: читабельний діалог і окремі чернетки завдань

- Текст хмарного діалогу збільшено до 16 px, додано A− / A+ з масштабом до 150% і збереженням вибору.
- Розміри Drive показуються з API або уточнюються за заголовками; невідомий розмір та експорт Документів позначено окремо.
- Успішний імпорт закриває діалог і показує підтвердження біля матеріалів. Завершений прогрес не відновлюється; нова форма не успадковує файли іншої чернетки, видалені матеріали не повертаються після перезавантаження.
- Додано посилання для API key та повну [інструкцію підключення](CLOUD_STORAGE.md).
- Перевірено: 814 тестів PostgreSQL, 31 перевірка операційних скриптів і Chromium у Docker. [Звіт](../RELEASE_VALIDATION_2026-10-19_CLOUD_UI.md).

## Оновлення 4.5.9: надійний хмарний імпорт

- Звичайні файли Drive зберігають справжній тип і назву; Google Docs/Sheets/Slides експортуються у відповідний формат.
- Передачу перенесено в серверну чергу з прогресом, скасуванням і приватним тимчасовим сховищем. Перевіряються розмір, доступні суми джерела, SHA-256 та структура підтримуваних форматів.
- Виправлено відображення помилок, перемикання дисків, вибір після пошуку, пагінацію API, оновлення OAuth та явне керування TLS Nextcloud. Перевірка Gmail більше не видається за авторизацію Drive.
- Довідка й історія завантажуються при відкритті; app/worker використовують один образ із перевіркою джерел, залежності Docker закріплено.
- Перевірено: 810 тестів PostgreSQL, 31 перевірка операційних скриптів і Chromium у Docker. [Звіт](../RELEASE_VALIDATION_2026-10-19_CLOUD.md).

- **📥 Швидкий імпорт матеріалів у завдання**: модальне вікно вибору файлів прямо у формі створення уроку з хлібними крихтами, пошуком, вибором декількох файлів та можливістю встановлення умови для модуля ШІ.

## Оновлення 4.4.2: повне видалення та аудит

Кнопка «Видалити» у списку класу та «Видалити учня та роботи» у профілі повністю прибирає учня й усі здачі з його збереженим ID, включно з попередніми спробами. Браузер запитує підтвердження. Дія та кожна видалена здача записуються в «Журналі дій»: автор, час, ідентичності профілю, класу, завдання та роботи збережені навіть після видалення. Окреме видалення здачі також журналюється.

Тезки не об’єднуються для видалення. Здачі інших учнів і спільні файли, що вони використовують, зберігаються. Файли без інших посилань видаляються після успішного збереження транзакції; відкат транзакції залишає їх. Якщо є роботи іншого вчителя, повне видалення потребує адміністратора. Учитель має доступ лише до своїх класів.

Видалення на цьому сайті не видаляє журнал на іншому сервері. Його позакласний запис можна окремо видалити в schooljournal 1.3.3; він не повертається після обміну. API v1/v2 та самостійна робота збережені; міграцій для 4.4.2 немає. Власні старі профілі, позначені неактивними, не видаляються під час оновлення.

Штатне оновлення: `bash scripts/update.sh` — перевірена копія, збірка та оновлення вебсервісу й AI worker. Повернення старого образу не повертає видалені роботи; відновлення даних із резервної копії потребує вибіркового перенесення з урахуванням пізніших змін. Не відновлюйте стару БД поверх нових оцінок.

## Перевірка інтеграції з журналом 1.3.2

Ігнорування конкретної оцінки чи учня на сімейній формі виконується у журналі. Завдання та їхні результати залишаються у власній базі цього сайту. Журнал пропускає ігноровані записи під час повторних запитів, навіть після виправлення оцінки. Відновлення у журналі не імпортує оцінки автоматично. Цей сайт працює без журналу й не потребує однакової версії. API v1/v2 збережені.

## Випуски 4.1.x

Версія **4.1.26** додає двосторонню REST API інтеграцію з локальним журналом оцінок та швидкий вибір учнів при здачі робіт:

- **🌐 REST API для локального журналу оцінок**:
  - **Керування API-ключами у налаштуваннях** (`/teacher/settings/?tab=api`): створення безпечних ключів доступу (`sk_journal_...`), розмежування прав (експорт оцінок / імпорт розкладу та списків), маскування токенів, копіювання в 1 клік, лічильник звернень, миттєве призупинення та відкликання.
  - **API вивантаження оцінок** (`GET /api/v1/journal/grades/`): передача оцінок, ПІБ учнів, класів, предметів, тем завдань, критеріїв НУШ та дат для автоматичного заповнення локального журналу. Підтримує фільтри за класом, предметом, завданням та часовим діапазоном.
  - **API синхронізації учнів та класів** (`POST` та `GET /api/v1/journal/roster/`): імпорт контингенту учнів з локального журналу без створення дублікатів (підтримуються формати ієрархічного JSON, списку об'єктів або звичайного тексту).
  - **Пряме опитування локального журналу** (`POST /api/v1/journal/pull/`): можливість підтягування списків безпосередньо з вказаної URL-адреси локального журналу в 1 клік.
  - **Інтерактивна документація**: готові приклади cURL та Python-скриптів прямо у вкладці налаштувань.
- **👤 Швидкий вибір учня зі списку класу при здачі робіт**: при виборі класу учневі більше не обов'язково щоразу вводити своє прізвище та ім'я вручну — автоматично завантажується список класу з журналу у зручний випадний список (quick-picker). При цьому можливість власноруч ввести прізвище або скористатися автодоповненням повністю збережена за допомогою перемикача «Ввести вручну».

Версія **4.1.25** усуває виявлені системним діагностичним аудитом помилки інтеграції ШІ-провайдерів (Groq, Gemini, OpenRouter):

- **🛡️ Запобігання Groq HTTP 413 (Payload Too Large)**: інтегровано точний підрахунок токенів (Token Counter з урахуванням кирилиці), зафіксовано безпечні ліміти вільного плану Groq (6000–6500 токенів, 3 зображення для Qwen), автоматизовано перемикання на моделі з більшим контекстом (Gemini/OpenRouter), а за їх відсутності — інтелектуальне авто-скорочення довідкової теорії вчителя (з повним збереженням робіт учнів та критеріїв).
- **⚙️ Усунення Gemini HTTP 400 (Invalid Argument)**: додано строгу валідацію та санітизацію payload для Gemini, білий список підтримуваних MIME-типів (відсіювання бінарних zip/docx із inlineData), очищення data-uri префіксів у base64, захист від порожніх parts та systemInstruction, а також каскадний авто-повтор без `thinkingConfig` / `responseMimeType` при відхиленні запиту застарілими чи специфічними версіями API.
- **🧩 Відновлення пошкодженого JSON (JSON Parsing Errors)**: додано балансувальник `repair_json_string`, який відновлює обірвані токенами масиви `[]`, об'єкти `{}` та лапки без втрати структури, та реалізовано повторний запит з експоненціальною паузою (exponential backoff) при отриманні синтаксично пошкодженої відповіді замість негайного збою.
- **⚡ Зовнішня стабільність (503 High Demand, Timeouts)**: збільшено таймаут запитів до Gemini з 35с до 50с для уникнення read timeouts, а також встановлено 60-секундний cooldown для моделі при отриманні 503 High Demand відповідно до патерну Circuit Breaker.
- Нових міграцій бази даних немає.
