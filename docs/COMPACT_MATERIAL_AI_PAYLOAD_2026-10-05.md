# Компактні матеріали та запити ШІ — 4.1.9

## План пріоритетів і виконання

1. **Виконано: перевірити Groq та вибір моделі.** Журнал показав запити до різних моделей, а не приховану підміну на GPT-OSS. Із робочого контейнера виконано два GET запити списку моделей з тим самим збереженим ключем. Стандартний Python-клієнт отримав Cloudflare Error 1010 / HTTP 403; із User-Agent SchoolNet отримано HTTP 200 та 11 моделей. Ключ не виводився. Додано User-Agent для обох HTTP-транспортів. 401, 403, дозволи проєкту й помилки шлюзу більше не об’єднуються у повідомлення «Недійсний API Key». Причина API зберігається з приховуванням ключа. Це діє в тесті підключення та оцінюванні. [Groq: коди помилок](https://console.groq.com/docs/errors), [дозволи моделей](https://console.groq.com/docs/model-permissions).
2. **Виконано: скоротити запити зі збереженням доказів.** JSON передається як компактний UTF-8 без зайвих пробілів і Unicode escape. Повторний великий блок інструкцій прибрано; системні правила, схема, поріг, критерії, усі ГР і повний текст матеріалів залишилися. Текст документа критеріїв не додається вдруге, якщо повністю збігається з уже включеним витягом. Програми й відповіді не обрізаються, відступи коду не змінюються.
3. **Виконано: стиснути медіа.** Lossless WebP використовується лише якщо менший за оригінал; роздільність, пікселі й прозорість зберігаються. Анімація залишається оригінальною. Якщо локальний кодек не може оптимізувати зображення, зберігається початковий файл. Точні дублікати об’єднуються зі збереженням усіх джерел. Для Gemini окреме зображення може бути замінене його повним представленням у PDF лише за точним збігом пікселів і перевіреною видимістю та достатнім розміром. Обрізані, повернуті, перекриті, прозорі, замалі чи неперевірені об’єкти залишаються окремими. Результати оптимізації кешуються за вмістом. [Gemini: обробка PDF та роздільність](https://ai.google.dev/gemini-api/docs/document-processing).
4. **Виконано: контролювати розмір OpenRouter.** Передається цілий PDF через `file_data`, із `file-parser` / `native`. Потрібна модель з нативним читанням PDF. Автоматичне OCR-перетворення не використовується: воно може обмежити число переданих зображень. Для інших OpenAI-сумісних API збережено перетворення всіх PDF-сторінок на картинки. Вимірюється фактичний розмір готового JSON після base64 і стиснення; межа 7 500 000 байтів дає запас до повідомлених користувачем 8 МБ. Завеликий запит повертає локальний 413 без мережевого виклику та без вигаданого запису фактичного API-запиту. За ввімкненого переходу використовується наступна модель черги; сторінки не вилучаються. [OpenRouter: нативні PDF та обмеження OCR](https://openrouter.ai/docs/guides/overview/multimodal/pdfs).
5. **Виконано: компактний перегляд та спільні блоки.** Кнопки режимів і слайдів об’єднано у спільній панелі. Для одного файла повторний список матеріалів приховано. На малих екранах назви кнопок коротші, але доступні повні aria-label; заголовок файла не створює окремий великий рядок. Збережено клавіші стрілок, Escape, фокус після закриття, завантаження та нову вкладку. До 1280 CSS px або за висоти до 760 px зменшено поля шапок, карток, форм, редактора, екрана здачі, розкладу, налаштувань і панелей дій. На малих екранах вкладки ШІ більше не займають висоту як липка панель. Текст читабельний, довгі назви переносяться; мобільні кнопки мають більшу висоту для натискання.
6. **Виконано: версія та README.** Версія 4.1.9, нових міграцій БД немає.

## Вимірювання та межі

- На синтетичному однаковому контексті текст запиту скоротився **7048 → 3550 символів**; системні правила **5608 → 5608**. Текст роботи, критерії та визначення ГР збережено.
- Для роботи зі скріншота записано 93 243 вхідні токени. Діагностичне читання без зовнішнього ШІ-запиту показало: текст учня 1971 символ, текст матеріалів учителя 33 191 символ; 3 PDF та 44 окремі картинки разом з роботою учня. Медіа після оптимізації: **47 → 46 об’єктів**, **12 524 660 → 9 671 168 байтів base64**, приблизно на 23% менше. Повторне використання кешу — 0,49 с. Вміст матеріалів і ключі не виводилися.
- Цей великий матеріал усе ще перевищує межу OpenRouter. Він потребує іншого постачальника у черзі або поділу на окремі завдання; система не маскує обрізаний матеріал під повну перевірку.
- Менше транспортних байтів не означає пропорційно менше токенів: модель окремо обробляє візуальні сторінки. Нове фактичне число токенів для цієї роботи не вимірювалося платною повторною перевіркою; 95 тисяч не замінюються вигаданою оцінкою економії.

## Перевірки

- Повний локальний набір: **487 тестів, 485 успішні, 2 пропущені, помилок немає**, 52,776 с. SQLite, медіа та кеш тимчасові; робоча БД не використовується. Додано 19 регресійних тестів транспорту й медіа.
- Повний набір у фінальному Docker-образі: **487 тестів, 485 успішні, 2 пропущені, помилок немає**, 51,632 с. Контейнер без мережі та робочих томів.
- Цільові перевірки покривають точний ключ і модель, HTTP-транспорти, помилки шлюзу й дозволів, приховування ключа, UTF-8 JSON, граничний розмір, нативний PDF, усі сторінки, джерела дублікатів, пікселі, прозорість, анімацію та локально непідтримуваний кодек.
- DOM-симуляція перевіряє 1/2 файли, спільну панель слайдів, клавіатурну навігацію, текстовий режим, очищення після закриття та повернення фокусу.
- Згенеровано шість сторінок: завдання учня, перегляд роботи, налаштування моделей, розклад, успішна здача та деталі роботи. Вкладених форм немає; контейнер спільної панелі слайдів присутній. Синтаксис 14 унікальних inline-скриптів перевірено у V8. Django `check`, `makemigrations --check --dry-run` та `git diff --check` успішні.
- Окремо в тимчасовій БД перевірено весь шлях оцінювання зі зменшеною межею запиту: локальний 413 для першого постачальника, успіх другого, збережений бал та його токени. HTTP-транспорт викликано рівно один раз; у журналі фактичних API-викликів один запис.
- Візуальна перевірка у справжньому браузері недоступна: інструмент не має браузерів. FHD/150% та малий екран потрібно переглянути на пристрої користувача.
