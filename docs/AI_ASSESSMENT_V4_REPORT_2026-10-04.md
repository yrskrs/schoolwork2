6. Перевірити поведінку автоматичними тестами, реальною моделлю на вигаданих матеріалах і браузером у двох темах. Оновити версію, README, довідку й «Оновлення платформи».
7. Зберегти резервну копію бази, перевірити зібраний образ, перезапустити Docker та порівняти дані до й після розгортання.

## Реалізовані зміни

### Критерії та оцінювання

- У параметрах завдання додано «Окремі критерії для класів». Клас успадковує спільний шаблон або отримує власний шаблон і набір ГР. Для традиційного оцінювання ГР не застосовуються.
- Єдина функція вибору критеріїв використовується учнівською, вчительською та пакетною перевірками. Явний вибір іншого шаблону вчителем залишається доступним.
- Власні критерії й розбаловка завдання передаються в модель та мають пріоритет над загальними правилами. Підсумковий бал із власними вагами не підміняється простим середнім ГР або пропорцією кількості вправ.
- ГР зіставляються точно: «ГР 1» не збігається з «ГР 10».
- ZIP-перенесення зберігає шаблони, документи критеріїв, класові налаштування та позначку першоджерела умови. Класи зіставляються за назвою; різні документи критеріїв не об'єднуються лише через однакову назву.
- Прибрано вигадування числового бала за довжиною дослідницького тексту чи кількістю знайдених відповідей без оцінених критеріїв.

### Контекст і пояснення

- ШІ отримує інструкцію, власні критерії, матеріали вчителя, текст роботи, коментар, доступне посилання та візуальні сторінки. Позначений файл умови має окрему роль.
- Презентації й PDF передаються без старого вибіркового обмеження перших слайдів / сторінок. Excel включає всі аркуші, формули, збережені значення та доступні дані діаграм. DOCX також включає таблиці, колонтитули й дані діаграм.
- Вимога «виконати вправу 3» не означає виконання всіх вправ у презентації. Виправлено помилкове зіставлення номера слайда з номером вправи.
- Правильний зміст в іншому форматі може отримати частковий кредит. Порушення формату пояснюється за відповідним критерієм, без автоматичного мінімального бала лише за розширення.
- «Як ШІ розуміє завдання» просить просте покрокове пояснення для віку учнів. Візуально визначений результат не підміняється локальним припущенням за словами «презентація» чи назвою файла. Нейтральні картки розбаловки враховують власні ваги вчителя.
- Зміни інструкції, матеріалів, класів, посилань або критеріїв роблять старий збережений аналіз неактуальним. Локальний запасний розбір явно позначено як допоміжний.
- Доступний статичний текст посилань вчителя кешується й додається до контексту. Для відео, динамічного ресурсу чи бінарного документа за URL зазначаються межі прочитаного.

### Рекомендації та одна спроба

Учень і вчитель отримують причину бала, конкретні докази за критеріями та послідовні кроки покращення. Учневі ці блоки доступні й після перезавантаження сторінки. Вони зберігаються в даних його самоперевірки, без розкриття остаточних оцінок вчителя.

Одна успішна самоперевірка на завдання зберігається між повторними здачами. Невдала, обірвана або технічно неможлива перевірка не витрачає спробу. Непрочитаний елемент позначається «не вдалося перевірити», а не «не виконано». Відповідь без достатніх даних для бала або некоректний JSON не зберігаються як успішна оцінка.

Анонімна здача, відсутність реєстрації учнів і можливість надсилати файли понад 500 МБ збережені. Остаточні оцінки учням не відкрито.

## Перевірка форматів

| Формат | Підтверджена обробка | Обмеження |
| --- | --- | --- |
| DOCX / DOC / ODT / RTF | Текст і PDF після LibreOffice; DOCX — таблиці, колонтитули, діаграми | Складні об'єкти залежать від конвертера; невдача відображається явно |
| PPTX / PPT / ODP | Слайди й візуальні сторінки; текст і дані діаграм підтримуваних презентацій | Анімації та вбудоване відео не виконуються |
| XLSX / XLS / ODS | Аркуші, таблиці, доступні формули й діаграми, візуальні друковані області | Макроси не виконуються; збережені значення формул можуть бути відсутні |
| PDF / зображення | Текст і візуальні сторінки / зображення | Потрібна мультимодальна модель; якість залежить від читабельності |
| Scratch SB3 | Повна структура блоків, змінних, списків, повідомлень і метаданих ресурсів | Немає автоматичного запуску, перевірки звуку, анімації чи вигляду костюмів |
| micro:bit HEX | Доступний вбудований код і структура | Немає фізичної перевірки пристрою; без вихідного коду аналіз обмежений |
| Access MDB / ACCDB | Схема, таблиці, доступні SQL / зв'язки, вибірки даних | Немає повної перевірки форм, звітів, VBA та виконання макросів |
| Код / текст | Статичний аналіз тексту | Код не виконується |
| Архіви | Вибірковий текст і частина зображень ZIP | Не повна перевірка вкладень; обмеження передаються моделі |
| Аудіо / відео / невідомі файли | Приймання, завантаження й ручний перегляд | Змістова ШІ-перевірка не реалізована; оцінювання за назвою заблоковано |

Gemini отримує PDF як документ. Для інших чат-провайдерів усі сторінки перетворюються на справжні JPEG, замість некоректного передавання PDF як `image_url`. Цю підготовку перевірено автоматично; реальну мультимодальну перевірку виконано на Gemini. Можливості конкретної моделі інших провайдерів потрібно враховувати при її виборі.

Система не може достовірно перевірити виконання будь-якої програми лише за її статичною структурою. Для таких вимог необхідна ручна перевірка. Відсутність підтвердження не перетворюється на твердження, що учень нічого не зробив.

## Швидкодія та вимірювання

- Спільний приватний кеш для вебпроцесів і worker зберігає витяги, PDF, зображення сторінок, HTML та хеші. Ключі враховують версію алгоритму й зміни файла.
- У запиті залишена одна копія фактів локального розбору. Стандартні повторні інструкції замінені компактними правилами; власні критерії та самі матеріали не відкидаються.
- Бюджет відповіді адаптується до числа ГР і завдань. Обірвана через ліміт відповідь не стає успішною оцінкою.
- Сторінка завдання спочатку завантажує метадані матеріалів; конвертація відбувається після відкриття конкретного файла. Спільний HTML-кеш і кеш перевірки збігів також скорочують повторні відкриття робіт вчителем.

Вимірювання на одному штучному прикладі з тим самим завданням і роботою:

| Показник | До / перший запуск | Після / повторний процес |
| --- | --- | --- |
| Текст запиту, разом із системними правилами | 38 770 символів у 3.5.10 | 5 394 у 4.0.0: на 86,1% менше |
| Витяг DOCX із підготовкою PDF | 1,4508 с | 0,0005 с із кешу |
| HTML того самого DOCX | 0,2105 с | 0,0001 с із кешу |

Кеш перевірено в окремих процесах: текст, PDF і HTML збереглися без зміни. Це вимірювання підготовки контрольного документа, а не гарантія часу всіх сторінок або відсотка економії загальних API-токенів. Візуальні сторінки й сама робота продовжують входити до контексту.

## Реальна проба моделі

На ізольованій SQLite у пам'яті створено вигаданий урок для 7 класу. Вправа 3 була зображенням на слайді 2; слайд 3 містив незадану вправу 4. Завдання вимагало бюлетень у дві колонки з трьома правилами безпеки. Вчитель задав 9 балів за зміст і 3 за формат. Учнівський приклад містив правильні правила на одному слайді презентації.

`gemini-3.1-flash-lite`:

- прочитав зображення, визначив вправу 3 й джерело «Слайд 2»;
- пояснив створення бюлетеня покроково для 7 класу;
- зарахував зміст, дав **9/12**, окремо пояснив відсутність двоколонкового формату;
- запропонував перенести текст у документ, налаштувати колонки та здати PDF / DOCX;
- не вимагав вправу 4 та не змінював збережену оцінку вчителя.

У фінальній пробі пояснення тривало 7,2 с, оцінювання — 9,01 с. API повернув 5 461 та 5 619 сумарних токенів для цих запитів відповідно. Проба не використовувала реальних робіт учнів або їхніх персональних даних. Ключі передавалися лише в пам'яті й не включені до звіту. Точність моделі на всіх можливих предметах і форматах із цієї проби не випливає.

## Перевірки

- Повний набір: **372 автоматичні тести**, PostgreSQL в окремій тестовій базі. Провайдери в них імітуються.
- 23 нові сценарії v4: класові критерії, точне зіставлення ГР, власні ваги, частковий формат, недоступні докази, JSON, одна спроба, збереження пояснень після перезавантаження, перенесення критеріїв, пізні слайди, Excel, Scratch, PDF для інших провайдерів, кеш і посилання.
- Перевірено відсутність незаписаних міграцій, компіляцію Python та форматування Git diff.
- Браузер: редактор створення / редагування, переглядач, учнівський результат і пояснення завдання; **20 станів** на 390 та 1280 px у світлій і темній темах. Без горизонтального переповнення сторінки та JavaScript-помилок. Довгі тексти рекомендацій і критеріїв переносилися. Виступ бейджа сповіщень за межі його кнопки є штатним елементом інтерфейсу.
