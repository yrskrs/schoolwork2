# Перевірка фільтрів звітів — 4.4.16

## Причина й виправлення

При виборі 8-В та позакласних учнів знятий прапорець «Лише оцінені роботи» показував 12 робіт: 4 з обраного класу та 8 неоцінених з іншого класу. Фільтр використовував `assignment.classes` як альтернативу класу здачі. Тому спільне завдання додавало чужі роботи, а відсутність цих учнів у журналі обраного класу додатково позначала їх як позакласних. Оцінені роботи приховували проблему лише через відсутність оцінок у зайвих записах.

Фільтр використовує `Submission.class_group_id`. Призначення завдання кільком класам і поточний клас переведеного учня не змінюють клас історичної здачі. Гість іншого класу, який явно здав роботу за обраний клас, залишається в його звіті.

## Правила відбору

| Умова | Результат |
| --- | --- |
| Конкретний клас | Лише здачі цього класу. |
| Усі класи | Доступні здачі без обмеження класу. |
| Учні журналу / позакласні | Передані ID списку обраного класу та вчителя; список іншого класу не підставляється. |
| Немає підключених журналів | Попередній режим: позакласні — ручні здачі без профілю учня. |
| Лише оцінені | Непорожня остаточна оцінка або статус перевірки, включно з «Доопрацювати»; пропозиція ШІ не є остаточною оцінкою. |
| Прапорець знятий | Додаються неоцінені роботи в тих самих межах класу, журналу, завдання та доступу. |
| Звичайний учитель | Власні завдання, отримані або перевірені ним роботи; «Всі оцінки» та реквізити заміни не розширюють доступ. |
| Адміністратор | «Всі оцінки» охоплюють школу; «Тільки мої» зберігає обмеження власних/перевірених робіт. |
| Основний учитель | Контекст списку журналу та реквізити заміни в межах доступних робіт. |
| Завдання | Додаткова точна умова; несумісний вибір дає порожній звіт замість скидання до всіх робіт. |
| ПІБ | Усі введені частини мають збігатися з іменем або прізвищем здачі. |
| Дати | Дата перевірки, а за її відсутності — дата здачі; межі включні, часовий пояс Києва. |
| PDF із вибраними ID | Перетин вибраних ID з поточним відбором; чужі, старі та невідповідні рядки не додаються. |
| Некоректні ID, дати чи список PDF | Порожній відбір; обмеження не ігноруються. |

HTML та обидва режими PDF використовують спільний розбір параметрів і один сервіс відбору. У списку завдань доступні також роботи заміни й історичні здачі; явно вибране старіше завдання зберігається навіть поза першими 200 варіантами.

## Перевірки

- 75 тестів на ізольованій SQLite та окремій PostgreSQL-базі.
- Матриця 192 комбінацій: три різні класи та всі класи, три групи учнів, обидва стани оцінювання, конкретне/будь-яке завдання, обидва охоплення та ролі вчителя/адміністратора.
- Для 24 комбінацій сторінки перевірено точні ID видимих рядків і статистику; обидва режими PDF отримують ті самі ID. Окремо згенеровано й прочитано справжні PDF, щоб перевірити вміст відфільтрованої групи.
- Перевірені спільні завдання, учень після переведення, гість з іншого класу, ручні здачі, відсутній журнал, кілька вчителів, заміна уроку, видалене завдання, попередня спроба, порожні оцінки, пропозиція ШІ, межі дат у Києві, пошук імені та вибір рядків PDF.
- На чинних даних перевірено 102 комбінації для 16 доступних навчальних класів та всіх класів. Перевірка виконана з підготовленого образу у транзакції PostgreSQL `REPEATABLE READ READ ONLY`; реальні роботи й оцінки не змінювалися. Для позакласних учнів додатково звірені HTML і обидва режими PDF кожного класу.
- `manage.py check`, `makemigrations --check --dry-run` та `git diff --check` пройшли. Візуальна браузерна перевірка не виконувалася.

У знімку перевіреного класу 8-В результат після виправлення:

| Група | Лише оцінені | Прапорець знятий |
| --- | ---: | ---: |
| Усі роботи | 41 | 46 |
| Учні журналу | 37 | 42 |
| Позакласні | 4 | 4 |

Позакласних робіт однакова кількість, оскільки всі чотири вже мають оцінку або статус перевірки. Вісім робіт іншого класу виключені умовою класу в обох станах прапорця. Це кількість робіт у перевіреному знімку, а не постійна кількість учнів.

## Оновлення

Випуск 4.4.16 містить виправлення та узгоджені `VERSION`, `RELEASES.json`, журнал сайту, Markdown, README і версії Docker / Compose. Нових міграцій у цьому випуску немає. Застосовуйте звичайну процедуру з перевіреною резервною копією й перевіркою вебсервісу та ШІ-воркера. Відкат коду виконується поверненням попереднього образу.
