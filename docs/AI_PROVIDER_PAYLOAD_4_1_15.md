# OpenRouter / Groq: запити та межі — 4.1.15

Перевірено історію 4.1.9–4.1.14, журнал помилок контейнера й формування запитів. Попередня оптимізація зменшила матеріал, але локальний Groq preflight продовжував відхиляти запити за приблизним підрахунком і жорстко заданим безкоштовним тарифом. Такі 413 не означали фактичного виклику Groq. Резерв відповіді не враховував вхідний текст. OpenRouter/free отримував native PDF, а не звичайний візуальний вхід; збій обраного backend одразу передавав перевірку наступній моделі.

## Зміни

- Основний файл з кількома вправами фокусується на явно заданих номерах. Повна умова й вступ зберігаються. Підтримуються заголовки всередині сплощених таблиць DOCX. Невідомий номер, залежність від іншої вправи або зразка, неоднозначна розбаловка залишають повне джерело.
- Довідкові презентації враховують відмінки ключових слів і весь слайд; вимоги наприкінці довгого документа не губляться через ранній `break`. Посилання теж компактизуються.
- Для Groq правила й приклади JSON викладено компактно. Після знаходження основної умови повторна теорія й вправи не передаються; критерії, індивідуальна розбаловка, вимоги зі scope та текст учня зберігаються.
- Медіа мають роль джерела та ознаку доступного тексту. Groq/OpenRouter вилучають лише читабельні довідкові/критеріальні копії. Непрочитані джерела й потрібні візуальні умови залишаються. Текстова задана вправа без посилання на зображення не тягне в запит сторінки всіх незаданих вправ.
- Groq використовує `max_completion_tokens` з резервом для входу й похибки. Планові числа — не квоти акаунта і не створюють локальний 413. Швидкий режим Qwen використовує `reasoning_effort=none`, GPT-OSS — `low`; режим глибокого мислення не вимикається.
- `openrouter/free` отримує справжні зображення потрібних PDF-сторінок без примусового native parser. Інші OpenRouter-моделі зберігають попередню нативну передачу PDF. Після отриманого 502/503 є один повтор вибору маршрутизатора; мережевий тайм-аут і 429 у єдиній черзі не повторюються.
- Міркування без кінцевої відповіді не використовуються як результат. Масив текстових частин відповіді коректно читається. Непередані візуальні докази GPT-OSS та межа трьох зображень Qwen явно описуються моделі: залежні критерії `unverifiable`, за недостатності даних `assessment_blocked=true`.
- Журнал показує розмір контексту без його тексту чи ключів. Нових міграцій немає.

## Вимірювання без зовнішнього ШІ

На проблемній роботі №42 учитель задав вправу 6, основний DOCX містить вісім вправ. Повний основний текст: **4909 символів**, повний вибраний фрагмент зі вступом: **1246**. Текст учня: **1115 символів**, збережений у запиті повністю.

Підготовку виконано з перехопленим HTTP і відкатом транзакції, без збереження нової оцінки. Раніше загальний текст запиту становив **13477 символів**, правила **5902**, вихідний резерв **5380**. Після виправлення:

| Модель | Текст запиту, включно з підписами медіа | Правила | Приблизні текстові токени | Вихідний резерв | Тіло JSON | Візуальні частини |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| OpenRouter/free | 13072 | 5902 | 7278 | 5380 | 485261 байт | 2 |
| Groq Qwen | 7548 | 2893 | 4033 | 1800 | 471348 байт | 2 |
| Groq GPT-OSS-120B | 7428 | 3134 | 4080 | 3570 | 17567 байт | 0 |

Токени в таблиці — оцінка довжини тексту, без реального токенізатора та без візуальних токенів. Це не фактична статистика API. Плановий бюджет окремо резервує приблизно 1000 токенів на зображення та 350 на похибку/оформлення. Завелика обов'язкова робота, квота акаунта або недоступність сервісу все ще можуть спричинити перехід до іншої моделі.

## Перевірки

- Повний ізольований Docker-набір: **515 тестів, 513 успішних, 2 пропущені**. Контейнер без мережі, робочих томів і виробничої БД. Виявлений випадок `None` у витягу PDF виправлено; повторний набір пройшов.
- Нові регресії: повні вибрані вправи й залежності, сплощені DOCX-таблиці, пізні критерії, відмінки ключових слів, збереження тексту учня/власної інструкції/критеріїв, відсутність вигаданого 413, бюджет відповіді, ролі медіа, PDF для free router, reasoning-only відповіді, повтор 502 та відсутність повтору timeout/429.
- `manage.py check`, `makemigrations --check --dry-run`, `git diff --check` пройшли.
- Короткий живий штучний JSON-запит через збережені підключення: **OpenRouter/free, Groq Qwen, Groq GPT-OSS-120B — HTTP 200, коректний JSON**. Учнівські матеріали не надсилались. Тести підтверджують доступність підключень, а не успішність повного оцінювання цієї роботи.
- Повторний діагностичний експорт реальної роботи на зовнішні API відхилено автоматичною перевіркою дозволів; він не виконувався і потребує окремого дозволу користувача.

## Джерела можливостей провайдерів

- [Groq: rate limits](https://console.groq.com/docs/rate-limits): фактичні ліміти залежать від організації; TPM не є розміром контекстного вікна.
- [Groq: reasoning](https://console.groq.com/docs/reasoning): підтримувані значення `reasoning_effort` й `max_completion_tokens`.
- [OpenRouter: free router](https://openrouter.ai/docs/guides/routing/routers/free-router): вибір безкоштовної моделі враховує потрібні можливості входу.

## Розгортання

Фінальний образ пройшов ще **90 цільових тестів**, `check` і перевірку міграцій без мережі та робочих томів. Попередній образ збережено як `schoolwork2-app:before-v4.1.15`.

Перевірена узгоджена копія БД і файлів: `backups/2026-10-05_23-46-23_KsaAOu`. Після її створення оновлено `app` та `ai_worker`; обидва healthcheck пройшли. HTTP сторінки входу — 200, HTML і worker показують 4.1.15; heartbeat воркера актуальний. Схема БД не змінювалась. Оцінювання реальної роботи діагностикою не запускалось.

Після оновлення Groq Qwen та GPT-OSS повернули HTTP 200 і очікуваний тестовий JSON. OpenRouter теж повернув 200; одна відповідь не пройшла точне порівняння поля `ok=true`, тому додатково перевірено штатний JSON-парсер. Наступна штучна відповідь `{"ok":true}` коректно прочитана; фактична модель маршрутизатора — `dots-studio/dots-3-note-preview:free`. Це підтверджує працездатність нового транспорту, але не гарантує якість кожного довільно обраного безкоштовного backend.
