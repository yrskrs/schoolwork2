# SchoolNet 4.1.3

SchoolNet — платформа навчальних завдань для шкільної локальної мережі. Вчитель публікує інструкцію та матеріали, учні надсилають файли або посилання без реєстрації й бачать історію здач. Вчитель перевіряє роботи, залишає відгуки та веде журнал. Оцінки вчителя учням не показуються.

Версія **4.1.3** розширює перевірку робіт учнів на використання ШІ на презентації (.pptx, .ppt, .odp), зображення, PDF-документи та електронні таблиці. Забезпечено виявлення характерних ознак та преамбул чат-ботів на кожному слайді, сканування метаданих генераторів (Gamma, Tome, Canva, Midjourney тощо) та відображення статусу виявленого ШІ у пакетній перевірці. Історія змін доступна в «Оновленнях платформи» та [feed/changelog.py](feed/changelog.py).

## Запуск через Docker

Потрібні Docker, Docker Compose з підтримкою `up --wait --wait-timeout`, Bash і Python 3 на сервері для перевірки архівів. Образ використовує Python 3.12, Django з діапазону 5–6 та PostgreSQL 16. LibreOffice, Poppler, antiword і mdbtools уже входять до образу.

```bash
git clone https://github.com/yrskrs/schoolwork2.git
cd schoolwork2
cp .env.example .env
# Відредагуйте .env перед запуском.
docker compose build app
docker compose up -d --wait --wait-timeout 240 app ai_worker
docker compose ps
```

У `.env` задайте власні `SECRET_KEY`, `POSTGRES_PASSWORD` і відповідний пароль у `DATABASE_URL`; залиште `DEBUG=False`. `APP_PORT` за замовчуванням — `8000`. Не додавайте `.env` до Git.

Відкрийте `http://localhost:8000/` на сервері або `http://АДРЕСА_СЕРВЕРА:8000/` у шкільній мережі. Майстер першого запуску допоможе створити заклад, адміністратора, предмети та класи. Подальше керування доступне в кабінеті вчителя.

Compose запускає три служби:

| Служба | Призначення |
| --- | --- |
| `app` | Django / Gunicorn, сторінки, приймання робіт; міграції та збір статики при запуску |
| `ai_worker` | Черга перевірок, пояснення завдань і тестів моделей поза вебзапитом |
| `postgres` | Завдання, здачі, оцінки, налаштування та стан черги |

Томи `postgres_data`, `app_media` і `app_logs` зберігають дані між перезбираннями. Спільний `app_cache` містить повторно використовувані витяги документів, візуальні сторінки та HTML-перегляди. Кеш є приватним серверним сховищем, не публічним каталогом. Міграція `0049` додає налаштування критеріїв окремих класів; `0050` дозволяє невизначений відсоток ШІ замість вигаданого числа. Існуючі значення й оцінки зберігаються.

## Робота учня

- Стрічка завдань із фільтром за класом і предметом; однакова ширина та стиль зі сторінками завдання і здачі.
- На сторінці завдання основною є інструкція «Що потрібно зробити». Матеріали відкриваються по центру екрана; можна перемикати документ, текстовий вигляд, файл і слайд.
- Перед здачею видно тему та обраний клас. Рідкісні дії винесені з основного маршруту до кнопки надсилання.
- «Мої роботи» показує факти здачі й повторні спроби. Реєстрація учнів та код доступу до роботи не потрібні.
- Якщо вчитель дозволив, після здачі доступна **одна успішна самоперевірка ШІ на завдання**. Перездача не поновлює спробу. Технічний збій або недостатні дані для оцінки не витрачають спробу.
- Самоперевірка пояснює попередній бал, виконані й частково виконані критерії та конкретні кроки роботи над помилками. Остаточна оцінка вчителя залишається приватною.

Застосунок не вводить ліміт розміру завантаження: учні можуть надсилати великі роботи, зокрема понад 500 МБ. Вільне місце, час передавання та обмеження зовнішнього проксі залежать від середовища розгортання. Ліміти контексту провайдера ШІ є окремим питанням і не обмежують приймання файлів.

## Кабінет вчителя

Меню «Робота» містить завдання, здачі, журнал, звіти та заміни, учнів і класи, пакетну ШІ-перевірку й налаштування. Навігація та додаткові дії розділені; основні дії розташовані біля відповідного вмісту. Інтерфейс має світлу й темну теми та підтримує вузькі екрани.

У редакторі завдання класи й предмет зібрані в бічному блоці «Кому призначено». Можна додати кілька файлів, посилання, власні критерії, обрати файл із першоджерелом умови та зберегти чернетку або опублікувати завдання. Спільний шаблон критеріїв і ГР можна перевизначити для окремих класів у параметрах ШІ. Дублювання та ZIP-експорт / імпорт зберігають критерії, документи критеріїв і налаштування класів; при імпорті класи зіставляються за назвою.

У переглядачі роботи файл учня та інструменти перевірки розташовані поруч. Вкладки «Умова й матеріали», «ШІ-перевірка», «Відгук» і «Про роботу» зберігають стан під час перемикання. Інструменти або документ можна розгорнути; інструменти також можна згорнути до вузької смуги.

Верхня панель містить попередню й наступну роботу, завантаження, оцінювання, збереження та «Зберегти й далі». Видно індикатори ШІ, збігу файлів, групової роботи та кількість відгуків. `Alt + ← / →` перемикає роботи; `Enter` або `Ctrl + Enter` зберігає оцінку у відповідному полі. Групові роботи підтримують індивідуальні оцінки учасників.

## Як працює оцінювання ШІ у версії 4

1. Система визначає критерії **для класу цієї здачі**: індивідуальні налаштування класу або спільний шаблон завдання. Явно обраний вчителем шаблон у переглядачі / пакетній перевірці може перевизначити цей вибір. Переглядач відновлює останній успішний вибір вчителя й показує ГР наступної перевірки та попереднього результату. Кнопка «Повернути ГР завдання» застосовує налаштування цього класу.
2. Опис «Що потрібно зробити» визначає обсяг. Позначений файл умови та решта матеріалів розкривають зміст заданої вправи. Система передає текст і доступні візуальні сторінки, включно з пізніми слайдами та діаграмами.
3. Модель зіставляє потрібний результат із усіма файлами, коментарем і доступним посиланням учня. Інші вправи з матеріалів не стають обов'язковими автоматично.
4. Правильний зміст в іншому форматі зараховується за відповідними критеріями. Наприклад, презентація замість бюлетеня може означати часткове виконання; недолік формату пояснюється окремо.
5. Власні критерії та ваги завдання мають пріоритет. Обрані ГР зіставляються точно, тому «ГР 1» не підміняється «ГР 10». Для традиційного оцінювання ГР не застосовуються.
6. Рекомендації вчителю містять пояснення бала, результат за кожним критерієм, конкретні докази й наступні кроки. Учень бачить пояснення бала та поради; детальна «Перевірка критеріїв» залишається тільки вчителю. Пропущена моделлю обрана ГР відображається без бала з поясненням. Недоступний елемент позначається «не вдалося перевірити», а не «не виконано». Якщо даних недостатньо для бала, перевірка завершується повідомленням без використання учнівської спроби.

«Як ШІ розуміє завдання» пояснює учневі задані дії, очікуваний результат і порядок роботи мовою вікової категорії. Пояснення використовує всі прикріплені матеріали та враховує критерії класів. Зміна інструкції, файлів чи критеріїв робить збережений аналіз неактуальним. Якщо модель недоступна, локальний попередній розбір явно позначається як допоміжний.

Оцінка ШІ — рекомендація для вчителя, а не автоматичне остаточне рішення. Підозра на використання ШІ чи однакові файли не є доказом плагіату. Програми учнів не запускаються автоматично.

### Ознаки ШІ та правила вчителя

Перевірка зіставляє прочитані текст, код і зображення. Додатково читаються метадані зображень, зокрема вкладених у DOCX/PPTX/XLSX/SB3/ODT/ODP/ODS; також перевіряються декларації походження в метаданих OpenDocument, **до** оптимізації картинки. Відсутність метаданих, охайний стиль і гарна графіка не доводять самостійності чи генерації; змінювані метадані теж не є доказом авторства. C2PA/SynthID криптографічно не перевіряються. Відео, аудіо й непрочитані об’єкти не оголошуються перевіреними.

Вчитель і учень після своєї самоперевірки отримують пояснення конкретних ознак та правило завдання. Непідтверджений відсоток генерації й відсотковий поріг прибрані з нової перевірки. Якщо ШІ дозволено, сам факт його використання не знижує бал. Якщо заборонено, підозра потребує уточнення; пряме пояснення учня про використання може враховуватися за **явним критерієм самостійності та його вагою**, без вигаданого штрафу. Оцінка вчителя залишається приватною.

За відсутності виразних ознак показується «Походження роботи не встановлено», а не підтвердження самостійності. Бал оцінює наданий результат; процес створення статичного файла не встановлюється.

Автоматична перевірка не може надійно визначити авторство всього ШІ-контенту. Для спірних випадків потрібні пояснення кроків, чернетки або демонстрація результату учнем. [Офіційне пояснення обмежень текстових класифікаторів](https://openai.com/index/new-ai-classifier-for-indicating-ai-written-text/).

### Екрани та слабші комп’ютери

Інтерфейс перевіряється за логічною шириною viewport: FHD при 120% ≈ 1600 CSS px, при 150% ≈ 1280 CSS px; HD Ready — 1366 px. Враховується менша висота через панелі браузера, внутрішнє збільшення 120%, мобільний екран і обидві теми. Фізична діагональ не визначає компонування сама по собі.

Переходи короткі й без анімації кожної картки; браузери з View Transitions підтримують плавне перетікання сторінок, інші — легку появу та індикатор запиту. Системне зменшення руху враховується. За доступними сигналами до 4 логічних CPU або до 4 ГБ пам’яті вимикаються зайві ефекти та знімки переходів. Довідка й історія змін мають відкладений DOM; HTML стискається, потокові файли — ні. Heartbeat не надсилається з неактивної вкладки. Конвертації й ШІ виконуються на сервері. Перевірка з уповільненням CPU не замінює випробування на конкретному старому комп’ютері.

### Нормативні орієнтири

Запити враховують прозорість критеріїв, досягнуті результати та конструктивний зворотний зв'язок. Для базової школи перевірено актуальні джерела: [наказ №722 від 04.05.2026](https://zakon.rada.gov.ua/laws/show/z0922-26) і [рекомендації МОН №1427 від 14.08.2026 для 5–9 класів](https://mon.gov.ua/npa/pro-zatverdzhennia-rekomendatsii-shchodo-otsiniuvannia-rezultataiv-navchannia-uchniv-5-9-klasiv-zakladiv-zahalnoi-serednoi-osvity). Для старшої школи важливі відповідний навчальній програмі шаблон і перехідні положення; система не нав'язує всім класам однаковий набір ГР. Вчитель має перевіряти предметні критерії обраного шаблону та актуальність документів закладу.

### Формати та межі аналізу

| Формат | Що передається ШІ | Межі |
| --- | --- | --- |
| DOCX, DOC, ODT, RTF | Текст; сторінки після конвертації LibreOffice; для DOCX також таблиці, колонтитули й дані діаграм | Невдала конвертація явно позначається; складні об'єкти залежать від LibreOffice |
| PPTX, PPT, ODP | Текст слайдів, доступні дані діаграм, візуальні сторінки | Анімації, переходи та вбудовані відео не виконуються |
| XLSX, XLS, ODS | Аркуші, таблиці, формули / збережені значення, дані діаграм для підтримуваних форматів, сторінки PDF | Макроси не виконуються; збережені результати формул можуть бути відсутні. У PDF відображаються друковані області |
| PDF, зображення | Текст PDF і сторінки; зображення для мультимодальної моделі | Розпізнавання залежить від чіткості та можливостей обраної моделі |
| TXT, вихідний код | Текст та статичний аналіз | Програми не запускаються |
| Scratch SB3 | Повна структура блоків, змінні, списки та метадані ресурсів | Реальне виконання, звук, рух спрайтів і вигляд костюмів не перевіряються |
| micro:bit HEX | Доступний вбудований код / структура | Фізичний пристрій не перевіряється; без вихідного коду можливості обмежені |
| Access MDB / ACCDB | Схема, таблиці, доступні SQL / зв'язки та вибірки даних через mdbtools | Форми, звіти, VBA, макроси та їх виконання повністю не перевіряються |
| Архіви | Вибірковий перелік і вміст текстових файлів; частина зображень ZIP | Це частковий аналіз, не перевірка всіх вкладень |
| Аудіо, відео, невідомі формати | Приймання та ручний перегляд / завантаження | Автоматична змістова ШІ-перевірка не реалізована; один непрочитаний файл не оцінюється за його назвою |

Для Gemini PDF передається як PDF. Іншим сумісним чат-провайдерам сторінки перетворюються на справжні зображення. Обрана модель повинна підтримувати такі входи: текстова модель не стає мультимодальною через налаштування платформи. Перевищення лімітів API, неповний JSON чи обірвана відповідь обробляються як невдала перевірка.

Посилання вчителя додаються до контексту з доступним статичним текстом і межами прочитаного. Для YouTube доступні метадані, а не перегляд відео; бінарний документ за URL слід прикріпити файлом. Витяги посилань кешуються до години; «Оновити аналіз ШІ» повторно читає зовнішні джерела. Закриті, динамічні та недоступні сторінки не вважаються доказом помилки учня.

### Підключення та швидкодія

У «Налаштування → Модуль ШІ» є «Підключення», «Критерії», «Моделі», «Статистика» і «Помилки». Підтримуються Gemini, OpenAI, DeepSeek, Groq, OpenRouter, Ollama / сумісний endpoint. Каталог і квоти є довідковими; фактичні можливості й ліміти визначає провайдер. Пріоритети та fallback задаються для моделей. Результат тесту моделі показується біля запуску, статистика має фільтри та графік по моделях.

Temperature у додаткових налаштуваннях керує мінливістю відповіді, а не суворістю оцінки чи чутливістю до ШІ. Для Gemini 3 [Google рекомендує 1.0](https://ai.google.dev/gemini-api/docs/gemini-3#temperature); нижче значення не гарантує правильності. Значення 0 передається без підміни.

Ключі API задаються в кабінеті вчителя й не передаються у браузер або ZIP-експорт завдань. Хмарна ШІ-перевірка передає матеріали обраному провайдеру; їй потрібен інтернет. Основні локальні операції працюють без хмарного ШІ, але деякі вбудовані переглядачі та зовнішні матеріали також потребують мережі.

Для прискорення кешуються витяги й конвертації за версією алгоритму, шляхом, розміром та часом зміни файла. Вебпроцеси й worker використовують спільний кеш. Запит містить матеріали та правила без повторних копій локальної інтерпретації. Бюджет відповіді залежить від числа критеріїв і завдань. Матеріали уроку конвертуються після відкриття конкретного файла, а не всі при завантаженні сторінки. Час самої відповіді та кількість токенів залежать від моделі й обсягу матеріалів.

```bash
./scripts/update.sh
```

`backup.sh` призупиняє обидва процеси запису (`app`, `ai_worker`), створює дамп PostgreSQL та архів медіа, перевіряє їх і поновлює запущені служби. Копія містить контрольні суми, Git-коміт та ідентифікатор образу. `update.sh` вимагає чисту гілку та fast-forward, створює перевірену копію, зберігає попередній Docker-образ, збирає новий, зупиняє обидва процеси запису перед міграцією й чекає healthcheck вебсервісу та воркера. Помилка повертає ненульовий код. Таймаут можна змінити через `SCHOOLNET_DEPLOY_TIMEOUT` (типово 240 секунд).

Для ручного оновлення поточного коду після резервного копіювання:

```bash
docker compose build app
docker compose stop app ai_worker
docker compose up -d --wait --wait-timeout 240 app ai_worker
docker compose ps
```

Не видаляйте томи даних під час оновлення. Git-коміт зберігає код, а не базу та завантажені файли.

```bash
# Перевірка копії без заміни даних:
./scripts/restore.sh backups/КАТАЛОГ_КОПІЇ --verify-only
# Відновлення (CLI запитає підтвердження; --yes для автоматизації):
./scripts/restore.sh backups/КАТАЛОГ_КОПІЇ
```

Копія повинна містити `database.dump`, `media.tar.gz` і `SHA256SUMS`. Для старої **довіреної** копії без контрольних сум існує `--allow-legacy`; SQL і шляхи медіа однаково перевіряються. Відновлення спочатку створює копію поточного стану, зупиняє `app` та `ai_worker`, готує медіа, відновлює всю схему й дані однією SQL-транзакцією та замінює медіа включно з прихованими файлами. Посилання, спеціальні файли й вихід за каталог у tar відхиляються. Кеш очищається. Успіх повідомляється лише після healthcheck та перевірки міграцій; при помилці служби залишаються зупиненими для відновлення з попередньої копії.

БД і медіа не утворюють спільної файлової транзакції: якщо заміна медіа зірветься **після** успішного SQL, потрібно усунути причину та повторити відновлення або використати створену перед ним копію. Код/образ узгодьте з версією копії; автоматично застосовуються лише прямі міграції.

### Інший сервер з готовою БД та роботами

1. Зробіть повну копію на старому сервері через `backup.sh` і перенесіть **каталог копії приватно**, разом із потрібною конфігурацією `.env`. GitHub містить лише код.
2. Клонуйте репозиторій на новому сервері, задайте локальну `.env` та зберіть `docker compose build app`.
3. Перевірте копію `restore.sh … --verify-only`, потім запустіть `restore.sh …`. Скрипт підніме PostgreSQL, відновить дані й запустить вебсервіс та воркер.
4. Перевірте відкриття завдання, файл учня, матеріали та підключення ШІ. Адресу сервера в локальній мережі задайте у конфігурації вашого середовища.

Якщо дані вже знаходяться в Docker-томах того самого Compose-проєкту, використовуйте `update.sh`; **не** запускайте відновлення поверх них без потреби. Зміна каталогу/імені Compose-проєкту може створити інші порожні томи, тому зберігайте ім’я проєкту або переносьте копію описаним способом.

## Перевірки та розробка

```bash
docker compose run --rm --no-deps app python manage.py check
docker compose run --rm --no-deps app python manage.py makemigrations --check --dry-run
docker compose run --rm --no-deps app python manage.py test --settings=schoolnet.test_settings --noinput
```

`schoolnet.test_settings` використовує окремі тимчасові медіа, кеші та SQLite у пам'яті. API-виклики в автоматичних тестах імітуються. Для перевірки PostgreSQL додайте `-e SCHOOLNET_TEST_POSTGRES=1` перед назвою `app`; створюється й видаляється окрема тестова база. Одночасно не запускайте два набори PostgreSQL-тестів з однаковою назвою бази.

Якщо образ ще не перезібрано після редагування, для тестування коду можна підключити каталог проєкту до `/app` лише для читання. Для локального запуску без Docker використовуйте Python 3.12, залежності `requirements.txt` та встановіть системні конвертери окремо. `launcher.py`, `start.sh` / `start.bat` і скрипти реєстрації — додаткові інструменти локального керування.
