# SchoolNet 4.5.10 — виправлення хмарного діалогу

## Аналіз і порядок виконання

1. Перевірити шрифти, розміри Drive, завершення імпорту та відновлення стану форми.
2. Збільшити текст і додати масштабування зі збереженням налаштування.
3. Показувати доступні розміри файлів; для публічного списку уточнювати їх без імпорту.
4. Відокремити стан кожної форми, прибрати відновлення завершеного прогресу, показувати підтвердження біля матеріалів.
5. Додати посилання для API key; перевірити браузер, PostgreSQL, Docker і роботу після встановлення.

Причина повторного додавання: ключ `sessionStorage` залежав від URL сторінки, а завершена черга залишалася в ньому. Кожне нове відкриття створення завдання відновлювало ті самі імпорти. Видалення матеріалу з форми також не очищало цю чергу. Панель прогресу не скидалася при наступному відкритті діалогу.

Шрифти окремих елементів мали розмір 11.5–13 px. Публічний HTML-список Drive не містив розмірів, і замість уточнення інтерфейс показував загальний напис «Файл Drive».

## Реалізація

- Базовий текст 16 px, масштаб 100–150% через A− / A+; вибір зберігається для вчителя в браузері. Вміст прокручується, прогрес і кнопки залишаються в діалозі. Мобільні підписи таблиці також масштабуються.
- Розміри офіційного API показуються одразу, включно з порожнім файлом у 0 Б. У публічному списку розмір уточнюється за заголовками відповіді максимум двома запитами одночасно, без зчитування файла. Якщо джерело не повідомляє розмір, це зазначено явно. Для Google Документів відрізняються розмір у Drive та остаточний розмір експорту.
- Кожний запис історії форми має власний ідентифікатор чернетки. Перезавантаження відновлює лише її вибрані файли й активну чергу. Новий перехід до створення завдання починає окрему чернетку. Старий спільний ключ ігнорується й очищається. Видалення файла одразу оновлює збережений стан.
- Після повного успіху вікно закривається, прогрес очищається, фокус переходить до повідомлення «Додано та перевірено… Збережіть завдання». Біля кожного матеріалу показано остаточний розмір і перевірку цілісності. При помилках діалог залишається відкритим із поясненням.
- Поруч із API key є переходи до Google Cloud Credentials і ввімкнення Drive API. Порядок створення перевірено за [офіційною інструкцією Google](https://developers.google.com/workspace/guides/create-credentials).

Файли остаточно прикріплюються при збереженні завдання. Наявні раніше збережені матеріали автоматично не видаляються.

Підсумковий образ для публікації: `schoolwork2-app:4.5.10-a0c6b403af7e`. Відбиток джерел: `a0c6b403af7ebac9ac152a089f02c6adcc7bc2e7f095b8ef72699f8bf27e6adc`. Код і тести зафіксовано в [коміті 0ac3e8c](https://github.com/yrskrs/schoolwork2/commit/0ac3e8ceac95fa45788917793901bdbfdf13490c). Під час підготовки коміту прибрано кінцеві пробіли у двох винесених HTML-шаблонах; поведінка не змінювалася, остаточний образ повторно пройшов повний набір тестів. Revision позначено як `dirty`, оскільки документація ще доповнювалася під час збірки; виконуваний код відповідає коміту.

Браузерний сценарій працює виключно з тимчасовою базою, синтетичним WebDAV і відповідями Google. Він перевіряє завершення, перезавантаження під час імпорту без дублікатів, збереження вибору цієї форми, видалення з наступним перезавантаженням, дві нові форми за однаковим URL та відхилення старого спільного ключа. Додатково перевіряються метадані й публічні розміри, масштаб до 150%, ширини 375/1366 px, висоти 437/700/900 px, посилання API key, збереження трьох файлів і точна відповідність їхніх байтів та SHA-256.

Секрети, паролі й вміст приватних матеріалів користувачів не переглядалися.

## Встановлення та перевірка після запуску

Підсумкову збірку 4.5.10 із зафіксованим кодом встановлено локально 19.10.2026 після перевіреної резервної копії `backups/2026-10-19_20-56-25_wUnFz3`. Перед зупинкою перевірено відсутність активних імпортів і задач ШІ. Кількість завдань, вкладень, відповідей, учнів, учителів, класів і закладів після оновлення збігається.

Вебсервіс і воркер використовують однаковий образ, їхній відбиток коду збігається з перевіреним робочим каталогом. App, worker, updater і PostgreSQL мають стан healthy. Міграції застосовані. Збережено мережеві підключення, томи даних і параметри сховищ. Для відкату збережено образ попереднього випуску `schoolwork2-app:before-cloud-4510-20261019-205625`.

Після встановлення `/healthz/` повернув 200 і версію 4.5.10. Сервер видає нові `cloud_picker.js` та `cloud_materials.js`; сторінка входу й перевірені статичні ресурси повертають 200. П’ять хмарних маршрутів без входу спрямовують на авторизацію. Контрольна серія: 40 запитів, паралельність 4, помилок 0, медіана 1.52 мс, p95 196.76 мс. Це коротка перевірка після запуску, не довготривале навантажувальне випробування.

Публічний стан Nextcloud 35.0.2 доступний як із хоста, так і з контейнера сайту: HTTP 200, maintenance=false, needsDbUpgrade=false. Приватні облікові записи Drive/Nextcloud не використовувалися для ручної перевірки.
